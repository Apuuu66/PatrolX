核心建议

  1. 按职责拆页：647 行的 TaskDetailPage 拆成 Header、Health、Meta、RuleBrowser、Logs、Report、Modal。
  2. 数据逻辑下沉：新增 useTaskDetailData 和 useTaskActions，页面只做组合。
  3. 显式数据状态：区分 loading / ready / empty / error，尤其不要把 system 或 logs 的失败隐藏成空态。
  4. 筛选语义固定：状态、搜索 = 过滤；分类 = 聚焦置顶。URL 继续作为单一事实源。
  5. 重点信息限流：重点关注只显示前 5 条，超过折叠，避免重复渲染大表。
  6. 样式 token 化：状态色、间距、圆角走统一 token，减少散落的 inline style。

组件边界

TaskDetailHeader 面包屑、任务名、状态、主操作、更多操作。不读列表数据，只接收 task 和 action 回调。
TaskHealthPanel 状态卡、健康度条、重点关注摘要。筛选事件向上抛出，不直接改 URL。
TaskMetaPanel 基础信息、客户环境、时间。字段映射独立成 utils，便于测试。
RuleBrowser chips、搜索、排序、表格、空态。复用 RuleResultTable 渲染重点和全量。
TaskLogsPanel 日志 loading / empty / error / list。避免“加载失败”被显示成“暂无日志”。
ActionModal 增量重建、设备 ID 编辑各自独立组件，状态不泄漏到页面根。

数据与测试契约

  • useTaskDetailData：输入 taskId，输出 task / system / rules / logs / status；失败状态必须可区分。
  • useTaskDetailFilters：只负责 URL 与筛选状态互转，不做 API 请求。
  • RuleResultTable：props 明确 rules / variant / busyRuleCode / onOpen / onRerun。
  • 测试拆三层：utils 单测、组件状态测试、入口到关键结果的 E2E。
  • E2E 固定覆盖：默认平铺、分类聚焦不隐藏其他分类、组合筛选不丢入口、行级重跑、日志错误态。

推荐迭代顺序

  1. 先抽 RuleResultTable + 分类 chips，消除重复表结构。
  2. 抽数据 hook，显式区分 system/logs 失败与空态。
  3. 拆 Header / Health / Meta / RuleBrowser。
  4. 补组件状态测试和 E2E。
  5. 最后统一 inline style 到 token，不动交互语义。
设计说明：本稿使用 PatrolX Design System 的状态色与桌面优先布局。状态、搜索、分类、排序继续保存在 URL；分类点击只改变排序和高亮，不删除其他分类。
