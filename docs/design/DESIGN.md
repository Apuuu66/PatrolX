# PatrolX Design System

PatrolX 是面向运维和巡检场景的桌面优先系统。UI 应该专业、克制、信息密度适中，并优先支持快速扫读和异常排查。

## Brand

- 产品名：PatrolX
- 页面标题：系统维护巡检平台
- 基调：可靠、清晰、工程化
- 避免营销页风格、大面积装饰、复杂动效

## Layout

- 桌面优先，目标宽度从 1280px 到 1920px；不新增移动端适配。
- 主布局采用左侧固定导航 + 顶部栏 + 内容区。
- 内容区最大宽度 1600px；页面内容区保持 `padding: 24px` 与 `#f5f5f5` 背景。
- 卡片之间保持 16px 到 20px 间距；卡片内边距保持 16px 到 24px。
- 1280px 宽度下页面本身不得出现横向滚动；宽表（任务列表等）在视口不足时允许表格内部横向滚动，并把操作列固定在右侧。
- 1920px 宽度下内容不得无限拉伸，内容区不超过 1600px。

### Spacing

间距只使用以下五档语义刻度，不在页面内引入任意像素值：

| 变量 | 值 | 用途 |
| --- | --- | --- |
| `--space-1` | 4px | 图标、标签与文字的紧邻间距 |
| `--space-2` | 8px | 同组字段、按钮之间的间距 |
| `--space-3` | 12px | 区块内的次级分组间距 |
| `--space-4` | 16px | 卡片之间、区块之间的默认间距 |
| `--space-5` | 24px | 页面级分组与内容区边距 |

圆角沿用 `ConfigProvider` 的 `borderRadius: 8` 与 `--radius-round`（胶囊），不新增圆角档位。

## Color

### Brand

- Primary：AntD 蓝，建议基于 `#1677ff`
- Page background：`#f5f5f5`
- Surface：`#ffffff`
- Border：`#f0f0f0`
- Text primary：`rgba(0, 0, 0, 0.88)`
- Text secondary：`rgba(0, 0, 0, 0.65)`
- Text tertiary：`rgba(0, 0, 0, 0.45)`

### Status

状态色必须全站一致，并统一复用 `web/src/components/statusLabels.ts`：

| Status | 中文 | 颜色 |
| --- | --- | --- |
| pass | 通过 | 绿，基于 `#52c41a` |
| warn | 告警 | 黄，基于 `#faad14` |
| fail | 失败 | 红，基于 `#ff4d4f` |
| error | 异常 | 灰，基于 `#8c8c8c` |
| skip | 跳过 | 蓝，基于 `#1677ff` |

状态不应只依赖颜色，还需要文字标签。统计块、Tag、Badge、表格状态列都应使用同一套语义色。

0 值规则：

- 0 值状态不渲染计数、不渲染分段、不渲染独立占位块。
- 状态分布使用“分段条 + 非零计数”；五态总和为 0 时显示“暂无规则结果”。
- 只有 warn 的任务使用黄色结论，不得使用失败红。

## Typography

| 层级 | 规格 | 用途 |
| --- | --- | --- |
| 页面标题 | 16px / 600 | 每个页面唯一，置于 `PageHeader` |
| 区块标题 | 14px / 600 | 卡片、分组、折叠面板标题 |
| 正文 | 14px / 400 | 表格、列表、说明正文 |
| 次要说明 | 12px | 辅助说明、时间戳、脱敏提示 |
| 标识符 | 12px 等宽 | 任务 ID、规则编码、文件路径 |
| 数字指标 | 20px 到 24px / 600 | 仅概览条使用，同一页面不得出现第二组等权大数字 |

不得使用超过 24px 的页面标题或指标数字；同一页面只能有一个 16px 页面标题。

## Components

### Page Header

页面头部包含：

- 面包屑或标题上方定位信息
- 页面唯一标题
- 一句话说明
- 状态摘要
- 操作区

主操作最多保留 1 个，低频操作放入 Dropdown 或“更多”菜单。标题、说明、状态与操作必须保持稳定顺序，避免每个页面各写一套页头。

### Card

卡片用于任务、规则分组、报告块和配置区。

- 卡片标题使用 14px 粗体。
- 每张卡片只表达一个主要对象。
- 状态和关键数字应靠近标题或内容左侧。
- 操作应位于右上或底部，不与状态混排。
- 卡片内区块使用 12px 到 16px 间距或 1px `#f0f0f0` 分隔线，不能叠加多层边框。

### Status Distribution

状态分布用于任务列表、任务详情和摘要卡片：

1. 概览条：展示总量，弱化颜色。
2. 任务摘要：突出非零状态，特别是 warn / fail / error。
3. 规则表：使用 Tag 表达状态。

分布必须是“分段条 + 非零计数”，文字标签与非零状态同时出现。五态全为 0 时只显示“暂无规则结果”。

### Metadata List

任务元数据使用轻量键值展示：

- label：secondary text
- value：primary text
- label 与 value 之间保持 4px 间距
- 避免多个彩色 Tag 增加视觉噪音

示例：

```text
省份 江苏 · 运营商 移动 · 产品 路由器 · 版本 v2.1
```

### Actions

操作分层如下：

| 类型 | 示例 | 展示 |
| --- | --- | --- |
| Primary | 上传数据包、查看报告 | 主按钮，每个页面最多 1 个 |
| Secondary | 详情、报告、失败日志 | 文本按钮或链接 |
| More | 重跑、增量重建、全量重建 | `⋯` Dropdown |
| Danger | 删除、全量重建 | 危险样式 + 二次确认 |

列表行内最多平铺 3 个可见操作；删除与全量重建必须进入危险入口。禁用操作必须说明原因，例如“任务执行中不可查看报告”。

### Empty State

空状态必须包含：

- 简短说明
- 下一步动作

任务列表空状态的主 CTA 为“上传数据包”。局部列表为空时，优先提供“清空筛选”“刷新列表”或进入上游数据的动作。

### Loading State

- 页面级首次加载使用骨架屏。
- 局部刷新使用轻量 loading，不引起整页骨架抖动。
- 错误态复用统一重试入口，保持一致的文案风格；不得只在控制台报错。
- 数据准备失败、规则解析失败等局部问题使用局部提示，不中断整页渲染。

## Patterns

页面分为四类模式，分别使用统一的信息层级：

| 模式 | 核心目标 | 首要内容 |
| --- | --- | --- |
| 任务列表 | 快速发现异常任务 | 异常置顶的行式任务列表 |
| 任务详情 | 先给结论，再给证据 | 结论 Hero 与重点关注 |
| 规则详情 | 结论 → 证据 → 建议 | 规则结论与建议 |
| 其余主页面 | 统一视觉基线 | 页头、卡片、状态与操作分层 |

### Task List

任务列表是单表、列对齐的行式列表，每行一个任务。固定列顺序：

1. 任务：名称 + 状态 + 任务 ID + 失败原因摘要
2. 状态摘要
3. 元数据
4. 时间与耗时
5. 操作

规则：

- 固定列顺序为「任务 → 状态摘要 → 元数据 → 时间与耗时 → 操作」，操作列固定在右侧。
- `fail` / `error` 任务默认置顶，可扩展到 `warn`；同状态内按 `created_at` 倒序。
- 失败任务行直接显示原因摘要，并提供进入失败日志的入口。
- 行展开承载数据准备状态、问题文件摘要与重试、失败日志入口。
- 保留状态筛选、搜索、默认 10 条分页、轮询与上传表单。
- 不使用卡片网格，不展示五色等权状态块。

### Task Detail

任务详情按“结论优先”组织：

1. 面包屑
2. 结论 Hero：结论标签、一句话结论、状态计数、主操作与关键元数据
3. 重点关注：按 fail → warn 排序，默认可见，最多 5 条，其余折叠
4. 全部规则：按类别分组折叠，默认展开含异常的分组
5. 标签页：执行日志 / 设备台账 / 报告预览
6. 折叠的执行与技术信息

结论 Hero 必须在 1440×900 首屏内可见，覆盖全部通过、需要关注、任务失败、执行中、排队中五种形态。不得用“提示条”与“重点关注列表”重复表达同一事实。主包解压失败时展示失败原因与阶段及日志入口，不渲染空规则表格冒充结果。

### Rule Result

规则详情按“结论 → 证据 → 建议”组织：

1. 结论与建议
2. 源文件匹配
3. 发现
4. 证据面板
5. 折叠的技术信息

首屏必须可见规则状态、严重度、结论摘要与建议。`skip` 必须展示 `skip_reason`。指标表默认精简列，并支持“显示全部列”切换。重跑入口首屏可及；重跑中显示进行中状态，完成后只刷新本页结果。

### 其余主页面

设备台账、设备详情、基础指标、规则管理、数据字典、报告、日志、用户管理只套用视觉基线：

- 使用 `PageHeader`、统一卡片、状态标签与操作分层。
- 页面级加载使用骨架屏，局部刷新使用轻量 loading。
- 空状态提供下一步动作，错误态提供统一重试。
- 不重排原有信息架构，不改变功能语义。
- 设备台账与设备详情默认分页 10 条。

## Accessibility and Robustness

- 状态信息必须有文字，不得只靠颜色。
- 可交互元素必须可键盘聚焦，并用 Enter / Space 触发。
- 长任务名、规则名、文件路径必须截断显示，完整值通过 `title` 或复制获得。
- 既有路由与 URL 语义不得破坏，深链继续可用。
- 1280px 与 1920px 视口下页面均不得出现横向滚动，宽表只允许表格内部横向滚动；1920px 下内容不得无限拉伸。

## Do

- 使用一致的间距、字号和圆角。
- 保持状态语义全站统一。
- 让 fail / warn / error 比 pass / skip 更容易发现。
- 收纳低频和危险操作。
- 用可读文本替代 JSON 字符串。
- 优先展示结论、原因和下一步动作。

## Don't

- 不要为了视觉丰富牺牲信息密度。
- 不要给 0 值状态过高视觉权重。
- 不要使用过多彩色 Tag。
- 不要加入营销页动效。
- 不要把危险操作与普通操作混排。
- 不要在列表页展开过多次要信息。
