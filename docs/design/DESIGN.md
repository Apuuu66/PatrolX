# PatrolX Design System

PatrolX 是面向运维和巡检场景的桌面优先系统。UI 应该专业、克制、信息密度适中，并优先支持快速扫读和异常排查。

## Brand

- 产品名：PatrolX
- 页面标题：系统维护巡检平台
- 基调：可靠、清晰、工程化
- 避免营销页风格、大面积装饰、复杂动效

## Layout

- 桌面优先，目标宽度从 1280px 到 1920px；不新增移动端适配。
- 主布局采用左侧固定导航 + 顶部栏 + 内容区。
- 内容区最大宽度 1600px；页面内容区保持 `padding: 24px` 与 `#f5f5f5` 背景。
- 卡片之间保持 16px 到 20px 间距；卡片内边距保持 16px 到 24px。
- 1280px 宽度下页面本身不得出现横向滚动；宽表（任务列表等）在视口不足时允许表格内部横向滚动，并把操作列固定在右侧。
- 1920px 宽度下内容不得无限拉伸，内容区不超过 1600px。

### Spacing

间距只使用以下五档语义刻度，不在页面内引入任意像素值：

| 变量 | 值 | 用途 |
| --- | --- | --- |
| `--space-1` | 4px | 图标、标签与文字的紧邻间距 |
| `--space-2` | 8px | 同组字段、按钮之间的间距 |
| `--space-3` | 12px | 区块内的次级分组间距 |
| `--space-4` | 16px | 卡片之间、区块之间的默认间距 |
| `--space-5` | 24px | 页面级分组与内容区边距 |

圆角沿用 `ConfigProvider` 的 `borderRadius: 8` 与 `--radius-round`（胶囊），不新增圆角档位。

## Color

### Brand

- Primary：AntD 蓝，建议基于 `#1677ff`
- Page background：`#f5f5f5`
- Surface：`#ffffff`
- Border：`#f0f0f0`
- Text primary：`rgba(0, 0, 0, 0.88)`
- Text secondary：`rgba(0, 0, 0, 0.65)`
- Text tertiary：`rgba(0, 0, 0, 0.45)`

### Status

状态色必须全站一致，并统一复用 `web/src/components/statusLabels.ts`：

| Status | 中文 | 颜色 |
| --- | --- | --- |
| pass | 通过 | 绿，基于 `#52c41a` |
| warn | 告警 | 黄，基于 `#faad14` |
| fail | 失败 | 红，基于 `#ff4d4f` |
| error | 异常 | 灰，基于 `#8c8c8c` |
| skip | 跳过 | 蓝，基于 `#1677ff` |

状态不应只依赖颜色，还需要文字标签。统计块、Tag、Badge、表格状态列都应使用同一套语义色。

### 状态文字安全色（FR-019、SC-006、R13）

“填充色”与“文字色”分离：分段条、色点、Tag 底色继续使用上面的标准状态色；一旦把状态色用于**文字**，改用更深一档的文本安全色，保证白底 / 浅色底上对比度 ≥ 4.5:1。

| Status | 填充色 | 文本安全色 | 备注 |
| --- | --- | --- | --- |
| pass | `#52c41a` | `#237804` | 与跳过保持低视觉权重 |
| warn | `#faad14` | `#874d00` | 研究稿 `#ad6800` 未达 4.5:1，实现下移到 gold-8 |
| fail | `#ff4d4f` | `#cf1322` | 保留危险语义 |
| error | `#8c8c8c` | `#595959` | 中性灰，必须配合斜纹 / 方形等冗余标识 |
| skip | `#1677ff` | `#0958d9` | 侧边栏选中态文字复用同一色 |

唯一实现来源为 `web/src/utils/statusTextColors.ts`；CSS 变量 `--status-text-*` 与之一一对应，不得在页面内另写色值。

“异常”必须在颜色以外带冗余标识：分布条异常分段叠加斜纹、异常圆点改为方块、异常状态标签使用虚框 + 斜纹。

## 术语表（FR-022、R15）

界面文案、报告与接口展示文案统一使用下表术语；同义词仅允许出现在解释性文字中。

| 术语 | 定义 | 禁用写法 |
| --- | --- | --- |
| 任务（task） | 一个数据包对应的一次巡检；一个包 = 一个任务 = 一个输出目录 | 作业、工单、job |
| 规则结果（rule result） | 某条规则在一次任务中的执行结果，取值只有 pass / warn / fail / error / skip 五态，一条规则只有一条结果 | 检测项、检查结果、rule report |
| 发现（finding） | 规则结果内部的具体问题条目，一条规则可以产生 0 到多条发现 | 问题、异常记录、告警条目 |
| 问题条目 | “发现”在计数与列表场景的等价说法，计数口径必须与发现一致 | 缺陷、bug、异常数 |
| 状态分布（status distribution） | 五态计数按 fail → warn → error → skip → pass 排序的分段条 + 非零计数 | 状态统计条、饼图、占比图 |
| 状态 | 规则结果的五态语义（通过 / 告警 / 失败 / 异常 / 跳过），必须与文字标签同时出现 | 颜色、灯色、红黄绿 |

口径约定：

- “规则结果数” = 五态计数之和；“发现问题数” = 各规则发现条目之和，两者不相等是正常的。
- 只有 0 值不写：结论句、计数行、指标块都不出现“异常 0 条”这类表述。
- 状态词只用“通过 / 告警 / 失败 / 异常 / 跳过”，不得写成“成功 / 警告 / 错误 / 忽略”。

0 值规则：

- 0 值状态不渲染计数、不渲染分段、不渲染独立占位块。
- 状态分布使用“分段条 + 非零计数”；五态总和为 0 时显示“暂无规则结果”。
- 只有 warn 的任务使用黄色结论，不得使用失败红。

## Typography

| 层级 | 规格 | 用途 |
| --- | --- | --- |
| 页面标题 | 16px / 600 | 每个页面唯一，置于 `PageHeader` |
| 区块标题 | 14px / 600 | 卡片、分组、折叠面板标题 |
| 正文 | 14px / 400 | 表格、列表、说明正文 |
| 次要说明 | 12px | 辅助说明、时间戳、脱敏提示 |
| 标识符 | 12px 等宽 | 任务 ID、规则编码、文件路径 |
| 数字指标 | 20px 到 24px / 600 | 仅概览条使用，同一页面不得出现第二组等权大数字 |

不得使用超过 24px 的页面标题或指标数字；同一页面只能有一个 16px 页面标题。

## Components

### Page Header

页面头部包含：

- 面包屑或标题上方定位信息
- 页面唯一标题
- 一句话说明
- 状态摘要
- 操作区

主操作最多保留 1 个，低频操作放入 Dropdown 或“更多”菜单。标题、说明、状态与操作必须保持稳定顺序，避免每个页面各写一套页头。

### Card

卡片用于任务、规则分组、报告块和配置区。

- 卡片标题使用 14px 粗体。
- 每张卡片只表达一个主要对象。
- 状态和关键数字应靠近标题或内容左侧。
- 操作应位于右上或底部，不与状态混排。
- 卡片内区块使用 12px 到 16px 间距或 1px `#f0f0f0` 分隔线，不能叠加多层边框。

### 概览条（Overview Strip）

概览条位于页面标题之下、主内容之上，用于给出全站量级，不承担结论表达。

- 固定顺序：巡检任务 → 注册规则 → 规则结果 → 发现问题数；不得增删或重排指标。
- 排序意图：从左到右依次是"有多少任务 → 用了多少规则 → 产生了多少结论 → 发现了多少问题"，阅读方向与巡检流程一致。
- 弱化层级：指标数字 ≤ 24px / 600，标签 12px 次要色；无重色底、无渐变、无图标装饰，整体视觉权重必须低于其下的任务列表。
- 每个指标提供口径 Tooltip（固定写明"统计范围：全部任务"），避免"注册规则"被误读为任务内规则数。
- 右侧展示五态分布；数据未加载时显示"统计数据加载中"，不得渲染 0 值假分布。
- 统计值缺失用 `—`，不得用 0 代替缺数据。

### 时间列

时间与数字在列表、表格与详情中统一按以下规范呈现：

- 可见文本使用中文相对时间（如"3 小时前"），悬停显示完整时间 `YYYY-MM-DD HH:mm:ss`；无有效时间时不渲染 Tooltip。
- 时间、耗时、计数统一使用等宽数字（`tabular-nums` 类名），保证纵向对齐。
- 存储保持 UTC，展示按浏览器本地时区；字段命名保持 `*_at`。
- 空值或非法时间显示占位符 `-`，不得抛错、不得留空单元格。
- 可排序列在表头提供排序，并通过 `aria-sort` 暴露当前排序状态；不可排序列不得放置误导性箭头。

### Status Distribution

状态分布用于任务列表、任务详情和摘要卡片：

1. 概览条：展示总量，弱化颜色。
2. 任务摘要：突出非零状态，特别是 warn / fail / error。
3. 规则表：使用 Tag 表达状态。

分布必须是“分段条 + 非零计数”，文字标签与非零状态同时出现。五态全为 0 时只显示“暂无规则结果”。

### Metadata List

任务元数据使用轻量键值展示：

- label：secondary text
- value：primary text
- label 与 value 之间保持 4px 间距
- 避免多个彩色 Tag 增加视觉噪音

示例：

```text
省份 江苏 · 运营商 移动 · 产品 路由器 · 版本 v2.1
```

### 表格密度

- 提供"紧凑 / 舒适"两档，默认紧凑；紧凑 = AntD `small`，舒适 = `middle`。
- 切换只改变行高与单元格内边距，不得改变列顺序、字段内容、筛选条件与分页位置。
- 偏好写入浏览器本地存储（键名 `patrolx.tableDensity`），不写入 URL、不落库，避免污染深链与接口契约。
- 读取失败、非法值或隐私模式回退默认紧凑，不打断渲染。
- 入口为分段控件（`aria-pressed` 标记选中项），带键盘可见焦点；同一浏览器内任务列表、任务详情重点关注表与规则管理共用同一偏好。

### 发现条目（Finding Item）

规则详情中的每条发现独立成一个块，固定顺序：

1. 严重度标签 + 一句话标题
2. 来源（等宽路径 + 一键复制）
3. 证据（键值分段、关键数值高亮；超过 4 行折叠，可"展开其余证据 / 收起证据"）
4. 详情
5. 建议

规则：

- 证据使用 `；` 分段解析；解析失败时按原文降级展示，不丢信息、不报错。
- 折叠只影响证据行数，不隐藏严重度、标题与来源。
- 同一发现内的字段用 4px 到 8px 间距纵向排列，不再叠加多层卡片边框。

### Actions

操作分层如下：

| 类型 | 示例 | 展示 |
| --- | --- | --- |
| Primary | 上传数据包、查看报告 | 主按钮，每个页面最多 1 个 |
| Secondary | 详情、报告、失败日志 | 文本按钮或链接 |
| More | 重跑、增量重建、全量重建 | `⋯` Dropdown |
| Danger | 删除、全量重建 | 危险样式 + 二次确认 |

列表行内最多平铺 3 个可见操作；删除与全量重建必须进入危险入口。禁用操作必须说明原因，例如“任务执行中不可查看报告”。

### 上传弹窗（Upload Precheck）

上传弹窗必须在提交前给出可核对、可执行的前置反馈：

1. 选择文件后立即（1 秒内）展示：任务 ID 预览（等宽 token 样式，与后端 `clean_task_id` 同规则）、格式化文件大小、校验结论。
2. 校验不通过时列出具体原因（格式不支持 / 空文件 / 超限 / 文件名超长），并禁用提交按钮；不得提交后才报错。
3. 同名任务已在列表内时提示"checksum 相同时提交将打开已有任务，不同时会提示冲突"，并提供"查看已有任务"入口。
4. `package_checksum_conflict` 时在弹窗内给出说明与两个下一步动作：修改文件名（清空当前选择并提示重新选择）、查看已有任务（跳转既有任务）。
5. 校验结果文案只解释原因与下一步，不暴露后端错误码；不新增接口调用，错误码语义保持与 OpenAPI 一致。

### Empty State

空状态必须包含：

- 简短说明
- 下一步动作

任务列表空状态的主 CTA 为“上传数据包”。局部列表为空时，优先提供“清空筛选”“刷新列表”或进入上游数据的动作。

### Loading State

- 页面级首次加载使用骨架屏。
- 局部刷新使用轻量 loading，不引起整页骨架抖动。
- 错误态复用统一重试入口，保持一致的文案风格；不得只在控制台报错。
- 数据准备失败、规则解析失败等局部问题使用局部提示，不中断整页渲染。

## Patterns

页面分为四类模式，分别使用统一的信息层级：

| 模式 | 核心目标 | 首要内容 |
| --- | --- | --- |
| 任务列表 | 快速发现异常任务 | 异常置顶的行式任务列表 |
| 任务详情 | 先给结论，再给证据 | 结论 Hero 与重点关注 |
| 规则详情 | 结论 → 证据 → 建议 | 规则结论与建议 |
| 其余主页面 | 统一视觉基线 | 页头、卡片、状态与操作分层 |

### Task List

任务列表是单表、列对齐的行式列表，每行一个任务。固定列顺序：

1. 任务：名称 + 状态 + 任务 ID + 失败原因摘要
2. 状态摘要
3. 元数据
4. 时间与耗时
5. 操作

规则：

- 固定列顺序为「任务 → 状态摘要 → 元数据 → 时间与耗时 → 操作」，操作列固定在右侧。
- `fail` / `error` 任务默认置顶，可扩展到 `warn`；同状态内按 `created_at` 倒序。
- 失败任务行直接显示原因摘要，并提供进入失败日志的入口。
- 行展开承载数据准备状态、问题文件摘要与重试、失败日志入口。
- 保留状态筛选、搜索、默认 10 条分页、轮询与上传表单。
- 不使用卡片网格，不展示五色等权状态块。

### Task Detail

任务详情按“结论优先”组织：

1. 面包屑
2. 结论 Hero：结论标签、一句话结论、状态计数、主操作与关键元数据
3. 重点关注：按 fail → warn 排序，默认可见，最多 5 条，其余折叠
4. 全部规则：按类别分组折叠，默认展开含异常的分组
5. 标签页：执行日志 / 设备台账 / 报告预览
6. 折叠的执行与技术信息

结论 Hero 必须在 1440×900 首屏内可见，覆盖全部通过、需要关注、任务失败、执行中、排队中五种形态。不得用“提示条”与“重点关注列表”重复表达同一事实。主包解压失败时展示失败原因与阶段及日志入口，不渲染空规则表格冒充结果。

### Rule Result

规则详情按“结论 → 证据 → 建议”组织：

1. 结论与建议
2. 源文件匹配
3. 发现
4. 证据面板
5. 折叠的技术信息

首屏必须可见规则状态、严重度、结论摘要与建议。`skip` 必须展示 `skip_reason`。指标表默认精简列，并支持“显示全部列”切换。重跑入口首屏可及；重跑中显示进行中状态，完成后只刷新本页结果。

### 其余主页面

设备台账、设备详情、基础指标、规则管理、数据字典、报告、日志、用户管理只套用视觉基线：

- 使用 `PageHeader`、统一卡片、状态标签与操作分层。
- 页面级加载使用骨架屏，局部刷新使用轻量 loading。
- 空状态提供下一步动作，错误态提供统一重试。
- 不重排原有信息架构，不改变功能语义。
- 设备台账与设备详情默认分页 10 条。

## Accessibility and Robustness

- 状态信息必须有文字，不得只靠颜色。
- 可交互元素必须可键盘聚焦，并用 Enter / Space 触发。
- 长任务名、规则名、文件路径必须截断显示，完整值通过 `title` 或复制获得。
- 既有路由与 URL 语义不得破坏，深链继续可用。
- 1280px 与 1920px 视口下页面均不得出现横向滚动，宽表只允许表格内部横向滚动；1920px 下内容不得无限拉伸。

## Do

- 使用一致的间距、字号和圆角。
- 保持状态语义全站统一。
- 让 fail / warn / error 比 pass / skip 更容易发现。
- 收纳低频和危险操作。
- 用可读文本替代 JSON 字符串。
- 优先展示结论、原因和下一步动作。
- 时间统一相对时间 + 完整时间 Tooltip，数字使用等宽字形。

## Don't

- 不要为了视觉丰富牺牲信息密度。
- 不要给 0 值状态过高视觉权重。
- 不要使用过多彩色 Tag。
- 不要加入营销页动效。
- 不要把危险操作与普通操作混排。
- 不要在列表页展开过多次要信息。
- 不要把密度偏好写进 URL 或后端，不要把完整时间当作列表可见文本。
- 不要在概览条上使用重色底或超过 24px 的数字抢走任务列表的注意力。
