# Quickstart：界面新增动态派生指标

## 前置条件

1. 已完成 `python build.py install`。
2. 管理员账号可登录 Web。
3. KPI 基础资源中已有同业务域的分子和分母 raw 指标，并且两者均已分类。
4. 契约与前端客户端已按实现更新。

## 常用命令

```bash
python build.py contract
python build.py gen-web-api
python build.py lint
python build.py test
python build.py verify
cd web && npm run build
```

## 验证场景 1：正向成功率

1. 进入 KPI 基础资源页面，打开配置中心“派生指标”。
2. 新增指标：
   - key：`ui_call_success_rate`
   - 中文名：界面呼叫成功率
   - domain：`call`
   - 单位：`%`
   - formula：`ratio`
   - 分子：已分类成功次数 raw 指标
   - 分母：已分类请求/尝试次数 raw 指标
   - scale：`100`
3. 保存后列表出现该指标，配置审计记录 create。
4. 上传/使用包含两个输入的新任务并等待 KPI 巡检完成。
5. 任务详情显示派生指标值、`%`、状态和输入来源；配置公式为 `分子 / 分母 × 100`。

## 验证场景 2：受控反向成功率

1. 新增指标：
   - formula：`inverse_ratio`
   - 分子：失败次数 raw 指标
   - 分母：请求/尝试次数 raw 指标
   - scale：`100`
2. 新任务详情中的值应等于 `(1 - 失败总数 / 请求总数) × 100`。
3. 修改公式或 scale 后，已有任务结果不变；再次创建新任务使用新口径。

## 验证场景 3：校验和历史不可变

1. 尝试使用重复 key、未知指标、未分类指标、跨业务域指标或派生指标作为输入；保存被阻断且返回明确原因。
2. 构造分母为零或缺少分子的任务；派生结果显示不可用和原因，不显示错误值。
3. 删除被阈值引用的派生指标；请求被拒绝并显示引用来源。
4. 修改/删除派生指标后，打开历史任务；其 KPI 结果和快照内容保持不变。

## 验证场景 4：本地/在线同构

1. 通过 API 创建派生指标后使用 CLI 或 API 执行同一个新数据包。
2. 两侧任务 KPI 结果的结构和数值一致（执行标识和时间戳除外）。
