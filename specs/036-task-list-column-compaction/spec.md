# 功能规格：任务列表列宽压缩

**功能分支**：`036-task-list-column-compaction`

**创建日期**：2026-10-23

**状态**：已澄清

**输入**：用户描述："为什么任务列表里的操作是固定的，其他的会隐藏？保持这样吧，我可以缩放一下。你有什么好的建议？"→ 用户从建议清单选择 C：压缩任务列表总宽，减少表格内部横向滚动；合并"创建时间 / 最后运行 / 任务时长"三个物理列为单个时间列；元数据从 5 项平铺改为"前几项 + 更多"收纳；同时保留操作列固定右侧、操作平铺常驻。

## 背景

031 与 033 之后，任务列表列在视觉层级上已经分层，但物理列数没有收缩：当前为"任务 / 状态摘要 / 数据准备 / 元数据 / 创建时间 / 最后运行 / 任务时长 / 操作"共 8 列，声明总宽约 1530px（操作列固定右侧 280px）。在 1440px 与 1280px 桌面视口下，列表可用宽度分别约为 1192px 与 1032px，用户必须拖动表格内部横向滚动条才能看到右侧列——而右侧列恰好是操作入口。

034 为任务补充了"最后一次运行时间"和"任务时长"两个字段，033 又要求时间信息不换行、完整时间走 Tooltip，于是时间信息占用了 3 个物理列共 370px。本次把时间维度收拢成一个列，把元数据收起重复项，压掉总宽，让 1440px 视口下一屏看全任务行，同时不牺牲操作列的可达性。

**本轮边界**：

- 只改任务列表的前端展示层与 `docs/design/DESIGN.md`；不新增或修改 OpenAPI 契约，不改后端数据模型、执行器、规则与执行编排。
- 不改变任务排序、状态筛选、搜索、分页、轮询、深链与上传流程语义。
- 不引入新的 UI 组件库或新依赖。
- 不改变任务列表行的操作集合：无任务级"重跑"，重建与删除仍需二次确认，删除失败仍需在操作列就地重试。
- 不引入列宽拖拽、列显隐或列自定义等新能力。

## Clarifications

### Session 2026-10-23

- Q: "完全无需表格内部横向滚动"的验收视口取哪一个？ → A: **1440×900**。任务列表可用宽度约 1192px（视口 1440 − 侧栏 200 − 左右内边距 48），可在保留操作列 280px 的前提下容纳 6 列并保持任务名与元数据可读；该口径与 033 的 SC-001 一致。
- Q: 1280×900 是否也必须"完全无需内部横向滚动"？ → A: 不要求。1280 下允许表格内部横向滚动，但页面本身不得出现横向滚动、操作列必须始终固定右侧、列不得上下堆叠或降级为卡片（沿用 DESIGN.md 第 18 行既有口径）。
- Q: 时间列的信息层级与完整值获取方式？ → A: 耗时为第一主信息、最后运行时间为第二信息、创建时间为最次信息；完整时间仍通过悬浮获取；时间列使用等宽数字且不换行；不使用行展开承载时间。
- Q: 元数据列平铺几项？ → A: 默认平铺 3 项有值字段，其余进入带项数的"更多元数据"入口；平铺上限按列宽预算定为 2~3 项，实现阶段以 1440 视口整表不出现内部横向滚动为准。

## 用户场景与测试 *(必填)*

### 用户故事 1 - 一屏看全任务行（优先级：P1）

值班人员在桌面浏览器打开任务列表，无需拖动表格内部横向滚动条，就能在同一行里看到任务名与状态、状态摘要、数据准备摘要、关键元数据、最近一次运行的时间和耗时，以及右侧固定的操作入口。

**优先级理由**：横向滚动直接打断"逐行扫读、快速发现异常"这一任务列表的核心用途；这是本轮要解决的主问题。

**独立测试**：用既有 E2E 种子任务（含失败、告警、全通过、运行中、从未运行任务）分别在 1280、1440、1920 宽度打开任务列表，检查列数、总宽、时间列内容、排序列与页面级滚动状态。

**验收场景**：

1. **给定** 达到 FR-004 确认宽度的桌面视口，**当** 打开任务列表，**则** 表格不需要内部横向滚动即可看全任务名、状态摘要、数据准备、元数据、时间与操作列。
2. **给定** 1280 / 1440 / 1920 三个视口，**当** 打开任务列表，**则** 页面本身不出现横向滚动；视口不足时只允许表格内部横向滚动。
3. **给定** 某个任务已运行多次，**当** 查看该行时间列，**则** 主信息是最近一次运行的耗时，次要信息是最近一次运行时间，再次要是创建时间，完整时间可通过悬浮获取。
4. **给定** 任务正在执行，**当** 查看该行时间列，**则** 呈现运行中状态且不显示上一次运行的耗时；**给定** 任务从未运行，**则** 耗时显示占位符而非误导性数值。
5. **给定** 时间显示已合并，**当** 查看任意任务行，**则** 时间值不换行、行高一致，且数字列使用等宽数字对齐。

---

### 用户故事 2 - 关键操作始终可达（优先级：P1）

值班人员需要重建或删除任务时，无论表格多宽、是否横向滚动，操作列都固定在右侧且平铺常驻；执行失败的删除仍在同一行就地重试。

**优先级理由**：操作列是本轮压缩的"不可压缩项"——牺牲操作可达性换取列数减少会直接破坏既有可用性。

**独立测试**：用既有任务操作 E2E 用例，在 1440 与 1280 视口下检查操作列固定、按钮数量、可用性与二次确认。

**验收场景**：

1. **给定** 表格因视口不足出现内部横向滚动，**当** 用户滚动到任意水平位置，**则** 操作列始终贴右侧可见。
2. **给定** 处于不同状态与删除结果的任务行，**当** 查看操作列，**则** 详情、报告（失败任务为失败日志）、重建、删除、删除失败重试全部平铺可见，不使用 `⋯` 菜单、不依赖 hover 显现、不换行。
3. **给定** 用户点击重建或删除，**当** 操作发起，**则** 仍要求二次确认；**且** 任务列表不出现任务级"重跑"。

---

### 用户故事 3 - 元数据可收纳但不丢失（优先级：P2）

值班人员在列表里先看到最有用的几项任务元数据，需要其余项时点开"更多元数据"查看完整内容并复制。

**优先级理由**：元数据共 5 项，全平铺是宽度浪费的主要来源之一；但缩列不能导致元数据不可查。

**独立测试**：用带完整与部分缺失元数据的种子任务，检查平铺项数、更多入口、Popover 内容与空值处理。

**验收场景**：

1. **给定** 任务含 5 项有值元数据，**当** 查看该行，**则** 平铺展示前几项，其余通过"更多元数据"入口可展开。
2. **给定** 展开"更多元数据"，**当** 查看浮层内容，**则** 剩余字段的标签与完整值可见、可复制，点击浮层外部可关闭且单个任务的浮层互不干扰。
3. **给定** 任务某些元数据字段为空，**当** 查看该行，**则** 空字段不渲染占位横线，全部为空时元数据区域整体隐藏。
4. **给定** 增删"更多"入口，**当** 查看任务行，**则** 行高不因收纳状态跳变。

---

### 边界情况

- 三个时间点完全缺失：仍要给出可理解的表达（例如无运行记录），不得出现空单元格或乱码。
- 任务从未运行：最后运行时间为空、时长不显示，只展示创建时间。
- 任务运行中且已有上一次运行记录：不得把上一次耗时当作当前耗时展示。
- 视口宽度小于 1280px：允许表格内部横向滚动，但操作列仍固定右侧、页面本身不得出现横向滚动。
- 浏览器缩放导致有效视口宽度变化：布局按有效宽度重排，缩放后不出现内容重叠或操作列漂移。
- 删除失败：错误提示与重试入口都在操作列内可见，且不触发操作按钮换行或列宽撑开。
- 任务名、任务 ID、失败原因、元数据值、文件路径超长：截断展示并保留完整值获取方式，不撑破列宽。
- 元数据字段缺失或全空：不渲染空占位、不出现空白"更多"入口。
- 只有一条任务或列表为空：空状态主入口仍为"上传数据包"，布局不因行数变化而抖动。
- 分页每页条数变化、切换筛选或排序：列布局与时间列含义保持不变。

## 需求 *(必填)*

### 任务列表列结构与宽度

- **FR-001**：任务列表保留 6 个物理列，固定顺序为「任务 → 状态摘要 → 数据准备 → 元数据 → 时间 → 操作」；操作列固定在右侧。
- **FR-002**：声明总宽必须显著低于现状 1530px，使 1280 / 1440 / 1920 三个视口下页面本身不出现横向滚动，只允许表格内部横向滚动；在 FR-004 确认的目标视口下不需要内部横向滚动即可看全全部列。
- **FR-003**：操作列宽度不得低于 280px，以保证任何状态下操作按钮都单行平铺可见。
- **FR-004**："完全无需内部横向滚动"的验收视口固定为 **1440×900**（表格可用宽度约 1192px）。1280×900 下允许表格内部横向滚动，但页面级横向滚动必须为 0，且操作列保持固定右侧。
- **FR-005**：压缩列宽不得改变既有排序、筛选、分页、轮询与深链语义。

### 时间列

- **FR-006**：创建时间、最后运行时间、任务时长三个物理列必须合并为单个"时间"列，行内不再出现三个独立的时间列。
- **FR-007**：时间列以最近一次运行的耗时为主信息，其次展示最近一次运行时间，再次展示创建时间；完整时间通过悬浮提示获取。
- **FR-008**：任务运行时不得展示上一次运行耗时，应展示运行中状态；从未运行的任务不展示误导性时长，且最后运行时间为空时给出可理解的占位。
- **FR-009**：时间信息不得换行导致行高不一致，数值必须对齐（等宽数字）并与列头语义一致。
- **FR-010**：时间列合并不得丢失 034 的字段含义：创建时间不随运行变化，最后运行时间是最近一次运行的开始时刻，任务是该次执行的起止耗时；时间仍需按既有约定以 UTC 存储、界面按本地时区展示。

### 元数据列

- **FR-011**：元数据列默认只平铺展示前几项有值字段，其余通过"更多元数据"入口收纳，入口需显示收纳项数。
- **FR-012**：收纳内容必须完整可查：标签、完整值可见且可复制；空值与空白值不渲染，全部为空时元数据区域整体隐藏。
- **FR-013**：收纳不得改变行高：有无"更多"入口的任务行在列表中的高度一致。
- **FR-014**：元数据收纳只影响任务列表展示密度，不改变任务元数据的存储、校验与详情页展示。

### 操作列与交互保持

- **FR-015**：操作列必须固定右侧、操作平铺常驻，不使用 `⋯` 菜单、不依赖 hover 显现、不换行。
- **FR-016**：任务列表不得出现任务级"重跑"；单规则重跑入口仍只保留在规则详情页。重建、删除必须使用危险样式并要求二次确认；删除失败时必须在同一行就地提示并可重试。
- **FR-017**：既有交互必须保持：状态筛选、搜索、分页、轮询、深链、上传流程、报告查看、数据准备列与其列内弹层。

### 兼容与约束

- **FR-018**：本功能只改前端展示层与 `docs/design/DESIGN.md`；不新增或修改 OpenAPI 契约，不新增接口端点，不改后端数据模型与执行编排。
- **FR-019**：不引入新的 UI 组件库；新增依赖必须有明确收益并单独说明。
- **FR-020**：既有自动化测试必须继续通过；结构调整造成的断言变化必须等价替换，不得删除既有行为覆盖。
- **FR-021**：所有 UI 变更必须回写 `docs/design/DESIGN.md`，并同步 031 / 033 中"任务列表列顺序与列行为"的现行条款，避免文档与实现分叉。
- **FR-022**：不得把时间列或元数据收纳做成新的"隐藏信息"入口：展开后必须能拿到完整值，操作入口永不收纳。

## 关键实体 *(如果功能涉及数据则填写)*

本功能不引入契约数据实体，只重新组织既有展示对象：

- **任务行**：任务名、状态、任务 ID、失败原因摘要、状态摘要、数据准备摘要、元数据、时间信息、操作入口。
- **时间信息**：创建时间、最近一次运行时间（最近一次运行开始时刻）、任务时长（该次执行耗时）、运行中与从未运行状态。
- **元数据显示项**：有值元数据字段的标签与完整值、平铺项与收纳项、收纳项数。

## 假设

- 用户为运维与巡检人员，桌面环境使用（目标宽度 1280px ~ 1920px），不要求移动端适配。
- 表格内部横向滚动在 1280px 视口下仍属可接受行为（DESIGN.md 第 18 行）；"完全无需内部横向滚动"的目标视口已在 Clarifications 中确认为 1440×900。

- 本轮不涉及接口变更，因此无需 OpenAPI / 生成客户端变更。
- 任务列表列顺序与操作约束以 031 修订后的契约为准，本轮只压缩物理列数与宽度。
- 本轮不引入列宽拖拽、列显隐或用户自定义列能力。
