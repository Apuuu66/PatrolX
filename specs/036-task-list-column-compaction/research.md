# 阶段 0 研究：任务列表列宽压缩

**功能**：036-task-list-column-compaction | **日期**：2026-10-23

## R1 — 目标视口与可用宽度

**决策**：以 1440×900 作为"完全无需表格内部横向滚动"的验收视口；1280×900 沿用既有"允许表格内部滚动、不得页面级横向滚动"口径。

**依据**：

- 布局：侧栏 200px + `Content` 左右内边距各 24px，故列表可用宽度 = 视口 − 248px；1440 → 1192px，1280 → 1032px，1920 → 1600px（`.app-shell-inner` 上限）。
- `docs/design/DESIGN.md` 第 18 行只要求 1280px 下页面本身无横向滚动，宽表允许表格内部滚动。
- 033 的 SC-001 已把"任务列表首屏可见全部种子任务且无页面级横向滚动"绑定到 1440×900，沿用同一视口可避免两版规格互相冲突。

**被拒绝的替代方案**：把目标定到 1280×900。可用宽度只剩 1032px，扣掉 280px 操作列后 5 个信息列平均 150px，任务名与元数据会退化为频繁截断，收益不抵可读性损失。

## R2 — 列宽预算

**决策**：列宽定为 任务 240 / 状态摘要 160 / 数据准备 170 / 元数据 150 / 时间 160 / 操作 280，合计 1160px；`scroll.x` 直接取该合计值 1160。

**依据**：

- 1440 视口的可用宽度为 1192px，因此表格总宽声明值必须 ≤ 1192px；1160 留出 32px 余量，且明显低于现状 1530（压缩 370px，与三个时间列的原宽度同量级）。
- `scroll.x` 必须等于收敛后的合计宽度：AntD 只在 `scroll.x` 大于容器宽度时才启用内部横向滚动，声明值虚高会立刻产生"能放下却仍滚动"的假滚动。
- 操作列 280px 由 031/033 契约锁定（260px 容不下"删除失败"重试入口）。
- 时间列 160px 可容纳"10 秒 / 3 小时前 / 昨天"这类等宽数字文本而不换行；元数据列 150px 可平铺 1~2 项短标签。
- 任务列 240px 保留"名称 + 状态标签 / 任务 ID / 失败原因摘要"三行结构。

**待实现阶段实测确认**：若 1440 下仍出现内部滚动（例如 AntD 单元格内边距挤占），优先下调元数据平铺项数或数据准备列宽，不得把操作列压到 280 以下。

## R3 — 时间三列合一的信息层级

**决策**：单列内三段式——耗时（主，`text-primary`、等宽、字号 14px 语义等价）→ 最后运行时间（次，相对时间 + Tooltip）→ 创建时间（最次，相对时间 + Tooltip，弱化色）。三个既有 `data-testid`（`task-duration` / `task-last-run` / `task-created-at`）保留在同一单元格内，避免既有断言与调试入口失效。

**依据**：

- 034 FR-008/FR-009：最后运行时间是最近一次运行开始时刻、时长是该次执行耗时；从未运行不得显示误导性时长。
- 033 FR-006/FR-007：时间信息不换行、完整时间走 Tooltip、等宽数字。
- 保留三个 testid 可让既有 E2E 断言"等价替换"而不是删除覆盖（036 FR-020）。

**被拒绝的替代方案**：把创建时间并入任务列（任务 ID 下方）。会让"时间"语义分散在两个列里，且任务列已有三行内容，再加行会推高行高。

## R4 — 元数据平铺项数

**决策**：任务列表传 `maxVisible={3}`；`MetadataList` 默认值（4）与详情页 Hero 的行为不变。

**依据**：

- 036 FR-011 要求"前几项 + 更多"，033 FR-010 的详情页上限 4 项保持不变，压缩只作用于任务列表。
- 组件已实现空值过滤、带项数的"更多元数据"入口、完整值与复制、Popover 面板（`data-testid="metadata-more"` / `metadata-more-panel`），无需新增交互形态。
- 列表行高由 `.metadata-list` 的 `line-height: 20px` 与 `flex-wrap` 决定；平铺项减少不会增加行高，收纳与未收纳行的行高差保持在既有范围。

## R5 — 表格布局与固定列

**决策**：保持 AntD `Table` + `fixed: "right"` 操作列不变，新增 `table-layout: fixed`（`web/src/theme.css` 的 `.task-table table` 作用域），并把 `scroll.x` 从 1530 改为收敛后的合计宽度。

**依据**：

- 固定列依赖 AntD 的 sticky 实现，只要求未超过视口；`table-layout: fixed` 保证列宽声明被严格遵守，避免浏览器按内容撑开列导致总宽反弹。
- 固定列在 1280 视口横向滚动时仍贴右，`table-layout: fixed` 不影响 sticky 定位（sticky 作用于 `td/th` 的 `position`）。
- 不引入列宽拖拽（ResizableTable）——那属于被用户明确排除的另一项建议（B）。

**本次实测补充**：`table-layout: fixed` 必须与具体列宽一起生效，否则 AntD `colgroup` 宽度会被内容覆盖；实现阶段用 1440 视口断言 `table.scrollWidth <= table.clientWidth`。

## R6 — 回归风险与保护

**决策**：既有测试断言语义等价替换，不删除行为覆盖；新增 1440 无内部滚动断言与合并列结构断言。

**风险清单**：

| 风险 | 影响 | 保护 |
| --- | --- | --- |
| 合并时间列后既有 E2E 找不到 `task-last-run` / `task-duration` | 回归覆盖丢失 | 三个 testid 保留在同一单元格内，断言改为"同列"结构 |
| 列宽收敛导致操作按钮换行 | 操作可达性下降 | 操作列维持 280px，E2E 断言按钮数量与无换行 |
| `table-layout: fixed` 影响数据准备列内弹层 | 问题明细入口失效 | `task-preparation` 已 `white-space: normal`；E2E 保留列内弹层断言 |
| 1280 下页面级横向滚动被表格撑开 | 布局回归 | 复用 `theme.spec.ts` 的 1280 / 1920 页面级断言 |
| 元数据平铺上限与详情页互相干扰 | 详情页信息缺失 | 只在任务列表调用点传 `maxVisible={3}`，组件默认值不变 |
