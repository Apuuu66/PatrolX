# UI 契约增量：任务列表列宽压缩

本功能不修改 `docs/api/openapi.yaml`。以下契约约束任务列表的前端组件行为与展示规则，实现与测试必须以此为准；与 031 `ui-baseline.md` §4.1、033 `ui-refinement.md` §3 冲突时，以本文件为准（本文件是这两处在任务列表列定义上的增量修订）。

## 1. 列结构与宽度

- 物理列固定为 6 个，顺序：任务 → 状态摘要 → 数据准备 → 元数据 → 时间 → 操作。
- 宽度固定为 240 / 150 / 160 / 140 / 160 / 280（合计 1130px），实现使用 `table-layout: fixed`。
- 表格 `scroll.x` 取合计宽度 1130：1440×900 下不得出现表格内部横向滚动；1280×900 下允许内部横向滚动，但页面级横向滚动必须为 0。

> **实现期实测修正（2026-10-23）**：规划期按“视口 − 侧栏 200 − Content 内边距 48”估算 1440 可用宽度为 1192px，未计入卡体内边距 48px 与卡片边框 2px；实现期在浏览器实测得到 1440 下表格容器 `.ant-table-content` 可用宽度为 **1142px**（与 `specs/031-ui-information-hierarchy/verification.md` 记录的 1142 / 1142 完全一致）。据此按 research R2 的回退顺序，把列宽合计由 1160px 下调为 **1130px**（状态摘要 160→150、数据准备 170→160、元数据 150→140；任务 240、时间 160、操作 280 保持不变，操作列绝不压缩），1440 下留 12px 余量。需求口径（1440×900 无内部横向滚动）未变。
- 不得通过隐藏列、折叠列或响应式堆叠来达到宽度目标。

## 2. 时间列（合并自"创建时间 / 最后运行 / 任务时长"）

- 一个物理列承载三段信息，单元格标记 `data-testid="task-time"`。
- 视觉权重：耗时 > 最后运行时间 > 创建时间。
- `duration_ms` 通过 `getTaskDurationDisplay` 渲染：`running` → "运行中"，无有效值 → `-`；不得回退展示上一次耗时。
- 最后运行时间与创建时间使用相对时间，完整时间通过 Tooltip 获取；单元格内不得出现 `YYYY-MM-DD HH:mm:ss` 文本。
- 三段分别保留 `data-testid="task-duration"` / `task-last-run` / `task-created-at`，既有断言按"同列"结构做等价替换。
- 文本 `nowrap` + 等宽数字；行高不因时间文案变化。

## 3. 元数据列

- `MetadataList` 在任务列表传入 `maxVisible={3}`；详情页 Hero 保持组件默认（4 项）。
- 空值与空白值不渲染；全部为空时整块隐藏，不留占位横线。
- 其余字段进入"更多元数据（N）"Popover：标签与完整值可见、可复制、可键盘开启与关闭（复用既有 `metadata-more` / `metadata-more-panel` 结构）。
- 有无收纳项不改变任务行高度。

## 4. 操作列（保持不变）

- `fixed: "right"`，宽度 280px；横向滚动时始终贴右可见。
- 操作平铺常驻：详情、报告（失败任务为失败日志）、重建（可重建时）、删除；删除失败时就地追加重试入口。
- 不使用 `⋯` 菜单、不依赖 hover 显现、按钮不换行。
- 任务列表不提供任务级"重跑"；重建与删除必须二次确认。

## 5. 保持不变的交互

状态筛选、搜索、分页（默认 10 条）、轮询、深链、上传流程、报告查看、数据准备列的列内弹层与"删除失败就地重试"全部保持既有行为；列压缩不得重置分页或筛选。

## 6. 可访问性与兼容

- 长任务名、任务 ID、失败原因摘要截断显示并通过 `title` / Tooltip 提供完整值。
- 键盘焦点可见，Popover 与按钮可键盘触发。
- 无新增运行时依赖与组件库；不改路由与 URL 语义。
