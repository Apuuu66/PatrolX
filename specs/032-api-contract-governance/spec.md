**创建日期**：2026-10-10

**状态**：已澄清

**输入**：用户描述：巡检系统演进讨论批 A（治理止血 + 持续集成）。已确认决策：删除 `/api/v4` 空壳；删除 `/api/v2/tasks` 任务创建入口，`/api/v3/tasks` 成为唯一创建入口；旧版本冻结、同一能力只留一个当前入口；契约校验加深（operationId 唯一、无空版本、契约与生成客户端一致、废弃标记）；建立最小 CI（后端 lint + 测试 + 契约一致性，前端构建 + 单测，不跑完整 `verify`、不跑 E2E）；规格与文档状态同步（015 标已被替代，016 及路线图/架构/机制/入口文档中的 v4 引用改为现行 v5 入口，025–028/030 状态更新）。

## 背景

本批次是 2026-10-10 巡检系统演进讨论的第一个交付批次，只做"治理止血 + CI"，不引入新的巡检能力，也不改变巡检执行语义：

- **版本入口债务**：`/api/v4` 的实现已在 KPI 测量单元重构（`c429139`）中删除，但空壳路由仍注册；`/api/v2/tasks` 创建入口与 `/api/v3/tasks` 重复，前端已是 v3、但契约与生成客户端中旧入口仍在，测试辅助函数大量直连旧入口；路线图、架构、机制与入口文档仍在引用 v4。
- **契约守卫不足**：现有契约校验只覆盖路径/方法集合与 operationId 是否一致，无法阻止 operationId 重复、空版本前缀、契约与生成客户端漂移，以及未标注的废弃/替代关系。
- **无自动化门禁**：仓库当前没有任何 CI 配置（无 `.github/`），lint、测试、契约一致性与前端构建完全依赖人工执行。
- **规格状态失真**：015 标"已实现"但实现已被替代；016、025、026、027、028、030 已交付或已合入但状态仍停留在"草稿/已澄清"。

后续批次（②持久化与保留、③设备身份校验）各自独立走规格流程。本规格不包含数据库写入、结果入库、保留清理与设备校验的任何改动。

**本轮边界**：

- 不改动巡检规则、执行器、任务执行语义与数据模型；不新增业务能力。
- `/api/v2` 除任务创建外的其余接口（列表/详情/重跑/重建/报告/日志/台账等）保持冻结不变；`/api/v1` 与 `/api/v5` 现有接口不变。
- 直接删除 v2 创建入口是用户本次明确批准的一次性治理动作；此后同类收敛默认按"只留一个当前入口 + 旧入口标注废弃与替代"处理，只有用户明确批准才直接删除。
- CI 只覆盖后端 lint、后端测试、契约一致性（含客户端再生成差异）、前端构建与前端单测；不跑完整本地全流程 verify、不跑 E2E。

## 用户场景与测试 *(必填)*

### 用户故事 1 - 接口入口收敛，同一能力只有一个当前入口（优先级：P1）

平台维护者面对契约、生成客户端与实现时不再需要猜测哪个版本才是当前入口：任务创建只剩 v3；v4 空壳彻底消失；v2 其余接口冻结保留。

**优先级理由**：入口重复是文档引用混乱、调用方误用与客户端膨胀的根源；不先收敛，后续契约守卫没有稳定的检查基线。

**独立测试**：删除旧创建入口与 v4 空壳后，重新生成契约与前端客户端，分别在仓库与契约中检索：任务创建操作唯一（v3），不存在 v4 路径与 v4 路由注册；通过 API 冒烟验证 v3 创建全流程可用，v2 列表/详情等既有接口行为与改造前一致。

**验收场景**：

1. **给定** 当前仓库，**当** 删除任务创建的旧入口，**则** 契约中只剩一个任务创建操作，后端路由与生成客户端中不再存在旧创建入口，第一方调用方（前端 API 层、测试辅助、E2E 夹具）全部改用当前入口。
2. **给定** 旧创建入口已删除，**当** 重新生成契约与前端客户端，**则** 生成产物与仓库内容完全一致，无残留引用。
3. **给定** v4 空壳路由，**当** 完成清理，**则** 后端不再注册任何 v4 前缀路由，契约与面向当前系统的文档中不再存在 v4 引用。
4. **给定** v2 的列表、详情、重跑、日志、台账等接口，**当** 创建入口被删除后，**则** 这些接口的路径、字段与行为保持不变。
5. **给定** 现有测试套件，**当** 全部迁移到当前创建入口后运行，**则** 上传、幂等（同名同包复用、同名异包冲突）等既有边界行为与改造前一致。

---

### 用户故事 2 - 契约守卫自动拦截版本债务（优先级：P1）

维护者修改接口时，重复 operationId、空版本前缀、契约与生成客户端漂移、未标注的废弃入口会在测试阶段被直接拦截，不再依赖人工审查。

**优先级理由**：治理结论只有固化为自动守卫才能长期成立；这也是 CI 门禁的核心检查内容。

**独立测试**：分别构造四类违规（重复 operationId、只剩空壳的版本前缀、契约变更后未重新生成客户端、旧入口未标注废弃与替代），守卫必须以可定位的失败信息拦截；恢复后全绿。

**验收场景**：

1. **给定** 契约中存在两个相同 operationId，**当** 运行守卫，**则** 失败并指出重复的 operationId 及涉及的路径。
2. **给定** 后端注册了一个不含任何操作的版本前缀，**当** 运行守卫，**则** 失败并指出空版本前缀。
3. **给定** 契约已变更但生成客户端未同步，**当** 运行门禁，**则** 失败并提示重新生成客户端。
4. **给定** 同一能力同时存在新旧两个入口，**当** 运行守卫，**则** 未标记废弃或未注明替代入口的旧入口被判失败。

---

### 用户故事 3 - 每次推送自动跑最小门禁（优先级：P2）

维护者推送或发起合并请求后，后端与前端门禁自动执行并给出结论；门禁不通过则不能合入。

**优先级理由**：自动化是治理长期有效的保障，但它不改变产品行为，优先级低于入口收敛与契约守卫本身。

**独立测试**：在干净环境推送一次改动，观察门禁自动触发；四类检查（后端 lint、后端测试、契约一致性、前端构建与单测）结果与本地逐条执行一致；人为引入失败可阻断合入。

**验收场景**：

1. **给定** 一次推送到主分支或合并请求，**当** 门禁触发，**则** 自动执行后端静态检查、后端测试与契约一致性检查。
2. **给定** 一次前端改动，**当** 门禁触发，**则** 自动执行前端依赖安装、生产构建与前端单测。
3. **给定** 任一检查失败，**当** 查看门禁结果，**则** 明确显示失败项，且契约与客户端一致性检查不得被静默跳过。
4. **给定** 一次完整门禁运行，**当** 查看结果，**则** 未触发完整本地全流程与 E2E，整体反馈时间不超过 15 分钟。

---

### 用户故事 4 - 文档与规格状态反映真实现状（优先级：P3）

后续开发者与巡检运营按文档查找 KPI 能力或历史规格时，看到的是当前入口与真实交付状态，而不是已删除的 v4 设计与过期状态。

**优先级理由**：影响信息可信度，不阻塞运行，但会持续制造误判；可与前三个故事并行交付。

**独立测试**：按下述清单核对：015 标注已替代及替代关系；016 的 v4 引用改为现行 v5 入口或标注历史；025–028、030 状态与实际交付一致；面向当前系统的文档中不存在 v4 引用。

**验收场景**：

1. **给定** 规格 015 的实现已被测量单元 KPI 重构替代，**当** 查看其状态行，**则** 明确标注"已被替代"及替代实现，不再显示"已实现"。
2. **给定** 016 与路线图/架构/机制/入口文档中的 v4 引用，**当** 完成同步，**则** 引用指向现行 v5 入口，或显式标注为历史设计。
3. **给定** 025–028、030 已交付或已合入，**当** 查看状态行，**则** 状态与实际交付一致（已实现）。
4. **给定** 面向当前系统的文档，**当** 全局检索已删除的版本前缀，**则** 无未标注的残留引用。

### 边界情况

- 旧创建入口删除后，未知外部调用方继续使用它时，按平台默认"未找到"行为处理，不提供重定向或过渡期（见假设）。
- 遗留测试或夹具依赖旧创建入口的宽松表单（不传包类型、不传省份/运营商）时，迁移到当前入口必须补齐当前入口的必填元数据；不得为通过迁移而放宽当前入口的校验规则。
- 同一数据包重复上传的幂等与冲突语义（同包复用任务、同名异包冲突）在迁移前后必须完全一致。
- 被替代规格（015）内部的历史设计产物允许保留旧版本前缀，但必须带替代标注，避免被当成现行指引。
- 若客户端再生成产生纯格式差异，必须通过修正生成流程消除差异；不允许以"人工忽略 diff"方式通过门禁。
- CI 在干净检出环境运行，不得依赖开发者机器缓存或预先存在的生成产物。
- 门禁失败只报告，不自动改写契约、客户端或提交内容。
- 契约中存在尚无替代入口的废弃操作时，必须显式注明替代关系或说明不适用，不允许留空白。

## 需求 *(必填)*

### 功能需求

**版本入口治理**

- **FR-001**：系统必须删除 `/api/v2/tasks` 的任务创建能力；任务创建只能通过 `/api/v3/tasks` 完成。
- **FR-002**：删除创建能力后，`/api/v2` 的其余接口必须保持冻结：路径、字段语义与行为不得改变。
- **FR-003**：系统必须彻底移除 `/api/v4` 空壳路由，后端不得注册任何 v4 前缀路由。
- **FR-004**：第一方调用方必须全部改用当前创建入口：前端 API 层、测试辅助函数与 E2E 夹具中不得存在旧创建入口的调用；同一数据包"重复上传复用、同名异包冲突"的幂等语义必须保持不变。
- **FR-005**：契约、后端实现与生成的前端客户端必须同步更新：删除旧入口后重新生成客户端，且生成产物入库。
- **FR-006**：同一能力在契约中只允许存在一个当前入口；若必须保留旧入口，旧入口必须标记废弃并注明替代入口。

**契约守卫**

- **FR-007**：契约校验必须覆盖 operationId 唯一性，出现重复即失败并指明重复项。
- **FR-008**：契约校验必须覆盖空版本前缀：任何版本前缀在契约与实现中都必须至少包含一个真实操作。
- **FR-009**：契约校验必须覆盖契约与生成客户端一致性：以契约为源重新生成客户端后，仓库中的客户端必须无差异。
- **FR-010**：契约校验必须覆盖废弃与替代标记：以“去除版本前缀后的路径 + 方法”判定同一能力，存在多个版本入口时，非当前入口必须标记废弃并注明替代入口，否则失败。
- **FR-011**：上述守卫必须以自动化测试形式纳入既有测试套件，本地与 CI 执行同一套检查。
- **FR-012**：守卫失败信息必须指出违规的具体路径与操作，禁止只输出笼统失败。

**文档与规格同步**

- **FR-013**：规格 015 的状态必须改为"已被替代"，并注明替代实现（测量单元 KPI 重构）；其历史设计产物保留并受替代标注保护。
- **FR-014**：规格 016、025、026、027、028、030 的状态必须与其真实交付状态一致。
- **FR-015**：面向当前系统的文档（路线图、架构、设计机制、入口说明）中不得存在未标注的 v4 引用；涉及 KPI 能力的引用必须指向现行 v5 入口。
- **FR-016**：规格 016 的契约、研究与任务产物中指向 v4 的引用必须修正为现行 v5 入口，或显式标注为历史设计。

**持续集成门禁**

- **FR-017**：每次推送到主分支与每次合并请求必须自动触发门禁。
- **FR-018**：门禁必须包含后端静态检查（lint 与格式检查）、后端测试、契约一致性检查（含客户端再生成差异检查）。
- **FR-019**：门禁必须包含前端依赖安装、生产构建与前端单元测试。
- **FR-020**：门禁不得运行完整本地全流程与 E2E；任一检查失败必须使门禁失败，且不得静默跳过检查。
- **FR-021**：门禁必须复用仓库既有命令与锁文件，不引入与本地不一致的第二套检查脚本。

### 关键实体

- **能力入口**：方法 + 路径形式的对外可调用操作，归属于某个版本前缀；同一能力只允许一个当前入口，其余入口必须废弃并注明替代。
- **契约守卫**：把治理规则固化为可重复执行的自动检查，输出可定位的违规项，是 CI 门禁的组成部分。
- **规格状态**：草稿 / 已澄清 / 已实现 / 已被替代；必须反映真实交付情况。
- **门禁**：推送与合并请求自动触发的检查集合（后端静态检查、后端测试、契约一致性、前端构建与单测）。

## 假设

- 仓库托管在 GitHub，门禁采用 GitHub Actions；若未来迁移托管平台，检查项保持不变，仅触发方式替换。
- 外部调用方对旧创建入口的使用不在支持范围内：删除后按平台默认"未找到"行为处理，不提供重定向、墓碑或过渡期。
- 直接删除 v2 创建入口是本次演进讨论中用户明确批准的一次性动作；此后同类收敛默认采用"保留旧入口 + 标注废弃与替代"，只有用户明确批准才直接删除。
- 016 的能力（受控派生指标维护）在测量单元重构后仍以 v5 形式存在，因此 016 状态按"已实现"处理，仅修正 v4 引用；若实现核对发现某部分能力确实不存在，则在该规格中标注被替代范围。
- 016 的历史契约产物允许保留 v4 作为历史记录，但必须显式标注"历史设计，现行入口见 v5"，不得充当现行指引。
- CI 在干净检出环境运行，依赖使用仓库既有锁文件与生成命令，不引入新的包管理器或构建工具。
- 门禁"阻止合并"依赖仓库分支保护设置（由管理员把工作流配置为必需检查）；代码侧交付物为工作流与自动检查本身。
- 本批次不改变数据模型、不写数据库、不调整保留策略与设备校验；这些属于后续批次。
