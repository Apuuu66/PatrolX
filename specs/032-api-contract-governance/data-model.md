# 阶段 1 数据模型：API 契约治理与持续集成门禁

**日期**：2026-10-10 | **规格**：[spec.md](spec.md) | **计划**：[plan.md](plan.md)

本功能不新增运行时数据模型、不写数据库、不改任务/规则契约，因此本文件只定义治理概念模型——它们是守卫与文档同步的判定对象。

## 能力入口（Capability Entry）

- **含义**：对外可调用操作的治理单元，由 HTTP 方法 + 去版本前缀路径唯一标识，例如 `POST /tasks`。
- **属性**：版本前缀（如 `/api/v2`）、完整路径、方法、operationId、废弃标记、替代入口引用。
- **唯一性规则**：同一能力最多一个"当前入口"；版本号最大者为当前入口（必须未标废弃）；其余版本入口必须 `deprecated: true` 且描述中给出替代入口路径。
- **校验**：契约守卫按 `(method, 去版本前缀路径)` 分组检查；违规时输出分组与涉及版本。

## 版本前缀（Version Prefix）

- **含义**：`/api/vN` 形式的 API 表面分区。
- **属性**：版本号、注册来源（`app.api.router` 中的 `*_router`）、契约中的操作数量。
- **规则**：代码侧注册的每个版本前缀必须至少包含一个真实操作；契约中出现的每个版本前缀必须能对应代码侧注册；两侧集合一致。
- **当前状态（改造前 → 改造后）**：v1、v2、v3、v4(空)、v5 → v1、v2、v3、v5。

## 规格状态（Specification Status）

- **状态集合与转换**：
  - `草稿` → `已澄清`（clarify 完成）
  - `已澄清` → `已实现`（tasks 全部完成且交付合入）
  - `已实现` → `已被替代`（实现被后续重构整体替代，注明替代者）
- **本次迁移**：015 → 已被替代；016、025、026、027、028、030 → 已实现；032 自身按流程推进。
- **校验**：状态行必须与 tasks 完成度、合入记录一致；被替代规格必须给出替代者路径或重构名称。

## 门禁检查项（Gate Check）

- **属性**：名称、检查命令、判定条件、失败输出、超时上限（15 分钟）。
- **检查项集合**：后端静态检查、后端测试（含三条契约守卫）、契约一致性（`build.py contract`）、前端依赖安装、客户端零漂移、前端构建、前端单测。
- **排除项**：完整本地全流程（verify）与 E2E 不在门禁内。
- **失败语义**：任一项失败 → 门禁失败；不得静默跳过；门禁不改写任何仓库文件。

## 非目标（明确不建模）

- 不新增数据库表/字段，不改任务、规则结果、KPI 与资源观测模型。
- 不定义保留策略、清理与设备校验相关实体（属于后续批次）。
