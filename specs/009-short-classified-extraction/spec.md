# 功能规格：分类短路径解压与准备状态提示

**功能分支**：待任务评审后创建（`feature/*`）

**创建日期**：2026-09-15

**状态**：草稿

**输入**：用户描述：“分类后的 log 包直接解压到 log 目录，kpi 包也一样；识别到完整路径超过 Windows 260 时提前报错；解压状态和失败原因要在界面上提示出来。”

## Clarifications

### Session 2026-09-15

- Q: “直接解压到 log 目录”是否要压缩包内部目录结构？ → A: 保留内部相对结构；只移除系统额外添加的来源压缩包目录层。
- Q: 多个来源生成同一目标路径时如何处理？ → A: 不覆盖已有文件；按稳定处理顺序保留第一个，后续来源记录为冲突。
- Q: 260 长度限制如何生效？ → A: 在 Windows 传统路径限制环境下检查完整目标路径；达到或超过 260 即在写入前拒绝，非 Windows 环境不应用该限制。
- Q: 解压状态如何展示？ → A: 任务列表页对应任务卡片内以可折叠“数据准备”区域展示；不使用弹窗或独立页面，不与普通巡检规则混排，也不计入普通规则摘要。
- Q: 任务删除失败是否也要在界面展示？ → A: 需要；在任务列表使用行内错误提示展示任务、原因和可重试操作。完整提示展示 5 秒后自动收起，但任务行保留可重新展开的“删除失败”状态，不使用自动消失的全局轻提示替代。
- Q: `task_id` 是否同步缩短？ → A: 不允许修改；`task_id` 生成规则和既有任务身份必须保持不变。

## 约束与不变量 *(必填)*

- **C-001**：本功能不得修改 `task_id` 生成规则；不得缩短、哈希化、重命名或迁移既有 `task_id`。
- **C-002**：`task_id` 必须继续保持由归档包名称派生，并维持“一个归档包对应一个任务”的隔离模型。
- **C-003**：即使分类路径缩短后仍超过 Windows 传统路径上限，也不得通过修改 `task_id` 规避；系统应提前明确失败并提示用户处理数据包或运行环境。
- **C-004**：本功能不得破坏既有任务结果、输出目录身份、公共接口字段语义和普通巡检规则摘要口径。

## 用户场景与测试 *(必填)*

### 用户故事 1 - 分类现场直接落位（优先级：P1）

作为巡检用户，我希望日志、KPI 等分类压缩包在解压后直接进入对应的分类工作目录：目录结构按数据类型一眼可读，不因为来源压缩包名而增加一层重复路径，也让完整文件路径更短。

**优先级理由**：这是本次需求的核心收益。用户需要按分类快速定位文件，同时降低 Windows 路径过长导致的执行和清理失败。

**独立测试**：给定一个包含分类子包的样例数据包，执行任务后检查分类工作现场中每个文件的相对路径，确认只包含分类前缀和压缩包内部路径，不额外包含来源包目录层。

**验收场景**：

1. **给定** 一个会被识别为日志类的压缩包，**当** 任务解压完成，**则** 其内部文件出现在日志分类目录下，且路径中不再额外插入来源压缩包目录层。
2. **给定** 一个会被识别为 KPI 类的压缩包，**当** 任务解压完成，**则** 其内部文件出现在 KPI 分类目录下，且路径中不再额外插入来源压缩包目录层。
3. **给定** 分类包内部本身带有业务目录结构，**当** 解压完成，**则** 系统保留该内部结构，不把所有文件强行平铺到分类根目录。
4. **给定** 同一任务重复执行或单规则重跑，**当** 解压现场仍有效，**则** 系统复用已生成的分类现场，不重复展开。
5. **给定** 已存在旧布局的历史任务，**当** 用户重新触发解压或重跑，**则** 系统按新布局重建现场，并保证原上传包不变。

### 用户故事 2 - 长路径提前失败（优先级：P1）

作为巡检用户，我希望在 Windows 环境下，如果某个待生成文件的完整路径会超过系统传统路径上限，系统在写入前就明确报告原因，而不是等到写入失败、任务中断或删除残留时才出现难以理解的错误。

**优先级理由**：长路径问题会导致半成品目录、任务删除失败和排查成本升高；提前失败可以保护任务现场。

**独立测试**：给定一个包含超长内部路径的样例包，在 Windows 传统路径限制生效的环境下执行任务，验证对应目标在写入前被拒绝、错误信息可读，数据准备显示对应分类项失败，且没有该目标的半成品文件；其他可安全处理的分类项按容错策略继续。

**验收场景**：

1. **给定** 一个待写入文件的完整路径达到或超过 260 字符，**当** 解压流程准备创建该文件，**则** 系统在写入前拒绝该项并给出明确失败原因。
2. **给定** 长路径失败发生，**当** 用户查看任务，**则** 能看到路径长度、上限、来源包或来源路径、目标相对路径中的关键信息。
3. **给定** 主包证据现场或分类现场中出现长路径目标，**当** 检测失败，**则** 主包证据现场长路径失败阻断后续 prepare 和巡检；分类项清理该目标的临时文件或 staging，不把该目标暴露给规则执行，其他安全分类项可继续。
4. **给定** 相同路径不会超过 Windows 传统上限，**当** 解压执行，**则** 不因该检查产生误报。
5. **给定** 非 Windows 环境，**当** 执行任务，**则** 不应用 260 字符的 Windows 传统路径限制。

### 用户故事 3 - 数据准备状态可见（优先级：P2）

作为巡检用户，我希望在任务列表页对应任务卡片内看到可折叠的数据准备/解压状态：主包和各分类是否成功、耗时、冲突数量和失败原因，而不需要进入详情页或查看日志文件，也不把内部准备步骤误认为普通巡检规则。

**优先级理由**：解压失败会阻断或影响巡检结果；如果界面不展示，用户只能从任务状态或日志中间接排查。

**独立测试**：给定成功、局部冲突和失败三类解压任务，打开任务列表页，检查对应任务卡片内的数据准备区域能区分状态并显示可读原因，同时普通巡检规则摘要不包含这些内部步骤。

**验收场景**：

1. **给定** 解压成功，**当** 用户查看任务列表，**则** 对应任务卡片显示数据准备成功摘要；展开后显示主包和相关分类准备状态与耗时。
2. **给定** 分类子包目标路径冲突，**当** 用户查看任务列表，**则** 对应任务卡片默认展开数据准备区域；对应分类显示告警状态，并说明保留了哪个文件、哪个来源被跳过。
3. **给定** 分类子包因长路径或解析失败被拒绝，**当** 用户查看任务列表，**则** 对应任务卡片默认展开数据准备区域；对应分类显示失败状态，并展示原因、来源和目标路径。
4. **给定** 主包解压失败，**当** 用户查看任务列表，**则** 对应任务卡片默认展开数据准备区域并显示主包失败；普通巡检规则不开始执行。
5. **给定** 解压步骤有失败或告警，**当** 用户查看任务摘要，**则** 这些内部准备结果不改变普通巡检规则的统计口径。

### 用户故事 4 - 删除失败可见可重试（优先级：P2）

作为巡检用户，我希望删除任务失败时，任务列表能清楚告诉我失败原因和涉及的现场位置，而不是只看到一个全局短暂消失的“删除失败”，然后不知道任务是否还残留。

**优先级理由**：删除失败会直接造成残留数据和理解成本；特别是路径过长、目录被占用等场景需要用户判断重试或清理。

**独立测试**：给定一个删除会失败的任务，在任务列表触发删除后，验证系统返回明确失败状态，界面持续展示错误上下文，并且不会提示“任务已删除”。

**验收场景**：

1. **给定** 一个因 Windows 路径过长而无法删除现场的任务，**当** 用户在任务列表点击删除，**则** 对应任务行内显示删除失败提示，并展示任务名或任务标识、失败原因、相关现场位置和长度限制信息；完整提示展示 5 秒后自动收起。
2. **给定** 一个因任务正在排队或执行而无法删除的任务，**当** 用户触发删除，**则** 界面提示“任务正在排队或执行，不能删除”，任务仍保持原状态。
3. **给定** 删除失败后，**当** 用户点击重试，**则** 系统重新执行删除；成功后失败状态和错误提示消失，任务从列表移除。
4. **给定** 删除失败提示已展示 5 秒，**当** 提示自动收起，**则** 任务行仍保留“删除失败”状态标识，用户可以重新展开查看原因并重试。
4. **给定** 删除请求导致部分现场仍残留，**当** 接口返回失败，**则** 界面不得展示“任务已删除”。

### 边界情况

- 当多个来源包需要生成同一个目标路径时，系统不覆盖已有文件；按稳定处理顺序保留第一个，后续来源记录为冲突。
- 当目标路径超长时，系统不尝试静默截断、改名或 hash 化；当前版本应明确失败，便于用户修正数据包或运行环境。
- 当压缩包内部路径包含穿越、链接、重复路径或超过安全预算时，继续按既有安全规则拒绝。
- 当主包解压失败时，阻断后续 prepare 和巡检；当单个分类项失败时，记录原因并允许其他可安全处理的内容继续。
- 当来源压缩包没有明确分类时，按现有分类规则落入未分类现场，并保持可追溯。
- 当任务复用有效解压现场时，必须校验 manifest 中的路径限制上下文或策略指纹；限制上下文变化时按新限制重建，避免绕过后续路径检查。
- 当历史任务使用旧布局时，本次不要求迁移历史磁盘数据；重新执行时按新布局重建。
- 当任务删除因路径过长、目录被占用或权限不足失败时，系统必须返回明确失败并保留错误上下文；不得展示为删除成功。
- 当删除操作只处理了部分现场就失败时，系统必须报告失败状态；任务列表不得将该任务描述为已完全删除。

## 需求 *(必填)*

### 功能需求

- **FR-001**：系统必须把分类压缩包直接展开到其识别出的分类工作目录；除分类目录外，不得额外插入来源压缩包目录层。
- **FR-002**：系统必须保留分类包内部相对结构，不把文件强制平铺。
- **FR-003**：系统必须继续保留主包原始证据现场，且普通巡检逻辑不得读取该现场作为普通输入。
- **FR-004**：系统必须保证原始上传包内容不变。
- **FR-005**：系统必须在生成每个分类工作文件前确定其完整目标路径，并在 Windows 传统路径限制生效的环境下检查该路径是否达到或超过 260 字符。
- **FR-006**：系统必须在路径超长检查失败时阻止该文件写入，并提供包含长度、上限、来源信息和目标相对路径的可读错误。
- **FR-007**：系统必须在长路径失败时清理该目标对应的 staging 或未写入目标；主包证据现场长路径失败必须阻断后续 prepare 和巡检，分类项长路径失败不得留下该目标的半成品文件。
- **FR-008**：系统必须记录每个分类项的来源、目标、状态和失败原因，确保用户和后续报告能追溯“文件从哪里来、为什么失败”。
- **FR-009**：系统必须以稳定顺序处理同任务内的来源，避免同一输入重复执行产生不同结果。
- **FR-010**：系统遇到目标路径冲突时必须不覆盖已有文件，并把后续来源标记为冲突。
- **FR-011**：系统必须在任务列表页对应任务卡片内提供可折叠的数据准备状态区域，不使用弹窗或独立页面；展示范围包括主包解压和各分类解压，不与普通巡检规则混排。
- **FR-012**：数据准备区域默认显示状态摘要，并支持用户展开查看状态、耗时和可读原因；失败或冲突时必须默认展开，且展示足以定位问题的来源与目标信息。
- **FR-013**：数据准备结果不得计入普通巡检规则的摘要统计，也不得作为普通巡检规则展示。
- **FR-014**：系统必须维持既有路径穿越、链接、重复项、深度、文件数量和总量等安全防护。
- **FR-015**：普通规则仍然只能读取自身声明范围内的最终可巡检文件，不得感知来源压缩包的处理细节。
- **FR-016**：涉及任务列表或任务详情响应的数据准备信息时，公共接口契约必须先同步更新，再实现展示。
- **FR-017**：任务删除失败必须返回统一的可读错误信息，并包含任务标识、失败原因和可用的下一步操作提示。
- **FR-018**：路径过长导致删除失败时，错误信息必须包含完整路径长度、上限和相关现场位置；目录占用、权限不足等错误也必须给出可读原因。
- **FR-019**：任务列表必须在删除失败时使用行内错误提示展示完整信息 5 秒；5 秒后自动收起为持续可见的“删除失败”状态标识，并允许重新展开。不能只依赖自动消失的全局轻提示。
- **FR-020**：删除失败提示必须支持用户重新触发删除；重试成功后提示必须自动清除。

### 关键实体 *(如果功能涉及数据则填写)*

- **分类工作现场**：任务目录下按数据类型组织的最终可巡检文件集合；路径由分类目录和压缩包内部相对路径组成。
- **原始证据现场**：主包解压后的原始文件现场；用于保留证据和支撑重建，不作为普通规则输入。
- **解压项记录**：一个来源包、日志压缩文件或普通文件的落位记录；包含来源路径、目标路径、状态、错误、冲突原因和检查结果。
- **数据准备状态**：主包与各分类解压的可展示结果；包含状态、耗时、数量汇总和原因。
- **路径限制检查**：对完整目标路径长度的前置校验；在 Windows 传统路径限制环境返回长度、上限和目标上下文。

## 成功标准 *(必填)*

### 可度量结果

- **SC-001**：对代表 KPI、日志、告警、配置、资源和未分类的样例任务，100% 的分类文件落在正确分类目录，且路径中没有额外来源包目录层。
- **SC-002**：对一组代表性路径，分类工作现场的完整路径长度低于旧布局同等样例；只要移除来源包层即可低于 260 的样例，改造后必须能成功写入。
- **SC-003**：在 Windows 传统路径限制环境下，100% 达到或超过 260 的目标路径在写入前被拒绝，且没有对应的半成品分类文件。
- **SC-004**：100% 的解压失败项具有可读原因，至少包含状态、来源和目标上下文；长路径错误额外包含实际长度和上限。
- **SC-005**：100% 的任务列表任务卡片能展示主包和各分类的数据准备摘要；用户无需读取执行日志或进入详情页即可知道准备失败原因。
- **SC-006**：普通巡检规则摘要统计中，内部数据准备项的数量为 0；普通规则结果口径保持不变。
- **SC-007**：相同数据包在相同状态下重复执行时，分类落位、冲突记录和结果语义保持一致。
- **SC-008**：100% 的删除失败请求在任务列表行内展示包含任务上下文和失败原因的完整错误提示至少 5 秒，并保留可重新展开的失败状态标识。
- **SC-009**：100% 的删除失败响应不会被前端展示为“任务已删除”；用户重试成功后，提示消失且任务从列表移除。

## 假设

- 当前版本优先使用可读的分类路径，不引入短 hash 文件名；如果移除来源包层后仍超过 260，应明确失败。
- `task_id` 生成方式禁止调整；若路径仍超长，不得通过缩短或替换 `task_id` 规避。
- 主包原始证据现场继续保留；本功能只调整分类工作现场的落位。
- 目标路径冲突采用“先到先得、不覆盖”的策略。
- Windows 260 检查仅在传统路径限制生效时强制；长路径支持启用时不按传统 260 限制拒绝，注册表不可读时保守按传统限制处理。
- 历史输出不强制迁移；重新执行时按新规则重建。
- 桌面端界面是主要使用场景。
