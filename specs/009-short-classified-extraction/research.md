# 研究：009 分类短路径解压、长路径防护与状态展示

## 1. 分类现场落位

- **决策**：分类工作现场直接使用 `output/<task_id>/<category>/...`；不再插入来源子压缩包名或来源目录层。压缩包内部相对结构继续保留。
- **理由**：这是降低 Windows 完整路径长度的主要手段，同时保持用户可以直接按 `logs/`、`kpi/` 等类型定位文件。
- **备选方案**：
  - 继续保留来源包目录层：路径可读但重复且过长，拒绝。
  - 使用短 hash 或截断包名作为目录身份：会破坏可读性，且用户已明确不允许修改 `task_id` 或用短身份规避。
  - 启用 `\\?\` 前缀：只是运行时绕过，不解决展示、删除和用户理解问题；用户已要求回滚该方案。
- **影响**：manifest 内部结构需要升级，规则 `source_patterns` 仍然匹配 `logs/...`、`kpi/...`，语义不变；既有路径断言和样例需要在实现阶段更新。

## 2. manifest 演进

- **前置约束**：已存在的 `ExtractPolicyConfig`、`skip_all`、`skip_paths`、白名单策略和 manifest policy fingerprint 必须继续生效；本功能只调整策略命中后的记录结构和分类目标，不删除策略能力。

- **决策**：将解压 manifest 从 v3 升级到 v4；为普通分类文件增加落位记录，并让子包、日志 gzip、普通文件记录统一的可展示状态、来源、目标、错误码、路径长度和上限。
- **理由**：数据准备 UI 不能只依赖隐藏规则摘要，冲突和失败需要保留来源与目标上下文；普通文件当前缺少成功落位记录。
- **备选方案**：
  - 继续只从隐藏规则结果推断：信息太粗，无法完整展示冲突来源与目标。
  - 把准备明细写入 `task.json`：会把内部基础设施状态混入普通巡检结果，并增加契约和统计口径耦合风险。
- **兼容策略**：v3 manifest 不迁移；重新执行时按 v4 重建。历史任务的 `preparation` 可为 `null` 或按既有隐藏规则给出低精度摘要，普通规则结果与统计不变。

## 3. Windows 长路径策略

- **决策**：引入显式路径限制策略。传统 Windows MAX_PATH 限制生效时，在创建目录或写入文件前检查解析后的完整目标路径，长度达到或超过 `260` 即拒绝该项。
- **判定方式**：仅在 Windows 且系统未启用长路径支持时启用 `260` 检查；注册表不可读时按传统限制保守处理。非 Windows 平台不强制该阈值，测试通过注入策略模拟。
- **错误内容**：必须包含实际长度、上限、来源和目标相对路径；错误码使用 `path_too_long`。不使用 `\\?\` 前缀自动改写。
- **备选方案**：
  - 捕获系统错误后提示“失败”：用户无法判断原因，已排除。
  - 全局启用长路径改写：会隐藏根因，且用户明确要求回滚。
  - 缩短 `task_id`：违反本功能约束，禁止。

## 4. 冲突与稳定顺序

- **决策**：主包证据文件按稳定排序递归处理；同一目标路径已存在时不覆盖，保留第一个来源，并把后续来源记录为冲突或拒绝。压缩包 checksum 重复仍按重复跳过。
- **理由**：重复执行和同一现场多来源必须保持确定性；覆盖会破坏既有可巡检文件。
- **补充**：分类根目录只在 manifest 失效重建时清空；运行过程中遇到已有目标一律不覆盖。

## 5. 数据准备 API 读取模型

- **决策**：任务列表和任务详情响应增加可选 `preparation` 字段。该字段由 `output/<task_id>/.patrolx-extracted.json` 与隐藏 `pkg.extract.*` 结果在读取时组装，不进入普通规则统计。
- **理由**：任务列表需要直接展示准备状态；派生读取模型可以保持普通 `RuleResult` 和任务统计口径不变，也允许历史任务返回 `null`。
- **备选方案**：
  - 前端逐任务请求 manifest：列表请求放大，且暴露内部文件契约。
  - 前端解析隐藏规则列表：隐藏规则不属于普通展示契约，且缺少明细。
- **契约策略**：新增字段均为可选，属于非破坏性 `/api/v2` 扩展；`TaskSummaryV2.stats` 和 `SystemInspectionV2.rules` 口径不变。

## 6. 任务删除失败可观测性

- **决策**：删除文件现场失败时返回结构化错误 `task_delete_failed`，HTTP 状态使用 `500`；`detail` 携带任务、现场位置、失败路径、可选路径长度和上限。成功前不删除数据库记录；本地任务失败后恢复可读取的 `task.json`。
- **理由**：失败后任务必须仍能出现在列表中并支持重试；当前先删数据库记录、再删目录的方式可能在部分删除后让任务从列表消失。
- **备选方案**：
  - 只把 `OSError` 转成普通 message：丢失路径长度和现场上下文。
  - 使用 `409` 表达所有删除失败：与既有 `task_busy` 语义混杂。
  - 前端只展示短暂 toast：用户无法保留错误上下文，已排除。
- **前端策略**：删除失败完整提示展示 5 秒后收起，任务卡片保留“删除失败”状态并允许重新展开；状态保存在当前页面状态中，重试成功后清除。

## 7. 前端形态

- **决策**：任务列表页每个任务卡片内新增“数据准备”折叠区；点击标题或箭头展开，不使用 Modal、Drawer 或独立页面。
- **默认状态**：全部成功时折叠；失败、冲突或长路径错误默认展开。
- **理由**：保持多任务对比上下文，避免遮挡列表，也避免形成第二个详情页。
