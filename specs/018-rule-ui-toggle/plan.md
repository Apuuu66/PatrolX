# 实现计划：界面规则启停

**分支**：`018-rule-ui-toggle` | **日期**：2026-09-22 | **规格**：[spec.md](spec.md)

**输入**：来自 `/specs/018-rule-ui-toggle/spec.md` 的功能规格

## 摘要

在现有巡检系统中引入持久化的规则启停状态。既有配置中的停用规则只作为首次初始化来源；初始化后，界面状态成为唯一运行时事实来源。注册表继续装载全部规则定义，任务执行按任务开始时的启用状态过滤普通规则和对应私有 prepare。前端在既有规则列表页改用专用的分页规则状态列表，提供状态开关、筛选和错误提示。既有 `/api/v2/inspectors` 保持兼容；新增 `/api/v2/inspector-states` 数据列表默认分页 10 条，启停更新要求管理员权限。

## 技术上下文

**语言/版本**：Python 3.11+；前端 TypeScript / Vite

**主要依赖**：FastAPI、Pydantic v2、SQLAlchemy、React、Ant Design

**存储**：现有 SQLite 元数据库新增规则启停状态表；巡检结果仍保存在 `output/` 文件

**测试**：后端 pytest；前端 Vitest；契约校验与前端客户端生成使用 `build.py contract` / `build.py gen-web-api`

**目标平台**：本地桌面浏览器访问的离线巡检系统

**项目类型**：FastAPI 后端 + React 前端的 Web 应用

**性能目标**：规则列表启停操作在常规本地数据规模下 1 秒内返回

**约束条件**：离线优先；一个包一个任务一个输出目录；OpenAPI 契约驱动；历史任务结果不可因启停变化被改写

**规模/范围**：系统内巡检规则数量为数十级；当前只支持单条启停，不提供批量、定时或审批流

## 宪法检查

*门禁：必须在阶段 0 研究前通过。阶段 1 设计后重新检查。*

- **离线优先**：符合；只管理本地规则状态，不连接被检系统。
- **一个包、一个任务**：符合；启停状态只影响新任务规则集合，不改变任务目录模型。
- **契约驱动**：符合；接口新增字段和路径会同步 OpenAPI、Pydantic Schema、测试和前端客户端。
- **单文件失败隔离**：符合；停用规则不进入计划，启用规则失败隔离语义不变。
- **规则准备契约**：符合；普通规则停用时其私有 prepare 一并排除，prepare 仍只属于 owner。
- **调度器无业务硬编码**：符合；执行器只消费传入的启用规则集合。
- **历史结果保护**：符合；全量重建显式重新执行，普通启停不改写历史任务。
- **UTC 存储**：符合；状态时间字段使用 UTC 和 `updated_at`。
- **语言策略**：符合；规格与注释中文，标识符和接口字段英文。

## 实施切面

### 状态模型与服务

- 新增规则启停状态表和 Pydantic 契约模型。
- 新增服务函数：
  - 初始化缺失的普通规则状态；
  - 查询普通规则状态映射；
  - 更新普通规则状态并返回最新规则信息；
  - 返回当前启用普通规则代码集合。
- API 状态列表、TaskService 初始化、CLI 新任务、单规则重跑和增量重建都必须先调用同一个惰性初始化入口；初始化读取 `disabled_rules`，但只在对应规则没有状态记录时生效。
- 配置格式非法或引用未知规则时，初始化调用抛出统一业务错误并阻止本次状态读取或执行，不静默当作全部启用。
- 状态更新写入 UTC `updated_at`。
- 对未知规则返回 `not_found`，对隐藏规则返回 `rule_not_manageable`。

### 注册表与执行器

- 移除“装载后删除禁用规则”的行为，禁用规则继续保留在注册表中供列表和重新启用。
- `Executor` 增加任务级启用规则集合；默认全部启用以兼容直接构造场景。
- prepare 计划只包含 owner 启用的 prepare。
- inspect 计划只包含启用的普通规则。
- 隐藏解压规则和主包解压不受状态过滤。
- 若没有启用的普通规则，任务仍完成并生成空普通结果。

### API

- 既有 `GET /api/v2/inspectors` 保持响应结构兼容，不承载启停列表分页。
- 新增 `GET /api/v2/inspector-states`，参数为 `page`、`page_size`、`enabled`、`category`、`search`；响应包含 `items/total/page/page_size`，默认 `page=1`、`page_size=10`，只返回普通规则。
- 新增 `PUT /api/v2/inspector-states/{rule_code}/enabled`，请求体使用 strict boolean；请求体类型错误沿用 FastAPI/Pydantic 的 422 契约。
- 更新接口要求管理员角色。
- 错误统一使用现有 `{code, message, detail}` 结构。

### 任务与重跑

- 新任务开始时读取一次启用集合并注入执行器。
- 单规则重跑拒绝停用规则和不可管理规则。
- 增量重建选择停用规则时显式失败。
- 全量重建按当前启停状态执行，这是用户显式触发的既有重建语义。
- 普通启停操作不修改历史任务；历史任务结果只可能因用户显式重建/重跑按既有语义变化。

### 前端

- 先执行生成的 API 客户端更新，再在 `http.ts` 中仅做类型安全调用封装。
- 规则列表页使用分页规则状态接口，初始 `page=1`、`page_size=10`。
- 显示启停开关、更新时间和状态语义，支持启用状态、分类和关键字筛选。
- 非管理员禁用开关；更新失败显示后端错误。
- 切换成功后刷新规则列表。

## 测试策略

- 服务测试：
  - 首次初始化导入 `disabled_rules`；
  - 已有状态不被初始化覆盖；
  - 新注册规则默认启用；
  - 更新持久化并可重启恢复；
  - 未知规则、隐藏规则返回明确错误。
- 执行器测试：
  - 停用普通规则不进入 inspect 计划；
  - 对应 prepare 不执行；
  - 全部普通规则停用时任务完成但普通结果为空。
- API 测试：
  - 状态列表默认返回 10 条和分页元数据；
  - 列表返回启停字段；
  - 管理员可切换状态；
  - 非管理员被拒绝；
  - 未知和不可管理规则返回明确错误。
- 任务测试：
  - 停用规则的新任务不生成规则结果；
  - 重新启用后新任务恢复；
  - 单规则重跑停用规则被拒绝。
- 契约与前端：
  - OpenAPI / Pydantic 一致；
  - 前端客户端重新生成；
  - 前端构建通过。
