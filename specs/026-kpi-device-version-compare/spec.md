# 功能规格：KPI 同设备版本对比

**功能分支**：`026-kpi-device-version-compare`

**创建日期**：2026-09-24

**状态**：已澄清

**输入**：用户描述：KPI 里增加版本对比能力；历史会话已确认这是同一设备不同数据包/系统版本之间的 KPI 指标对比，不是规则版本对比。

## Clarifications

### 2026-09-24 会话澄清

- **基线任务选择**：同一基线版本存在多个已完成任务时，默认选择完成时间最新的任务；界面必须显示实际选中的任务 ID 和完成时间，不允许多个任务静默合并。
- **对比摘要默认口径**：第一版使用平均值作为当前值和基线值；如果后续指标数据能提供明确的累计/均值类型，再按类型演进为呼叫量类求和、失败率类平均。摘要输出绝对差值、变化比例和方向解释。
- **版本元数据缺失**：版本为空的任务可以继续任务级对比，但界面必须明确显示“版本未知”；不得把该结果伪装成完整版本对比。

## 背景

`025-kpi-cross-task-trend` 已支持同设备跨任务历史趋势、默认 7 天窗口、同时刻基线和降级提示。它回答的是“当前值和最近历史波动相比是否异常”，还不能直接回答“当前版本和某个历史版本相比，业务量是否上涨”。

本功能补充一个明确的对比模式：**同一设备，选择一个不同版本的历史任务作为基线**。系统展示当前任务和基线任务的曲线与涨跌摘要，帮助用户判断版本变更前后的业务变化。

本功能继续遵守以下约束：

- 一个压缩包仍然是一个任务和一个输出目录。
- 不合并压缩包、不合并任务，也不建立局点画像。
- 历史数据优先来自任务私有 `kpi/history/index.jsonl`。
- 不为了对比自动重建任务、重解压原始包或重跑 KPI 巡检。
- 同设备、同测量单元、同指标、同行对象和同周期才能对比。
- 版本来自任务元数据中的系统版本；不使用 `rule_version`。
- 当前任务和基线任务必须展示真实版本。

## 用户场景与测试 *(必填)*

### 用户故事 1 - 选择同设备历史版本（优先级：P1）

用户在 KPI 指标趋势中打开版本对比后，可以看到与当前任务相同设备 ID 的已完成历史版本。系统按任务元数据中的系统版本分组展示候选版本；用户选择一个与当前版本不同的版本后，系统使用该版本下的已完成任务作为基线任务，并显示基线任务的版本、任务 ID 和完成时间。

**优先级理由**：这是本功能的核心入口。没有明确的版本选择，用户无法确定当前曲线应该和哪个版本比较。

**独立测试**：准备同一设备、两个不同版本、数据覆盖不同时间的已完成任务；打开当前任务指标趋势，选择旧版本作为基线，确认界面显示两个版本、两条曲线和基线任务来源。

**验收场景**：

1. **给定** 当前任务设备 ID 是 `device-a`，版本是 `V2`，历史存在同设备 `V1` 已完成任务，**当** 打开版本对比，**则** 候选列表显示 `V1`。
2. **给定** 历史存在同设备 `V1` 和 `V3` 任务，**当** 打开版本对比，**则** 候选列表不包含其他设备 ID 的版本。
3. **给定** 用户选择基线版本 `V1`，**当** 系统完成对比，**则** 界面显示当前版本 `V2` 和基线版本 `V1`，以及基线任务 ID 和完成时间。
4. **给定** 同一基线版本存在多个已完成任务，**当** 用户选择该版本，**则** 系统默认使用完成时间最新的任务，并明确显示选中的任务 ID；不允许静默合并多个任务。
5. **给定** 用户选择与当前任务相同的版本，**当** 发起对比，**则** 系统提示版本相同，不能作为版本对比基线。
6. **给定** 当前任务或候选任务版本为空，**当** 展示候选或发起对比，**则** 系统明确显示“版本未知”，不把该对比伪装成版本对比。

---

### 用户故事 2 - 展示不同版本曲线（优先级：P1）

用户选定基线版本后，系统按当前任务的测量单元、指标、行对象和周期读取当前任务与基线任务的数据，并展示两条独立曲线。两条曲线必须分别来自当前版本任务和基线版本任务，不得把多任务或多版本数据合并成一条曲线。

**优先级理由**：版本对比的关键是保留版本归属。混合曲线会让用户无法判断变化来自版本还是其他任务。

**独立测试**：构造当前版本和基线版本各有一个任务，包含相同对象和周期但不同数值的数据；选择基线版本后确认系统生成两条独立曲线，且每条曲线都能追溯到任务 ID。

**验收场景**：

1. **给定** 当前任务和基线任务同设备且维度一致，**当** 用户选择基线版本，**则** 系统分别展示当前版本曲线和基线版本曲线。
2. **给定** 两个任务存在相同测量时间的数据，**当** 展示曲线，**则** 两个任务在同一时间位置各自保留自己的值。
3. **给定** 当前任务和基线任务的数据日期相距很远，**当** 使用版本对比模式，**则** 系统仍能对比；该模式不受默认 7 天历史窗口限制。
4. **给定** 基线任务缺少当前测量单元、指标、对象或周期，**当** 用户选择该任务，**则** 系统返回明确的维度不一致原因，不显示误导性空图。
5. **给定** 基线任务未完成或历史索引缺失，**当** 用户选择该任务，**则** 系统显示对应降级原因，不自动重建或回填。

---

### 用户故事 3 - 输出版本涨跌摘要（优先级：P1）

用户完成版本对比后，可以看到当前版本值、基线版本值、绝对差值、变化比例和业务方向解释。对于呼叫量等越高越好的指标，系统能表达“当前版本相对基线版本上涨”或“下降”；对于越低越好的指标，系统按指标方向解释是否改善。

**优先级理由**：用户最终关心的是“新版本业务是否变好”，只看曲线无法快速得到结论。

**独立测试**：构造同一指标在当前版本和基线版本中的不同值，验证摘要能显示基线值、当前值、差值、比例和方向；再使用 `lower_better` 指标验证方向解释正确。

**验收场景**：

1. **给定** 指标方向是 `higher_better`，当前版本值大于基线版本值，**当** 查看摘要，**则** 系统显示上涨及变化比例。
2. **给定** 指标方向是 `higher_better`，当前版本值小于基线版本值，**当** 查看摘要，**则** 系统显示下降及变化比例。
3. **给定** 指标方向是 `lower_better`，当前版本值小于基线版本值，**当** 查看摘要，**则** 系统显示改善或正向变化。
4. **给定** 当前版本值或基线版本值无效，**当** 查看摘要，**则** 对应字段为空，不输出误导性的上涨或下降结论。
5. **给定** 基线任务可用样本不足，**当** 查看摘要，**则** 系统显示样本不足，不输出统计显著性结论。

---

### 用户故事 4 - 保留可定位失败原因（优先级：P2）

版本对比看不到历史数据时，系统必须说明基线任务没有进入对比的原因。时间、任务状态、索引、设备、版本和维度都可能是不匹配原因。

**优先级理由**：只提示“暂无历史”会让用户无法判断应该补版本元数据、修改设备 ID、检查任务状态还是选择其他版本。

**独立测试**：构造同设备候选任务分别为版本相同、版本未知、未完成、索引缺失、维度不一致和数据有效的场景；发起版本对比后确认提示能说明具体原因。

**验收场景**：

1. **给定** 基线任务和当前任务版本相同，**当** 发起版本对比，**则** 提示“版本相同，不能作为版本对比基线”。
2. **给定** 基线任务版本为空，**当** 发起版本对比，**则** 提示“基线任务版本未知”。
3. **给定** 基线任务未完成，**当** 发起版本对比，**则** 提示基线任务未完成或缺少完成时间。
4. **给定** 基线任务缺少历史索引，**当** 发起版本对比，**则** 提示基线任务索引缺失，而不是提示“暂无历史”。
5. **给定** 基线任务设备 ID 不同，**当** 发起版本对比，**则** 提示设备不一致，且不展示其数据。

---

### 边界情况

- 当前任务缺少设备 ID 时，系统必须先提示设备 ID 缺失，不猜测版本对比归属。
- 当前任务和基线任务版本都为空时，可以继续任务对比，但必须显示“版本未知”，不得称为版本对比。
- 同一版本存在多个任务时，不允许静默合并；必须显示实际参与对比的任务 ID。
- 历史索引存在坏行时，坏行跳过；如果导致任务没有有效点，应提示索引为空或无效。
- 原始包中的 CSV 缺失列或无数据时，不得编造数据点。
- 时区处理必须继续使用 UTC 存储，界面按现有时间展示规则转换。

## 需求 *(必填)*

### 功能需求

- **FR-001**：版本对比必须以同设备任务为候选，不展示其他设备 ID 的候选版本。
- **FR-002**：版本对比必须要求基线任务系统版本与当前任务系统版本不同；版本为空时必须明确显示“版本未知”。
- **FR-003**：用户必须能够看到基线版本、当前版本、基线任务 ID 和基线任务完成时间。
- **FR-004**：版本对比必须校验同测量单元、同指标、同行对象和同周期。
- **FR-005**：版本对比必须分别展示当前版本任务曲线和基线版本任务曲线，不得合并成一条混合曲线。
- **FR-006**：系统必须输出版本对比摘要，包括当前值、基线值、绝对差值、变化比例和按指标方向的业务解释。
- **FR-007**：无历史、降级或维度不匹配时，系统必须返回可定位的中文原因和稳定 `reason_code`。
- **FR-008**：版本对比必须继续按行读取任务私有索引，并只加载当前维度数据。
- **FR-009**：系统不得为了版本对比自动重建任务、重解压原始包或重跑 KPI 巡检。
- **FR-010**：OpenAPI 必须先更新版本对比契约，再更新服务端、前端客户端和界面实现。

### 关键实体 *(如果功能涉及数据则填写)*

- **设备版本候选**：同一设备 ID 下按系统版本分组的历史任务集合；只包含已完成任务。
- **基线任务**：用户选定的基线版本中实际参与对比的任务；必须显示版本、任务 ID 和完成时间。
- **版本对比摘要**：当前值、基线值、绝对差值、变化比例、方向解释、样本数和降级原因。

## 成功标准 *(必填)*

### 可度量结果

- **SC-001**：用户打开同设备版本对比后，能在 3 次点击内选择一个不同版本作为基线。
- **SC-002**：对比结果始终显示当前版本、基线版本和基线任务来源，用户无需查看日志确认数据归属。
- **SC-003**：用户能直接看到呼叫量等指标相对基线版本是上涨、下降、改善还是基本持平。
- **SC-004**：对 600+ 指标任务，版本对比仍然只请求当前指标、对象和周期，不加载任务级大结果。
- **SC-005**：所有版本对比和历史降级场景都有可读原因和稳定 `reason_code`。

## 假设

- 版本对比由用户显式选择基线版本；第一版不自动推荐“去年版本”。
- 一个版本可能对应多个任务，但同一版本内的多个任务不合并统计。
- 版本信息来自任务元数据；缺失时不能自动推断。
- 局点画像、任务组、版本管理和自动同版本聚合不在本 spec 范围内。
- 版本对比服务于单指标趋势，不改变任务总览和风险排序。
