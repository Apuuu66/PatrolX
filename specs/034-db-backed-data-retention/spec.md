# 功能规格：任务数据长期留存与磁盘现场治理

**功能分支**：`034-db-backed-data-retention`

**创建日期**：2026-10-12

**状态**：已澄清

**输入**：用户描述："运维人员针对月度巡检、动网操作后巡检，要能快速识别问题，以及长期观察 KPI 和资源监控。"多轮讨论确定：界面展示数据全部以数据库为唯一来源；上传包与任务现场只保留最近 50 个任务；手动指定的设备 ID 必须已存在于设备台账；任务补充最后一次运行时间与任务时长；规则结果以最新为准、不做版本管理；不做自动重试与断点续跑。

## 背景

当前系统存在"数据库索引 + 任务现场文件"双数据源：任务现场（解压数据、规则结果、报告、执行日志）是展示数据的主要来源，数据库只存任务索引与状态等元数据。现场文件当前不自动清理，磁盘会随任务数量持续增长；而一旦为释放磁盘删除文件，历史任务在界面上就无法查看。

这与两个核心运维场景冲突：

1. **月度巡检 / 动网操作后巡检**：要能快速识别问题，历史结论必须随时可回溯。
2. **长期观察 KPI 与资源监控**：需要跨任务、长时间窗口的趋势观察，数据不能随磁盘清理丢失。

本轮按已确认结论收敛：

- 界面上展示的一切数据以数据库为唯一来源；本地文件仅是执行期临时现场。
- 数据库中的任务、规则结果、发现与 KPI 数据长期保留，不设自动删除期限。
- 上传的原始压缩包与任务现场各只保留最近 50 个任务对应的文件，按任务最后一次运行时间排序清理。
- 执行日志不入库，仅留在磁盘现场，随现场一起清理。
- 规则结果以最新一次执行为准，不做版本管理；任务失败不做自动重试或断点续跑，通过显式重跑/重建恢复。
- 任务补充"最后一次运行时间"与"任务时长"。
- 手动指定的设备 ID 必须已存在于设备台账，否则拒绝。

**本轮边界**：

- 不改变"一个包 = 一个任务 = 一个输出目录"的隔离模型与既有执行编排。
- 不引入规则结果版本历史、自动重试、断点续跑、归档到外部存储等机制。
- 保留额度固定为 50，暂不提供配置界面与按元数据的例外规则。
- 设备台账自身能力不变，本特性只增加"手动指定设备 ID"的存在性校验。

## Clarifications

### Session 2026-10-12

- Q: 磁盘文件被清理后，任务详情、规则结果、KPI 数据还能看吗？ → A: 能。界面展示内容全部从数据库读取，磁盘清理不影响数据查看。
- Q: 执行日志是否入库？ → A: 不入库，仅保留在磁盘现场。
- Q: 磁盘留存策略？ → A: 上传压缩包保留最近 50 个；任务现场只保留对应任务的文件；"最近"按任务运行时间判定，不按文件修改时间。
- Q: 规则结果如何存储？ → A: 以最新为准，每个任务/规则只保留最新一次执行结果，不做版本管理。
- Q: 失败任务是否自动重试？ → A: 不考虑复杂重试；失败通过重跑或重建解决。
- Q: 手动指定的设备 ID 如何约束？ → A: 必须是设备台账中已存在的设备，否则拒绝。
- Q: 磁盘现场被清理后，历史任务的报告是否仍需可查看？ → A: 不保证可查看；报告视为磁盘现场产物，清理后不提供查看，入口给出明确提示，核心数据仍从数据库可查。
- Q: 留存清理以什么方式触发？ → A: 任务结束后自动清理（含失败收尾），无需人工干预。
- Q: "最后一次运行时间"应记录最近一次运行的开始时刻还是完成时刻？ → A: 开始时刻；配合任务时长即可推知结束时刻。
- Q: 创建时间与运行时间是否为独立字段？ → A: 是。创建时间固定为任务创建时刻、不随运行变化；最后一次运行时间随每次运行更新，从未运行则为空。
- Q: 现场已被清理的任务如何重新执行？ → A: 重传同名包时先提示覆盖，确认后清空旧任务并用当前数据包全量重建（结果以本次重建为准）；取消则既有任务与已保留数据保持不变。（2026-10-13 修订，与 033 FR-024 对齐）

## 用户场景与测试 *(必填)*

### 用户故事 1 - 磁盘清理后仍能完整回溯历史任务（优先级：P1）

运维人员打开任意历史任务（即使其磁盘现场已按留存策略被清理），任务详情、规则结果、发现与 KPI 数据仍然完整可查；长期观察 KPI 与资源监控不再依赖磁盘文件是否还在。

**优先级理由**：长期观察 KPI 与资源监控是核心目标；"清理磁盘 = 历史数据消失"直接阻断该目标，必须先解决。

**独立测试**：构造一个磁盘现场与原始压缩包都已被清理的任务，打开任务列表、任务详情、规则详情与 KPI 视图，逐项核对与清理前一致（执行日志与报告文件除外）。

**验收场景**：

1. **给定** 某任务的磁盘现场与上传压缩包已被清理，**当** 打开任务详情，**则** 任务摘要、规则结果、发现与 KPI 数据完整显示，不出现因文件缺失导致的错误或空白。
2. **给定** 同一任务的数据参与 KPI 跨任务趋势，**当** 查看趋势视图，**则** 该任务的数据正常参与对比与展示。
3. **给定** 某任务经过多次重跑，**当** 查看规则结果，**则** 展示最近一次执行结果，且没有历史版本入口。

---

### 用户故事 2 - 磁盘文件按策略自动受控（优先级：P1）

随着任务数量增长，系统只保留最近 50 个任务对应的上传压缩包与任务现场文件；更早的文件被清理，磁盘占用受控，数据库数据不受影响。

**优先级理由**：动网操作后巡检会产生高频任务，不治理磁盘必然写满；留存额度直接决定清理行为是否符合运维预期。

**独立测试**：构造超过 50 个任务（运行时间不同），完成留存清理后核对磁盘仅保留最近 50 个任务对应的文件，且被清理任务的界面数据完整。

**验收场景**：

1. **给定** 系统存在 51 个以上已运行任务，**当** 留存清理生效，**则** 磁盘上只保留按最后一次运行时间排序最近的 50 个任务对应的压缩包与现场文件。
2. **给定** 某任务正在执行，**当** 留存清理生效，**则** 该任务及其压缩包、现场文件不受影响。
3. **给定** 从未运行过的任务，**当** 计算保留范围，**则** 按创建时间参与排序。
4. **给定** 某任务的磁盘文件已被清理，**当** 用户发起重跑或重建，**则** 收到明确提示（包含重新上传同名数据包、确认覆盖后全量重建的路径），而不是静默失败或空白。

---

### 用户故事 3 - 任务元数据补充最后运行时间与时长（优先级：P2）

运维人员在任务列表即可看到每个任务最后一次运行的时间与本次执行耗时，用于判断任务新旧、发现耗时异常，无需进入详情。

**优先级理由**：长期巡检场景下"何时跑的、跑了多久"是最基础的观察维度，当前缺失。

**独立测试**：对已完成、重跑过、从未运行三类任务，核对列表中最后运行时间与任务时长展示。

**验收场景**：

1. **给定** 某任务已执行完成，**当** 查看任务列表与详情，**则** 显示最后一次运行时间与任务时长。
2. **给定** 某任务经过多次重跑，**当** 查看，**则** 显示最近一次运行的时间与耗时，不显示历史记录。
3. **给定** 某任务从未运行或正在运行，**当** 查看，**则** 不显示误导性的时长数值（未运行显示占位，运行中表明尚未结束）。

---

### 用户故事 4 - 手动指定设备 ID 必须存在于设备台账（优先级：P2）

运维人员手动输入设备 ID 时，系统校验其必须已存在于设备台账；不存在的 ID 被拒绝并给出明确提示，避免脏数据进入任务记录。

**优先级理由**：设备 ID 是任务关联设备与 KPI 对比的关键元数据；错误 ID 会污染后续台账观测与版本对比。

**独立测试**：分别输入台账中存在 / 不存在的设备 ID，验证接受与拒绝（含提示，且拒绝时不创建任务）。

**验收场景**：

1. **给定** 设备台账包含设备 D，**当** 手动指定 D，**则** 校验通过，任务正常创建。
2. **给定** 设备台账不包含 ID X，**当** 手动指定 X，**则** 拒绝并提示设备不存在，任务不被创建。
3. **给定** 设备 ID 为可选项，**当** 不指定设备，**则** 校验不触发，任务正常创建。

---

### 边界情况

- 清理与执行并发：任务执行期间不得清理该任务的文件，正在执行的任务不因留存策略缺文件。
- 保留范围边界：任务数恰好 50 时不清理；出现第 51 个任务（运行时间最新）时清理最旧任务的磁盘文件。
- 从未运行任务：无运行时间，以创建时间参与"最近"排序。
- 现场已清理的任务：报告查看给出明确提示；重跑/重建提示重新上传同名原始包，提交时先覆盖确认、确认后全量重建（2026-10-13 修订）；不得静默失败。
- 设备 ID 后续失效：任务创建后设备从台账被删除，历史任务保留已记录的值，不受影响。
- 多次重跑：最后运行时间、任务时长与规则结果均以最近一次执行为准。
- 人工删除任务：仍按既有语义删除任务记录与文件；"长期保留"指不设自动删除期限，不排除人工操作。

## 需求 *(必填)*

### 功能需求

- **FR-001**：界面上展示的全部巡检数据（任务摘要、规则结果、发现、KPI 数据、任务元数据等）必须以数据库为唯一数据来源；磁盘文件仅作为执行期临时现场，不作为界面查询依据。
- **FR-002**：数据库中的任务记录、规则结果、发现与 KPI 数据必须长期保留，不设自动删除期限；磁盘清理不得删除或修改这些数据。
- **FR-003**：执行日志不得写入数据库，仅保留在磁盘任务现场，并随现场清理一并移除。
- **FR-004**：系统必须在每次任务结束（完成或失败）后自动执行留存清理：上传的原始压缩包与任务现场文件只保留最近 50 个任务对应的范围，超出的文件必须被清理，无需人工干预。
- **FR-005**：保留范围的"最近"必须按任务最后一次运行时间排序判定，不得使用文件修改时间；从未运行的任务以创建时间参与排序。
- **FR-006**：正在执行的任务及其压缩包、现场文件在运行期间不得被清理。
- **FR-007**：任务与规则的巡检结果必须以最新一次执行为准：重跑或重建覆盖旧结果，不保留历史版本。
- **FR-008**：每个任务必须记录"最后一次运行时间"（最近一次运行的开始时刻）与"任务时长"（该次运行的起止耗时）；重跑或重建后更新为最近一次运行的值。创建时间与最后一次运行时间是两个独立字段：创建时间不随运行变化，从未运行的任务其最后一次运行时间为空。
- **FR-009**：任务列表与任务详情必须展示最后一次运行时间与任务时长；从未运行或尚未完成的任务不得显示误导性时长数值。
- **FR-010**：用户手动指定设备 ID 时，系统必须校验其已存在于设备台账；不存在时必须拒绝提交、给出明确提示，且不得创建任务记录。
- **FR-011**：磁盘现场已被清理的任务，当用户访问依赖现场文件的功能时，系统必须给出明确提示，不得静默失败或展示空白：报告查看提示报告已随现场清理、不可查看；重跑或重建提示重新上传同名数据包、确认覆盖后全量重建；重传提交按 FR-013 先覆盖确认、确认后全量重建。
- **FR-012**：任务失败后的恢复只能由用户显式发起（重跑或重建）；系统不得引入自动重试、断点续跑或中断后自动续作。
- **FR-013**：重传同名包（含现场已被清理的任务）必须先提示覆盖，确认后清空旧任务并用当前数据包全量重建（重新执行全部解压、数据准备与规则检查，结果以本次重建为准）；取消或未确认时既有任务与已保留数据保持不变，不得静默打开已有任务。（2026-10-13 修订：原“仅写回现场、保留历史、不自动重跑”口径改为覆盖确认 + 全量重建，与 033 FR-024 对齐；创建接口的校验和恢复矩阵保留为探测未命中时的兜底，见 contracts/api-delta.md。）

### 关键实体 *(如果功能涉及数据则填写)*

- **任务**：一次巡检请求的记录；关键属性：任务 ID、元数据（省份、运营商、产品形态、版本、设备 ID）、状态、创建时间、最后一次运行时间（最近一次运行开始时刻）、任务时长（该次执行耗时）。
- **规则结果**：任务中每条规则的最新执行结果；属性：状态（pass/warn/fail/error/skip）、发现、证据、跳过原因；随任务长期保留。
- **发现**：规则结果下的具体问题条目；属性：来源位置、证据、规则标识、相关值与阈值。
- **KPI 数据**：任务级指标快照，支撑跨任务长期趋势与资源监控；以最新执行为准。
- **设备台账**：既有设备记录集合；设备 ID 为唯一标识，手动指定设备 ID 时以其校验存在性。
- **磁盘现场**：任务的原始压缩包与执行产物（解压数据、规则结果文件、执行日志、报告）；按留存策略清理，不承载界面查询职责。

- **SC-002**：系统空闲（无任务执行）时，磁盘上保留的上传压缩包与任务现场均不超过最近 50 个任务对应的文件量。
- **SC-003**：自系统首次运行以来的全部历史任务均可查询与回溯，不因磁盘清理丢失；任意时间跨度的 KPI 趋势均可查看。
- **SC-004**：任务列表中 100% 的任务可直接看到最后一次运行时间；已完成任务显示任务时长，识别耗时异常无需进入详情。
- **SC-005**：手动输入不存在的设备 ID 时 100% 被拒绝并给出明确提示；不存在于台账的设备 ID 进入任务记录的条数为 0。

## 假设

- 保留额度固定为 50（上传包与任务现场一致），暂不提供配置入口或按元数据的例外；该策略对本地模式与在线模式统一生效。
- 清理是独立于巡检执行流程的系统动作，在每次任务结束（完成或失败）后自动执行；清理不得写入规则编排，也不得影响执行结果。
- "长期保留"指不设自动删除期限；人工删除任务等既有显式操作仍按其既有语义执行。
- "最后一次运行时间"为最近一次运行的开始时刻，任务时长为该次执行的起止耗时；时间按既有约定以 UTC 存储、界面按本地时区展示。
- 报告文件属于磁盘现场产物，不纳入"清理后仍可查看"的保证范围；其数据来源（规则结果、发现、KPI）仍在界面可查。
- 设备台账能力已存在；本特性只增加手动指定场景的存在性校验，从台账选择不触发额外校验。
- 重传以系统首次接收原始包时记录的校验和为准（创建接口同名校验依据）；界面重传按 FR-013 提示覆盖并在确认后全量重建。（2026-10-13 修订）
- 界面展示数据入库后，既有展示结构与交互语义保持不变。
