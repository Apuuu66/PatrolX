# 功能规格：基于测量单元的 KPI 巡检

**功能分支**：`017-kpi-measurement-units`

**创建日期**：2026-09-22

**状态**：已被 `specs/021-kpi-auto-catalog/spec.md` 部分替代；本规格中的“任务发现列先生成候选绑定，再由人工确认”主流程不再作为新实现目标。

**输入**：用户描述：重构 KPI 巡检资源模型。以测量单元 `MU_*` 为管理主体，管理指标 `ME_*`、单位 `UNIT_*`、指标与测量单元绑定关系、任务 CSV 匹配、指标可读性巡检、行对象观察和派生成功率；删除旧的业务域 KPI 模型，不做旧任务兼容。

## 用户场景与测试 *(必填)*

### 用户故事 1 - 维护测量单元资源目录（优先级：P1）

巡检维护人员导入一份资源目录文件后，系统能识别测量单元、指标和单位，并在测量单元目录中查看和维护它们。维护人员可以启用或停用测量单元，被停用的测量单元不再参与巡检。

**优先级理由**：测量单元是新版 KPI 的管理核心；没有该目录，任务文件无法归属，指标也无法维护。

**独立测试**：导入一份包含 `MU_*`、`ME_*`、`UNIT_*` 的资源目录文件后，检查资源目录数量、名称、状态和重复导入结果。

**验收场景**：

1. **给定** 一份包含 3 个测量单元、20 个指标和 5 个单位的资源目录文件，**当** 维护人员执行导入，**则** 系统显示新增 3 个测量单元、20 个指标和 5 个单位。
2. **给定** 同一份资源目录文件被再次导入且部分中英文名称已修改，**当** 导入完成，**则** 系统更新对应名称，不删除资源目录中已有但本次未出现的资源。
3. **给定** 某测量单元被停用，**当** 巡检任务包含其对应文件，**则** 该文件被标记为“停用测量单元”，不参与巡检，但对维护人员可见。

---

### 用户故事 2 - 将任务 CSV 归属到测量单元（优先级：P1）

系统扫描离线巡检包中的任务 CSV，根据测量单元英文名生成的文件名片段识别文件归属。一个测量单元可以对应一个或多个任务文件；未识别、歧义、停用和解析失败的文件都必须有明确去向。

**优先级理由**：任务文件只有先归属到测量单元，后续指标检查才有意义。

**独立测试**：准备匹配、大小写不同、多文件、无法识别和匹配冲突的任务包，检查文件归属状态和原因。

**验收场景**：

1. **给定** 测量单元英文名为 `Call Session API Statistics`，**当** 任务包中存在 `ne333_Call_Session_API_Statistics_15_0_202609020000.csv`，**则** 该文件匹配该测量单元。
2. **给定** 文件名使用 `call_session_api_statistics`，**当** 系统匹配测量单元，**则** 因大小写不一致而不匹配，并进入未识别文件列表。
3. **给定** 同一测量单元和周期存在多个文件，**当** 巡检执行，**则** 系统分别解析并合并展示该测量单元的结果。
4. **给定** 一个文件名可能命中多个测量单元，**当** 系统无法唯一判断，**则** 将文件标记为歧义，不自动选择。

---

### 用户故事 3 - 自动发现并确认指标绑定（优先级：P1）

系统读取任务 CSV 表头，发现“周期(分钟)”之后的指标列，并根据去除单位括号后的名称匹配资源目录中的指标。维护人员可以确认、忽略或处理绑定冲突。只有已确认的指标绑定参与巡检。

**优先级理由**：资源目录只有指标定义，任务 CSV 才有真实列名；绑定关系是把两者连起来的关键。

**独立测试**：使用包含已定义指标、未注册列、重复匹配和已绑定冲突列的任务 CSV，检查候选、冲突、未注册和确认后的巡检范围。

**验收场景**：

1. **给定** 资源目录指标名为 `呼叫请求次数`，任务 CSV 列名为 `呼叫请求次数(次)`，**当** 系统发现指标列，**则** 生成候选绑定，并保留原始列名 `呼叫请求次数(次)` 和展示单位 `次`。
2. **给定** 候选绑定未被确认，**当** 巡检任务执行，**则** 该指标不参与巡检结论。
3. **给定** 维护人员确认候选绑定，**当** 后续任务出现相同列名，**则** 系统按已确认绑定检查该指标。
4. **给定** 一个指标已经绑定到其他测量单元，**当** 另一个测量单元尝试绑定它，**则** 系统提示冲突，不自动改绑。
5. **给定** 任务 CSV 中存在无法匹配资源目录的列，**当** 文件解析完成，**则** 该列进入未注册指标列表，供维护人员后续处理。

---

### 用户故事 4 - 查看测量单元巡检结果（优先级：P1）

巡检查看人员进入任务结果后，可以按测量单元看到整体状态、文件数量、指标覆盖情况和异常原因。没有配置阈值时，成功读取的指标不因业务值大小被判定失败；全 0 只作为数据形态提示。

**优先级理由**：巡检的首要价值是让查看人员快速知道哪些测量单元完整可读、哪些测量单元存在缺失或异常。

**独立测试**：执行包含正常、列缺失、空值、解析失败和全 0 指标的任务包，检查状态和提示。

**验收场景**：

1. **给定** 测量单元的所有已确认指标列都存在且可读取，**当** 巡检完成，**则** 该测量单元结果为通过。
2. **给定** 某个已确认指标列缺失，**当** 巡检完成，**则** 该指标为失败，测量单元汇总也反映失败。
3. **给定** 某个指标列存在空值或不可解析值，**当** 巡检完成，**则** 该指标为失败，并显示异常来源。
4. **给定** 某个指标所有值都是 0，**当** 巡检完成，**则** 该指标结果为通过，并显示“全 0”提示。
5. **给定** 测量单元没有已确认指标绑定，**当** 任务执行，**则** 该测量单元跳过，并说明原因是“未配置已确认指标绑定”。

---

### 用户故事 5 - 观察行对象结果（优先级：P2）

当 CSV 的维度列表示不同对象时，例如容器、实例或服务，系统按行对象聚合展示指标。查看人员可以下钻到某个对象，观察该对象的指标值和异常；对于行对象相同的传统 KPI 文件，则表现为一个默认或相同对象的结果。

**优先级理由**：CPU、内存等资源文件每行代表不同对象，只看整体统计会掩盖单个对象的异常。

**独立测试**：准备多个行对象、重复行对象、某对象异常和没有维度列的 CSV，检查对象明细、汇总和异常定位。

**验收场景**：

1. **给定** CSV 第一列分别为 `pod-a`、`pod-b`、`pod-c`，**当** 系统解析 CPU 使用率，**则** 三个对象分别显示自己的值。
2. **给定** `pod-b` 的 CPU 使用率无法解析，**当** 系统解析完成，**则** `pod-b` 的 CPU 指标失败，其他对象不受影响。
3. **给定** 同一行对象出现多行数据，**当** 系统聚合，**则** 显示该对象的数据行数、有效值数、空值数、解析错误数和基础统计值，并保留来源行号。
4. **给定** CSV 没有维度列，**当** 系统解析，**则** 所有数据行聚合到一个默认行对象。

---

### 用户故事 6 - 查看成功率派生指标（优先级：P3）

维护人员可以为某个测量单元配置一个成功率派生指标，指定分子指标和分母指标。系统按行对象计算成功率，并在分母为 0 时提示疑似业务未触发，不判定失败。

**优先级理由**：成功率是最常见的派生指标；先支持该模板可以验证派生模型，同时避免一开始引入复杂公式能力。

**独立测试**：配置分子、分母后执行包含正常、分母为 0、分子缺失和分母缺失的数据包，检查计算结果和状态。

**验收场景**：

1. **给定** 成功请求次数为 9876、呼叫请求次数为 10000，**当** 系统计算成功率，**则** 显示 98.76%。
2. **给定** 分母为 0，**当** 系统计算成功率，**则** 不判失败，显示疑似业务未触发。
3. **给定** 分子或分母指标缺失，**当** 巡检完成，**则** 成功率派生指标失败，并说明依赖指标缺失。
4. **给定** 一个指标已经被配置为成功率派生指标，**当** 系统处理任务 CSV，**则** 不把它当作原始 CSV 列绑定。

---

### 边界情况

- 当资源目录文件中存在无法识别的资源 ID 前缀时，系统跳过该行并在导入报告中说明原因。
- 同一类资源的中文名一致时，系统按同一个资源合并；英文名差异按更新处理。
- 合并不以资源 ID 为判断键；同名不同 ID 时保留既有或首个资源 ID。
- 同一资源 ID 对应不同中文名时，系统不得覆盖已有定义；后续行使用稳定的冲突键生成新资源 ID 后导入。
- 资源目录与任务 CSV 支持 UTF-8 和 GB18030（含 GBK/GB2312）回退；无法解码时按对应错误处理。
- 当任务文件缺少标准表头 `测量开始时间`、`测量结束时间`、`周期(分钟)` 时，文件进入解析失败，不影响其他文件。
- 当数据行的周期与文件名周期不一致时，该行记录错误，不参与指标聚合。
- 当数据行列数与表头不一致时，该行记录错误，不参与指标聚合。
- 当某个文件解析失败时，其他文件和其他测量单元继续巡检。
- 当测量单元英文名片段存在包含关系时，系统优先选择更长的匹配片段；仍无法唯一判断时标记歧义。
- 当任务 CSV 内部元数据与文件名归属不一致时，系统不依赖该元数据改变归属，仅可作为展示或排查信息。
- 当单位括号内容不是标准单位时，系统只作为展示信息，不影响指标名称匹配。

## 需求 *(必填)*

### 功能需求

- **FR-001**：系统必须支持导入包含 `资源id`、`中文描述`、`英文描述` 三列的资源目录文件。
- **FR-002**：系统必须按资源 ID 前缀识别 `MU_*` 测量单元、`ME_*` 指标和 `UNIT_*` 单位。
- **FR-003**：资源目录导入必须采用新增或更新语义；本次未出现的已有资源不得自动删除。
- **FR-004**：系统必须展示资源导入报告，包括新增数、更新数、跳过数和错误明细。
- **FR-005**：测量单元必须包含资源 ID、中文名、英文名、由英文名派生的文件名片段和启用状态。
- **FR-006**：文件名片段必须由英文描述中的空格替换为下划线生成，且匹配时大小写敏感。
- **FR-007**：系统必须只对启用状态的测量单元执行任务文件匹配和巡检。
- **FR-008**：任务文件匹配状态必须至少区分匹配、未匹配、歧义、停用和解析失败。
- **FR-009**：系统必须识别标准表头 `测量开始时间`、`测量结束时间`、`周期(分钟)`，并将 `周期(分钟)` 之后的所有列作为候选指标列。
- **FR-010**：系统必须将 `周期(分钟)` 之前及 `周期(分钟)` 本身作为元数据或维度列，不作为指标绑定。
- **FR-011**：系统必须解析候选指标列的原始列名，并支持从尾部括号中提取展示单位；展示单位只用于展示，不参与指标名匹配。
- **FR-012**：系统必须按去除尾部单位括号后的指标名匹配资源目录中的指标定义。
- **FR-013**：一个指标最多只能绑定一个测量单元；绑定冲突必须显式展示，不得自动改绑。
- **FR-014**：绑定状态必须至少支持候选、已确认、冲突和忽略；只有已确认且启用的原始指标参与巡检。
- **FR-015**：系统必须按测量单元、周期、文件时间戳和行对象组织指标观察结果。
- **FR-016**：系统必须把 `测量开始时间` 前的第一个维度列作为行对象；如果没有维度列，则使用一个默认行对象。
- **FR-017**：同一行对象有多行数据时，系统必须统计行数、有效值数、空值数、解析错误数、0 值数、最小值、最大值和平均值，并保留异常来源。
- **FR-018**：单个数据行错误只影响该行和相关指标结果，不得中断文件、测量单元或任务。
- **FR-019**：系统必须提供测量单元巡检汇总，包括状态、文件数、对象数、指标覆盖数和异常原因。
- **FR-020**：系统必须提供指标明细，包括读取状态、值形态、来源文件、来源行、样本值和异常说明。
- **FR-021**：系统必须集中展示未匹配文件、歧义文件、解析失败文件、未注册指标列、候选绑定和绑定冲突。
- **FR-022**：系统必须支持配置成功率派生指标的分子指标和分母指标，并按行对象计算。
- **FR-023**：成功率派生指标的依赖指标缺失、空值或不可解析时，派生结果必须失败；分母为 0 时必须显示疑似业务未触发，不判失败。
- **FR-024**：系统必须支持重点指标标记，用于结果页突出展示；该标记本身不得改变巡检结论。
- **FR-025**：系统必须移除旧的业务域 KPI 分类、配置、巡检和展示能力，新任务只使用测量单元模型。
- **FR-026**：系统必须保证旧任务数据不参与新版测量单元巡检，也不提供旧任务到新模型的迁移或重跑能力。

### 关键实体 *(如果功能涉及数据则填写)*

- **测量单元**：KPI 管理主体，包含资源 ID、中文名、英文名、文件名片段和启用状态；一个测量单元可对应多个任务文件。
- **指标**：资源目录中的指标定义，分为原始指标和派生指标；不同资源 ID 即使名称相同也视为不同指标。
- **单位**：资源目录中的弱参考资源，仅用于展示或后续参考，不参与核心匹配。
- **指标绑定**：原始指标与测量单元之间的一对一关系，包含原始列名、基础列名、展示单位和状态。
- **派生定义**：派生指标与测量单元之间的归属关系；MVP 只支持成功率模板，并记录分子指标和分母指标。
- **文件发现**：任务包中 CSV 文件与测量单元的匹配结果，包含状态、周期、时间戳和原因。
- **巡检结果**：按测量单元、指标和行对象组织的检查结果，包含覆盖统计、读取状态、值形态、样本和异常证据。

## 成功标准 *(必填)*

### 可度量结果

- **SC-001**：维护人员导入一份合法资源目录文件后，可以在资源目录中找到全部 `MU_*`、`ME_*` 和 `UNIT_*` 记录，重复导入不产生重复资源。
- **SC-002**：对包含 10 个已确认指标绑定且全部可读的测量单元，巡检结果必须显示 10/10 覆盖并通过。
- **SC-003**：只要一个已确认指标缺失、全部为空或存在解析失败，对应测量单元结果必须能从汇总页直接识别为失败。
- **SC-004**：对于包含多个行对象的 CPU 或内存文件，查看人员可以在结果中分别找到每个行对象的指标观察结果。
- **SC-005**：未匹配文件、歧义文件、解析失败文件、未注册指标列和绑定冲突必须全部出现在待处理视图中，且每条记录都能追溯到任务文件。
- **SC-006**：新版 KPI 结果中不得出现旧业务域分类；旧 KPI 配置入口不再对新任务可用。

## 假设

- 输入仍然只来自离线巡检包，不连接被检系统，不做在线采集。
- 任务 CSV 的标准表头沿用现有契约：`测量开始时间`、`测量结束时间`、`周期(分钟)`。
- `测量开始时间` 之前的第一个维度列可以代表容器、实例、服务或其他对象；系统不理解其业务语义。
- 资源目录文件不包含指标与测量单元的绑定关系；绑定关系由任务发现和人工确认维护。
- 单位资源不是本功能的管理重点；不提供独立单位管理能力。
- MVP 不引入业务阈值、通用公式、指标依赖图、单位换算和自动改绑。
- 旧 KPI 模型按完全删除处理，不保留双轨运行、旧任务兼容或历史数据迁移。
