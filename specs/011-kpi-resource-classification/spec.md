# 功能规格：KPI 资源全集登记与在线分类

**功能分支**：`011-kpi-resource-classification`

**创建日期**：2026-09-18

**状态**：草稿

**输入**：用户描述：资源文件是 KPI 指标全集，工具只从资源 CSV 生成基础指标信息，不自动划分 KPI 域；系统提供在线分类能力，由用户后续将指标归入 `call`、`api` 或 `media`。

## 用户场景与测试 *(必填)*

### 用户故事 1 - 从资源全集生成基础指标库（优先级：P1）

运维或配置管理员导入一份 KPI 资源全集 CSV。系统识别其中的指标资源，生成稳定 key、中英文名、单位和基础指标类型，但所有指标先保持未分类状态。用户不需要手工逐条创建指标，也不会因为工具自动猜测业务域而得到错误的 KPI 分组。

**优先级理由**：资源全集是分类和后续 KPI 配置的基础；没有可靠的登记入口，在线分类无法开始。

**独立测试**：给定一个包含单位资源和指标资源的资源 CSV，用户执行导入后可以看到指标基础库中只出现指标资源，且每个指标都能对应到唯一的资源 ID，所有指标均为未分类。

**验收场景**：

1. **给定** 资源 CSV 中存在 `ME_21002,创建媒体资源请求次数(次),Create Media Resource Request Count`，**当** 用户导入资源全集，**则** 系统生成基础指标 `me_21002`，中文名为 `创建媒体资源请求次数`，英文名为 `Create Media Resource Request Count`，单位为 `次`，业务域为未分类。
2. **给定** 资源 CSV 中存在 `UNIT_1,次,times`，**当** 用户导入资源全集，**则** 该行作为单位资源处理，不生成 KPI 指标。
3. **给定** 资源 CSV 中存在 `ME_21003,媒体成功率,对应英文`，**当** 用户导入资源全集，**则** 系统生成 `me_21003`，根据中文语义识别为基础成功率指标，英文名以待补充占位展示。

---

### 用户故事 2 - 查找和审查未登记与未分类指标（优先级：P1）

配置管理员打开专门的 KPI 指标资源页面，可以通过资源 ID、中文名或英文名搜索指标，查看每个指标的基础信息和分类状态。用户能快速区分未分类、`call`、`api` 和 `media` 指标，并发现仍需要处理的指标。

**优先级理由**：全集可能包含大量指标；只有可搜索、状态清晰的列表才能支持持续治理。

**独立测试**：给定一个包含 100 个指标的资源库，用户按资源 ID 或中英文名关键词搜索，并按分类状态筛选，能在列表中找到目标指标及其基础信息。

**验收场景**：

1. **给定** 资源库中存在未分类和已分类指标，**当** 用户筛选未分类，**则** 页面只显示未分类指标。
2. **给定** 用户输入 `21002`、`媒体` 或资源英文名片段，**当** 执行搜索，**则** 系统展示匹配的资源 ID、中文名、英文名、单位、基础指标类型和分类状态。
3. **给定** 某个指标已归入 `media`，**当** 用户查看该指标，**则** 页面显示其当前业务域为 `media`，而不是未分类。

---

### 用户故事 3 - 在线完成单个或批量分类（优先级：P1）

配置管理员在 KPI 指标资源页面选择一个或多个未分类指标，将其归入 `call`、`api` 或 `media`。系统保存分类结果，使对应指标进入对应 KPI 域配置。工具不自动生成阈值和公式。

**优先级理由**：资源全集来自公共资源系统，业务域归属必须由了解业务的人确认；批量分类能降低大量指标的处理成本。

**独立测试**：给定若干未分类指标，用户分别执行单条分类和批量分类，然后刷新页面并检查 KPI 域配置，确认指标只出现在目标域。

**验收场景**：

1. **给定** `me_21002` 为未分类，**当** 用户将其分类为 `media`，**则** 保存后该指标状态变为 `media`，并且不再出现在未分类列表。
2. **给定** 3 个未分类指标，**当** 用户批量选择并分类为 `api`，**则** 3 个指标都变为 `api`；如果其中一个操作失败，系统不得让其他指标出现重复归属或半写状态。
3. **给定** 用户对指标发起分类，**当** 保存成功，**则** 系统不自动生成阈值、告警规则或派生公式。

---

### 用户故事 4 - 保护已引用指标的分类配置（优先级：P2）

当指标已经进入某个 KPI 域并被公式、阈值或其他 KPI 配置引用时，系统不允许用户在普通分类操作中悄悄移动到另一个域。用户必须先处理或解除既有引用；系统保持原配置可用，不产生重复指标。

**优先级理由**：KPI 公式和阈值依赖稳定 key；静默换域或重复写入会破坏巡检配置和结果可比性。

**独立测试**：给定一个已被公式或阈值引用的 `api` 指标，用户尝试将其分类到 `media` 时收到明确错误，且原 `api` 配置保持不变。

**验收场景**：

1. **给定** 指标属于 `api` 且无公式或阈值引用，**当** 用户重新分类为 `call`，**则** 系统可以从 `api` 移除并加入 `call`，最终只保留 `call` 归属。
2. **给定** 指标属于 `api` 且被公式或阈值引用，**当** 用户尝试重新分类为 `media`，**则** 系统拒绝操作，说明存在引用，且不修改任何域配置。
3. **给定** 分类请求到达时配置已被其他操作更新，**当** 系统处理该请求，**则** 系统不会覆盖较新变更，而是返回冲突并要求用户刷新后重试。

---

### 边界情况

- 当资源 CSV 表头缺失或与约定表头不一致时会发生什么？系统必须拒绝本次导入并返回可读错误，不产生部分导入结果。
- 当同一资源 ID 出现多行时会发生什么？内容完全一致时合并为一项；中文名、英文名或资源类型冲突时拒绝本次导入并指出冲突行。
- 当资源 ID 不是 `ME_` 指标资源时会发生什么？`UNIT_` 行作为单位资源跳过；其他资源不生成 KPI 指标，并在导入结果中说明跳过原因。
- 当中文描述缺失或中文括号内单位为空时会发生什么？系统拒绝该导入或该行，不生成不完整且不可识别的指标。
- 当中文描述以括号单位结尾时会发生什么？系统提取括号内文本作为单位，删除该括号片段后作为中文指标名。
- 当英文描述为空或仍是 `对应英文` 这类占位文本时会发生什么？系统保留稳定 key 并生成待补充英文名，不把占位文本当作真实英文名。
- 当重复导入同一资源全集时会发生什么？系统按资源 ID 幂等更新基础信息，不生成重复指标，也不改变已确认的业务域。
- 当资源全集中缺少某个已分类指标时会发生什么？系统不得自动删除该已分类指标；可在导入结果中提示该资源 ID 未出现在本次全集。
- 当用户未选择目标域或选择的域不存在时会发生什么？系统拒绝分类操作并提示必须选择 `call`、`api` 或 `media`。
- 当多个用户同时分类或导入时会发生什么？系统必须保证配置不损坏；后提交者如果基于过期数据，应收到冲突而不是静默覆盖。

## 需求 *(必填)*

### 功能需求

- **FR-001**：系统必须支持导入表头为 `资源id,中文描述,英文描述` 的 UTF-8 资源 CSV。
- **FR-002**：系统必须将 `ME_` 开头的资源 ID 识别为 KPI 指标资源，并将小写资源 ID 作为稳定 key；不得为该功能引入指标别名。
- **FR-003**：系统必须将中文描述作为中文名、英文描述作为英文名，并在英文名缺失或为占位文本时生成待补充英文名。
- **FR-004**：系统必须识别中文描述结尾括号内的单位并从中文名中移除该括号片段。
- **FR-005**：系统必须根据中文语义识别基础指标类型和默认单位，例如请求次数、成功次数识别为计数，成功率识别为比率；不得依据语义自动分配业务域。
- **FR-006**：系统必须把导入生成的基础指标初始业务域标记为未分类，且不得直接写入 `call`、`api` 或 `media` 任一业务域配置。
- **FR-007**：系统必须跳过 `UNIT_` 单位资源，不将其展示为 KPI 指标。
- **FR-008**：系统必须持久化资源指标库，重复导入时按稳定 key 幂等合并。
- **FR-009**：系统必须提供专门的 KPI 指标资源页面，不得复用通用数据字典页面。
- **FR-010**：用户必须能够按资源 ID、中文名或英文名搜索指标，并按未分类、`call`、`api`、`media` 筛选。
- **FR-011**：用户必须能够查看指标的稳定 key、资源 ID、中文名、英文名、单位、基础指标类型和当前分类状态。
- **FR-012**：用户必须能够将一个未分类指标分类为 `call`、`api` 或 `media`。
- **FR-013**：用户必须能够批量选择多个未分类指标并分类到同一个目标域。
- **FR-014**：系统必须保证一个指标在同一时刻只有一个业务域归属。
- **FR-015**：系统必须在分类保存后把可用基础指标写入目标业务域配置，且不得自动生成阈值、派生公式或告警建议。
- **FR-016**：系统必须在校验通过后原子保存分类结果；失败时不得留下部分写入的配置。
- **FR-017**：系统必须在指标已被目标域或来源域的公式、阈值等配置引用时阻止重新分类，并提示需要先解除引用。
- **FR-018**：系统必须在并发更新或过期提交时返回冲突，不得静默覆盖较新的分类结果。
- **FR-019**：系统必须提供导入结果摘要，包括新增、更新、跳过、失败和未出现在本次全集的已登记指标数量。
- **FR-020**：系统必须为导入和分类操作保留操作结果或审计信息，至少包括操作时间、操作类型、目标指标和操作结果。
- **FR-021**：涉及查询或变更 KPI 指标资源库的接口必须先更新接口契约，再同步实现、前端调用和测试。

### 关键实体 *(如果功能涉及数据则填写)*

- **KPI 资源指标**：从资源系统全集登记的一个指标，包含稳定 key、资源 ID、中文名、英文名、单位、基础指标类型、登记状态和当前业务域；业务域只能为未分类、`call`、`api` 或 `media`。
- **单位资源**：资源文件中用于描述计量单位的非指标资源；只作为单位参考或导入统计，不进入 KPI 指标资源列表。
- **分类操作**：用户把一个或多个资源指标归入业务域的变更；包含目标域、命中的指标、校验结果、保存结果和操作时间。
- **KPI 域配置**：`call`、`api` 或 `media` 的运行配置；只有完成在线分类的指标才进入对应域，公式和阈值仍由用户显式维护。

## 成功标准 *(必填)*

### 可度量结果

- **SC-001**：用户导入一份 1000 行以内的资源全集 CSV 后，能在 2 分钟内看到全部 `ME_` 指标已进入可搜索的资源库。
- **SC-002**：重复导入相同资源全集后，指标数量不增加，已确认业务域保持不变。
- **SC-003**：用户能在 30 秒内通过资源 ID 或中英文名关键词定位任意一个已登记指标。
- **SC-004**：用户能在一次操作中完成最多 100 个指标的批量分类，且成功结果全部出现在目标域。
- **SC-005**：分类保存失败或并发冲突时，用户能看到明确错误；系统不产生重复归属或部分写入的域配置。

## 假设

- 资源 CSV 是用户提供的离线资源全集快照，不是 PatrolX 运行时从被检系统采集的数据。
- `ME_` 前缀代表指标资源，`UNIT_` 前缀代表单位资源。
- 资源 ID 在资源系统中唯一，可作为 KPI 指标的稳定 key 来源。
- 本功能的在线分类是本地配置管理能力，不包含在线采集、被检系统连接或 KPI 数据计算。
- 首版只需要 `call`、`api`、`media` 三个业务域；新增业务域属于后续扩展。
- 首版不要求根据资源语义自动分类业务域，也不要求自动生成阈值、公式或告警。
- 桌面浏览器是主要操作入口，不要求移动端适配。
