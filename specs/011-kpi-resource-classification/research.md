# 研究记录：KPI 资源全集登记与在线分类

## 决策

### 1. 资源库存储方式

**决定**：使用 `deploy/config/kpi/resource_metrics.yaml` 保存基础指标与 `domain` 状态，使用 `deploy/config/kpi/resource_metrics_audit.jsonl` 追加审计记录。

**原因**：KPI 当前配置已经是轻量文件配置；资源库与域配置属于同一配置生命周期，无需引入数据库。YAML 便于审查和备份，JSONL 适合追加式审计。

**影响**：部署时需要保留两个文件的持久化卷；并发写入必须加锁。

### 2. 稳定 key 生成

**决定**：`ME_21002` 生成 `me_21002`；资源 ID 必须在小写后满足现有 KPI key 规则。

**原因**：资源 ID 是资源系统唯一标识，可避免中英文名冲突；同时与巡检结果中的指标 key 兼容。

**影响**：非法资源 ID 不得自动改写，否则后续配置会不稳定。

### 3. 单位和中英文名解析

**决定**：沿用现有保守推断：括号单位优先；成功率/次数/时延/容量按中文语义推断基础类型；英文名以资源 CSV 提供值为准，占位文本转为待补充。

**原因**：能快速生成可用基础配置，同时不假装知道业务域。

**影响**：不生成派生公式、阈值、告警或业务域。

### 4. 导入失败策略

**决定**：表头错误、编码不可识别、重复资源 ID 冲突导致整次导入失败；单行资源 ID 缺失、非法或非 `ME_`/`UNIT_` 资源记录在报告里并跳过。

**原因**：全局结构错误可能代表文件选错，必须阻止部分导入；单行异常不应阻塞全集其余可用资源。

**影响**：导入响应必须包含足够的行号和原因，便于修正 CSV。

### 5. 分类事务

**决定**：使用进程内文件锁、配置快照校验、临时文件写入和失败回滚；资源库与域配置都成功后才提交审计。

**原因**：分类会同时影响资源库和域 YAML，必须避免半写和并发覆盖。

**影响**：批量请求是原子的；部分指标失败时整批失败并返回详细原因。

### 6. 引用保护

**决定**：扫描域配置中的公式输入、阈值指标和容量声明；任何引用目标指标时禁止换域。

**原因**：key 是公式和阈值稳定性基础，静默换域会破坏巡检配置。

**影响**：用户必须先解除引用，再执行重新分类。

## 风险

| 风险 | 缓解 |
| --- | --- |
| 资源全集与现有域配置存在同名或同 key 数据 | 导入只登记，不自动分类；分类时发现重复定义先校验内容，冲突则失败 |
| 并发导入/分类导致旧状态覆盖新状态 | 文件锁 + revision 快照比较，过期提交返回 409 |
| 大 CSV 前端一次性渲染卡顿 | 分页查询 + 搜索筛选，首版上限保持 200/page |
| 审计文件增长 | 每条记录只保留关键上下文；后续可按运维策略归档 |
