# 研究记录：KPI 指标字典与分组展示

## 决策 1：KPI 配置按领域目录化

**决策**：将 `deploy/config/kpi_rules.yaml` 演进为 `deploy/config/kpi/` 下的 `common.yaml`、`call.yaml`、`api.yaml`、`media.yaml`。

**理由**：新增指标只影响目标领域，避免一个全局 KPI 文件无限膨胀；公共时区、版本和预算不重复；领域归属在加载时天然确定。

**备选方案**：
- 继续使用单一文件并加 `domains` 层级：改动小，但长期新增仍集中在一个文件。
- 按职责拆成 `metrics/aliases/limits` 多个目录：职责清晰，但新增一个指标常要跨文件维护。
- 数据库配置：便于扩展，但引入在线维护需求，违反本版离线、静态配置边界。

**结论**：选择领域自包含目录。领域文件内部仍可同时包含指标、别名、公式和阈值，保证新增一个指标通常只改一个文件。

## 决策 2：配置版本与兼容

**决策**：新目录配置 `version=2`；新规则结果 `metadata.version=2`；不迁移历史结果。

**理由**：目录结构和指标契约发生实质扩展；版本号可避免历史结果与新结构混淆。`RuleResult` 顶层字段不变，历史 JSON 继续可读。

**备选方案**：沿用 `version=1` 并新增字段：迁移少，但无法明确区分旧结果与具备目录能力的新结果。

## 决策 3：名称匹配采用归一化精确匹配

**决策**：别名匹配执行 Unicode `NFKC`、去首尾空白、压缩连续空白和 `casefold` 后精确比较。

**理由**：能处理大小写、全半角和多余空格差异，同时避免模糊匹配把业务含义不同的指标错误归并。

**备选方案**：
- 直接字符串匹配：最保守，但中英文导出常见空格差异会造成重复维护。
- 拼音或语义相似度：维护成本低，但会产生不可解释和随机归属风险。

## 决策 4：派生公式使用声明式模型

**决策**：第一版支持声明式 `ratio` 公式和可选分母求和兜底，不支持任意表达式求值。

**理由**：成功率、失败率是当前明确需求；声明式输入便于做存在性、类型、循环依赖校验和 provenance 展示。不使用 `eval`，也不在第一版引入表达式解释器。

**备选方案**：
- Python `eval`/受限 AST：表达力强，但安全、审计和依赖校验复杂。
- 只硬编码成功率：实现快，但不能满足后续新增派生指标。

## 决策 5：公式优先且不直接值兜底

**决策**：配置了公式时始终按公式计算；直接同语义列只保留为交叉参考。公式输入缺失或分母为零时输出不可用原因。

**理由**：这是规格澄清结论，保证同一名义指标在不同文件中的计算口径一致，避免“有输入时公式值、无输入时直接值”的混合口径。

## 决策 6：多周期主值聚合先聚合再计算

**决策**：比率类先汇总全量分子、分母再计算；计数求和；容量取最大；时延取最大或指定分位。

**理由**：比率平均值会受到周期分母权重影响，产生口径失真。先汇总分子和分母才是全量成功率。

**备选方案**：各周期比率平均或中位数：只适合特定诊断视图，不适合主值结论。

## 决策 7：KPI 元数据进入既有 RuleResult

**决策**：不新增 KPI 规则结果端点；把目录和指标结果写入 `RuleResult.metadata`，并在 OpenAPI 中补充 schema 说明与示例。

**理由**：规则结果已有稳定资源端点和缓存 JSON；KPI 元数据属于规则私有结果展示结构，写入 `metadata` 可避免修改既有 `Metric` 字段语义。

**备选方案**：
- 扩展 `Metric` 增加分组、公式等字段：会改变通用契约模型并影响所有规则。
- 新增 `/kpi/catalog` 端点：需要处理任务/规则上下文一致性，增加重复读取。

## 决策 8：原始记录按需分页查询

**决策**：新增 KPI 原始记录分页端点，并为规则结果接口增加可选 `exclude_records=true`。默认规则结果行为保持不变。

**理由**：历史结果和既有调用保持兼容；新前端首屏可避免传输和渲染全部原始记录，抽屉按指标、文件、周期和状态查询。

**备选方案**：
- 只在前端分页：接口仍一次返回大数组，无法满足首屏性能目标。
- 修改默认规则结果移除记录：会改变既有调用语义，不满足兼容要求。

## 决策 9：前端按 metadata 版本选择视图

**决策**：`metadata.version >= 2` 使用目录式面板；旧结果继续使用现有 KPI 明细表。

**理由**：前端不能假设所有历史任务都重跑；按版本回退可以在不迁移历史数据的情况下兼容展示。

## 决策 10：静态配置校验时机

**决策**：配置加载器在规则执行前完成结构、引用、冲突和预算校验；校验失败让目标规则返回 `error` 和具体原因。

**理由**：不引入新的在线维护端点；错误留在规则状态内符合单规则失败不中断任务的约束。

**备选方案**：仅启动时校验：无法覆盖测试注入和单规则重跑上下文；静默降级会掩盖配置错误。
