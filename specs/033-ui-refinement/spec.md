# 功能规格：界面降噪与一致性精修

**功能分支**：`033-ui-refinement`

**创建日期**：2026-10-10

**状态**：已澄清

**输入**：用户描述："针对已优化的界面 你还有哪些建议？"。评审提出 18 条改进建议，用户回复"全部采纳"。

## 背景

031（主界面信息层级重构）已完成"结论 → 证据 → 明细"的骨架。031 之后对任务列表、任务详情、规则详情与规则管理页走查，发现三类残留问题：

1. **状态权重与口径**：概览条五色等权、饱和色抢注意力；"规则结果"与"发现问题数"口径不清；0 值状态与空字段占位横线仍在渲染。
2. **次要信息占用首屏**：任务行时间列三行同权、操作入口平铺；规则详情"源文件匹配"独占一张卡片；"重点关注"与"全部规则"重复展示同一批规则；长证据以单段长文本呈现。
3. **一致性与可访问性缺口**：黄色状态文字对比度不足、异常灰与中性灰难区分；顶栏与页头重复品牌；侧边栏选中态过重；术语混用（规则结果 / 发现 / 问题条目）；上传流程缺少提交前反馈。

本轮不改信息架构与功能语义，按"降噪 + 一致 + 可访问"精修 031 之后的界面，并把规则回写 `docs/design/DESIGN.md`。

**本轮边界**：

- 只改前端展示层与 `docs/design/DESIGN.md`；不新增或修改 OpenAPI 契约（上传流程改进为前端前置反馈，复用既有接口与错误码）。
- 不改路由与 URL 语义，既有深链保持可用。
- 不引入新的 UI 组件库；沿用 React + TypeScript + Vite + Ant Design + ECharts。
- 不改变后端规则、执行器、数据模型与执行编排。

## Clarifications

### Session 2026-10-10

- Q: 18 条建议如何拆分版本？ → A: 合并为单一版本，按 P1/P2/P3 排序一次性落地（用户已回复"全部采纳"）。
- Q: 概览条"弱化"的口径？ → A: 概览条（KPI 卡）中"通过 / 跳过"使用低饱和浅色，"失败 / 告警 / 异常"保持标准状态色；计数与分段顺序统一为"失败 → 告警 → 异常 → 跳过 → 通过"。
- Q: 表格密度默认值？ → A: 默认"紧凑"，偏好存浏览器本地；本地偏好不可用时静默回退默认。
- Q: 严重度如何降噪？ → A: 严重度改为"色点 + 文字"的轻量表达，不再使用描边标签；彩色标签额度留给状态。
- Q: 源文件匹配如何降级？ → A: 从独立卡片降为规则头部下的一行元数据（等宽字体、可复制），不再占用首屏高位。
- Q: 上传流程是否需要契约变更？ → A: 不需要。任务 ID 预览与校验反馈在前端完成，后端校验语义与错误码（含 `package_checksum_conflict`）保持不变。

## 用户场景与测试 *(必填)*

### 用户故事 1 - 值班人员在任务列表只被异常信息吸引（优先级：P1）

值班人员打开任务列表时，概览条与任务行都应把注意力让给"失败 / 告警 / 异常"：正常状态低饱和呈现，计数按异常优先排序，指标口径一眼可查；时间与操作不再与异常信息争夺注意力。

**优先级理由**：任务列表是入口页面，"看到一个彩虹条却不知道先看哪"是当前最主要的噪音来源。

**独立测试**：用既有 E2E 种子任务（含失败任务、全通过任务、告警任务）打开任务列表，检查分布条与计数排序、指标口径提示、时间列层级、行内操作数量与空字段处理。

**验收场景**：

1. **给定** 某任务存在失败 5、告警 3、跳过 2、通过 4，**当** 查看该任务行与概览条，**则** 计数顺序为"失败 → 告警 → 跳过 → 通过"，分段条顺序一致，悬浮任一段显示中文状态、计数与占比。
2. **给定** 概览条同时存在通过与非通过状态，**当** 查看分段条，**则** 通过 / 跳过为低饱和浅色，失败 / 告警 / 异常为标准状态色。
3. **给定** 用户不理解"规则结果"与"发现问题数"的差异，**当** 悬浮对应指标，**则** 显示口径说明与统计范围，并解释一条规则可产生多条发现。
4. **给定** 某任务全部规则通过，**当** 查看该行，**则** 只显示"通过 N"，不出现 0 值状态与空元数据占位符。
5. **给定** 某任务行有报告、失败日志等多个次要入口，**当** 查看该行操作区，**则** 常驻操作不超过 1 个，其余在悬浮或"更多"菜单中可及。

---

### 用户故事 2 - 任务详情结论无噪音、不重复（优先级：P1）

值班人员打开任务详情时，结论句只讲非零事实；元数据只显示真实有值的字段；"重点关注"与"全部规则"不再重复表达同一批规则。

**优先级理由**：详情页是排查主战场，零值与重复会让用户在首屏重复阅读同一事实。

**独立测试**：用含失败与告警的种子任务打开详情页，检查结论句、元数据行、重点关注与全部规则的去重与"显示全部"入口。

**验收场景**：

1. **给定** 某任务失败 5 条、无异常，**当** 查看结论句，**则** 只表达失败与告警等非零状态，不出现"异常 0 条"。
2. **给定** 任务元数据中版本、设备为空，**当** 查看结论区元数据，**则** 只渲染有值字段且最多平铺 4 项，空字段不显示占位横线，其余可在"更多元数据"查看并复制。
3. **给定** 8 条规则进入"重点关注"，**当** 查看下方"全部规则"，**则** 已上浮规则不与其等权重复，且存在"显示全部"入口可恢复完整列表。

---

### 用户故事 3 - 规则详情先读结论与证据，长证据可展开（优先级：P2）

排查人员打开规则详情时，首屏看到结论、建议与结构化后的发现条目；证据按键值分行展示、关键数值高亮，超长证据可展开，来源路径可复制；"源文件匹配"降为一行元数据，不再占用高位。

**优先级理由**：规则详情是排查闭环最后一跳，当前长段落与高位配置卡片让用户在文字墙里找结论。

**独立测试**：用 `alarm.flapping` 失败规则与全通过规则分别打开详情页，检查发现条目结构、关键数值高亮、长证据折叠、复制动作与源文件匹配位置。

**验收场景**：

1. **给定** 某发现条目的证据包含来源、证据、详情、建议四类信息，**当** 查看该条目，**则** 四类信息分行（或键值对）展示而非单段长文本，关键数值可见高亮。
2. **给定** 证据超过 4 行，**当** 查看该条目，**则** 默认折叠并可展开 / 收起，展开后信息完整。
3. **给定** 用户需要来源文件路径，**当** 点击"复制"，**则** 路径复制成功并有可见反馈。
4. **给定** 规则声明了 `source_patterns`，**当** 查看规则详情，**则** 源文件匹配以不超过一行的元数据展示（等宽字体、可复制），位置在结论与建议之后、发现之前。
5. **给定** 发现条目含严重度，**当** 查看条目，**则** 严重度以"色点 + 文字"呈现，不与状态标签争夺视觉权重。

---

### 用户故事 4 - 列表密度可选，规则管理页细节到位（优先级：P2）

运维人员可以按自己的屏幕与任务切换表格密度，偏好被记住；规则管理页的时间、编码与启停操作表达更工程化。

**优先级理由**：桌面分辨率跨度大（1280~1920），固定密度无法同时兼顾扫读效率与舒适度。

**独立测试**：在任务列表切换紧凑 / 舒适并刷新页面，检查偏好保持、筛选与分页不重置；在规则管理页检查时间格式、排序与开关反馈。

**验收场景**：

1. **给定** 用户在 1440×900 打开任务列表，**当** 切换到紧凑密度，**则** 同视口可见行数增加，筛选、分页与滚动位置保持不变，刷新后密度保持。
2. **给定** 本地偏好不可用，**当** 打开列表，**则** 使用默认紧凑密度且无报错。
3. **给定** 用户查看规则管理列表，**当** 查看更新时间列，**则** 以相对时间展示并可悬浮查看完整时间，该列可排序，规则编码为等宽字体。
4. **给定** 用户切换规则启停，**当** 请求失败，**则** 开关回滚到变更前并给出失败原因；请求进行中不可重复触发。

---

### 用户故事 5 - 全局视觉一致且对色觉障碍用户可用（优先级：P2）

用户在任意页面切换时，状态语义、顶栏、侧边栏与术语一致；状态不依赖颜色单独表达，文字对比度满足可读性要求。

**优先级理由**：一致性决定"是否还要重新适应"，可访问性决定信息在弱色觉与低对比环境下是否仍然可读。

**独立测试**：逐页走查顶栏、侧边栏、状态标签与术语；对状态文字做对比度核算，并检查异常状态是否带颜色以外的冗余标识。

**验收场景**：

1. **给定** 页面显示黄色系状态文字，**当** 计算对比度，**则** 达到 WCAG AA（≥ 4.5:1）；填充色块保持标准状态色不受影响。
2. **给定** 状态为"异常"，**当** 查看分布条与标签，**则** 除灰色外还有形状或纹理等冗余标识，可与中性灰文本区分。
3. **给定** 用户进入任意页面，**当** 查看顶栏，**则** 顶栏不重复产品名，而是展示当前页面上下文与用户区；访客模式下"登录"不是主按钮权重。
4. **给定** 用户查看左侧导航，**当** 查看当前选中项，**则** 选中态为淡色底 + 左侧指示条 + 品牌色文字，不再是整块实心主色。
5. **给定** 界面出现"规则结果 / 发现 / 问题条目"等词，**当** 对照 `docs/design/DESIGN.md` 术语表，**则** 用词与术语表一致。

---

### 用户故事 6 - 上传前就知道会创建什么（优先级：P3）

运维人员选择数据包后，在提交前看到将生成的任务 ID、文件校验结果与同名任务处理方式，避免提交后才发现命名冲突或格式问题。

**优先级理由**：一个包 = 一个任务 = 一个输出目录，命名冲突的代价高；前置反馈可以把返工挡在提交之前。

**独立测试**：分别选择合法文件、非法扩展名、超长文件名与已存在同名任务，检查预览、禁用状态与提示文案。

**验收场景**：

1. **给定** 用户选择一个合法压缩包，**当** 文件选定，**则** 弹窗显示将生成的任务 ID 预览、文件大小与格式校验结果。
2. **给定** 用户选择非法格式或超限文件，**当** 文件选定，**则** 提交按钮禁用并给出具体原因。
3. **给定** 同名任务已存在且数据包 checksum 不同，**当** 用户提交，**则** 提示修改文件名或查看已有任务；checksum 相同时提示将打开已有任务。

---

### 边界情况

- 五态全为 0 时只显示"暂无规则结果"，不渲染分段条与 0 值计数。
- 数据加载中不得渲染易误解的 0 值分布。
- 只有告警（无失败）的任务结论为"需要关注"，使用黄色而非失败红。
- 元数据字段全部为空时隐藏元数据行，不显示占位横线。
- 文件名包含中文、大写字母或连续特殊字符时，任务 ID 预览必须与后端派生结果一致。
- 同名任务存在且 checksum 相同时按其幂等语义提示"将打开已有任务"。
- 本地偏好读取失败或不可写时回退默认密度且不报错。
- 紧凑密度下超长任务名、规则名、路径截断显示，完整值可悬浮或复制获得。
- 1280px 宽表内部横向滚动时操作列保持固定且不遮挡其他列。
- 密度切换、复制、展开 / 收起必须可键盘触发并有可见焦点。

## 需求 *(必填)*

### 状态与口径

- **FR-001**：状态分布（概览条、任务行计数行、任务详情分布）必须统一按"失败 → 告警 → 异常 → 跳过 → 通过"排序，计数与分段顺序一致。
- **FR-002**：概览条中"通过 / 跳过"必须使用低饱和或浅色表达，"失败 / 告警 / 异常"保持标准状态色；不得五色等权饱和表达。
- **FR-003**：分布条每一段必须可悬浮查看状态中文名、计数与占比（整数百分比）；五态全 0 时显示"暂无规则结果"且不渲染分段条。
- **FR-004**：概览指标（巡检任务 / 注册规则 / 规则结果 / 发现问题数）每一项必须提供口径说明与统计范围（全部任务或当前筛选）；说明必须解释"规则结果"与"发现问题数"的差异。
- **FR-005**：0 值状态不得渲染：结论句、计数行、分布条、指标块均不得出现 0 值状态；仅在全部为 0 时展示统一空文案。

### 列表可扫读

- **FR-006**：任务列表"时间与耗时"列必须以耗时为主信息，创建 / 完成时间为次要信息并展示相对时间；悬浮可查看完整时间；数字使用等宽数字对齐。
- **FR-007**：时间与耗时信息在列宽内不得因换行导致行高不一致；超长耗时按统一格式收敛并可悬浮查看完整值。
- **FR-008**：任务行内常驻可见操作最多 1 个（"详情"）；"报告 / 失败日志 / 重跑 / 重建 / 删除"收进悬浮显示或"更多"菜单；危险操作保持二次确认；同一入口不得重复出现；失败原因摘要本身可点击进入日志。

### 任务详情

- **FR-009**：任务详情结论句只表达非零状态，不得出现"异常 0 条"这类零值表述。
- **FR-010**：任务关键元数据只渲染有值字段，空字段不渲染占位横线；最多平铺 4 项，其余收进"更多元数据"入口；完整值可复制。
- **FR-011**：同一规则不得在"重点关注"与"全部规则"中默认等权重复；必须提供去重标记或默认排除，并保留"显示全部"入口，不得造成信息丢失。

### 规则详情

- **FR-012**：发现条目证据必须结构化展示（来源 / 证据 / 详情 / 建议 分行或键值对），不得把多段信息用分隔符拼成单段长文本。
- **FR-013**：发现条目关键数值（分组数、次数、阈值、窗口时长）必须高亮；严重度以"色点 + 文字"轻量表达，不使用描边标签。
- **FR-014**：长证据默认折叠（阈值 4 行），提供展开 / 收起；来源文件路径提供复制动作并有成功反馈；不得丢失既有字段。
- **FR-015**：规则详情"源文件匹配"不得作为独立高位卡片，必须以不超过一行的元数据展示（等宽字体、可复制），位置在结论与建议之后、发现之前。

### 密度与管理页

- **FR-016**：任务列表、任务详情"重点关注"表格与规则管理列表必须提供"紧凑 / 舒适"密度切换；默认紧凑；偏好持久化在浏览器本地；切换不得重置筛选、分页与滚动位置；偏好不可用时静默回退默认。
- **FR-017**：规则管理列表更新时间以相对时间为主并可悬浮查看完整时间，支持排序；规则编码使用等宽字体。
- **FR-018**：规则启停开关变更必须有结果反馈，失败时回滚到变更前；请求进行中不可重复触发。

### 全局一致性与可访问性

- **FR-019**：状态不得仅依赖颜色；用于文字的状态色必须满足 WCAG AA（≥ 4.5:1）；"异常"必须在分布条或标签中带颜色以外的冗余标识（形状 / 纹理 / 图标）。
- **FR-020**：顶栏不得重复产品名，承载当前页面上下文与用户区；访客模式下"登录"不得使用主按钮权重。
- **FR-021**：侧边栏选中态使用淡色底 + 左侧指示条 + 品牌色文字，不使用整块实心主色。
- **FR-022**：`docs/design/DESIGN.md` 必须新增术语表，统一"规则结果 / 发现 / 问题条目 / 状态"等词；界面文案遵循术语表。

### 上传前置反馈

- **FR-023**：上传弹窗选择文件后必须展示将生成的任务 ID 预览、文件大小与格式校验结果；不合法（格式、超长、空文件、超限）时提交前给出具体原因并禁用提交。
- **FR-024**：任务 ID 预览必须与后端派生规则一致；同名任务存在时给出明确说明与下一步动作（修改文件名 / 查看已有任务）；checksum 相同时提示"将打开已有任务"。
- **FR-025**：上传改进不得改变后端校验语义、状态码与错误码，不得为预览新增接口调用；若未来确需接口变更，必须先更新 `docs/api/openapi.yaml` 并同步生成客户端。

### 兼容与约束

- **FR-026**：既有交互必须保持：状态筛选、搜索、分页、轮询、深链、单规则重跑、报告查看、删除与重建确认。
- **FR-027**：1280px ~ 1920px 宽度下页面不得出现横向滚动；1920px 内容宽度不超过 1600px；宽表仅允许表格内部横向滚动。
- **FR-028**：既有自动化测试必须继续通过；结构调整导致的断言变化必须等价替换，不得删除既有行为覆盖。
- **FR-029**：不得引入新的 UI 组件库；新增依赖必须有明确收益并单独说明。
- **FR-030**：所有 UI 变更必须回写 `docs/design/DESIGN.md`，并在验证文档中留存可复现的截图与测试证据。

### 关键实体 *(如果功能涉及数据则填写)*

本功能不引入契约数据实体；涉及以下展示对象：

- **概览指标口径说明**：指标名称、统计范围、计算口径、与相邻指标的差异解释。
- **状态分布**：五态计数、排序（异常优先）、各段颜色权重与占比。
- **发现条目**：来源、证据、详情、建议、严重度、关键数值与来源路径。
- **显示偏好**：表格密度（紧凑 / 舒适）及持久化状态。
- **上传预检**：预计任务 ID、文件大小、格式校验结论与同名冲突提示。
- **术语表**：规则结果、发现、问题条目、状态等全站统一用词。

## 假设

- 用户为运维与巡检人员，桌面环境使用；不要求移动端。
- 18 条建议合并为一个版本交付，按 P1 / P2 / P3 顺序实现；P1 先形成可演示切片。
- 本轮不修改 OpenAPI 契约；上传改进复用既有接口与错误码。
- 表格密度偏好存储在浏览器本地，不引入用户设置接口。
- 术语表由本版本首次确定，后续版本沿用。
- 概览指标口径说明使用既有字段推导，不新增统计接口。
