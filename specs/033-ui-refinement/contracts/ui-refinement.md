# UI 契约：界面降噪与一致性精修

本功能不修改 `docs/api/openapi.yaml`。以下契约约束前端组件行为与展示规则，实现与测试必须以此为准。

## 1. 状态分布（StatusDistribution）

- 输入：五态计数（既有 `TaskStats` 结构）与可选交互回调；不新增数据字段。
- 排序：`fail → warn → error → skip → pass`。
- 权重：`variant="full"` 且用于概览卡时 pass/skip 使用弱化色；任务行与详情保持标准状态色。
- 交互：每段与计数提供 Tooltip，内容为"状态 计数（百分比）"；交互模式下点击计数触发现有状态筛选。
- 空态：五态全 0 渲染"暂无规则结果"，不渲染空条与 0 值。

## 2. 概览指标（OverviewMetric）

- 四项指标必须提供口径说明与统计范围；说明文案固定包含"一条规则可产生多条发现"。
- 数值为 0 时仍展示指标本身（任务总量类），但状态分布不渲染 0 值段。

## 3. 任务列表行（TaskRow）

- 常驻可见操作最多 1 个（详情）；报告 / 失败日志在 hover / 聚焦时显示且保留在更多菜单；重跑 / 重建 / 删除仅在更多菜单。
- 时间列：耗时为主信息，创建 / 完成为相对时间；完整时间通过 Tooltip 获取；数字等宽对齐。
- 元数据列：空值不渲染；超长截断并提供完整值。
- 失败任务：行内失败原因摘要可点击进入日志；不得重复出现第二个失败日志入口。

## 4. 任务结论与元数据（ConclusionHero）

- 结论句只包含非零状态；不出现"异常 0 条"。
- 元数据只渲染有值字段，最多平铺 4 项，其余收纳在"更多元数据"；完整值可复制。
- "重点关注"与"全部规则"默认不重复展示同一规则；提供"显示全部"。

## 5. 规则详情（RuleDetail）

- 顺序：结论与建议 → 源文件匹配（一行元数据）→ 发现 → 证据 → 技术信息。
- 源文件匹配高度不超过一行，等宽字体，可复制。
- 发现条目：来源 / 证据 / 详情 / 建议分行；证据按 `；` 结构化，关键数值高亮；超过 4 行折叠；来源路径可复制。
- 严重度使用"色点 + 文字"，不与状态标签争夺权重。
- 重跑入口与进行中状态保持不变。

## 6. 密度切换（Density）

- 三处接入：任务列表、任务详情重点关注表、规则管理列表。
- 默认 `compact`；持久化 key `patrolx.tableDensity`；非法值回退默认。
- 切换不重置筛选、分页与滚动位置；控件可键盘操作且状态可读。

## 7. 可访问性（Accessibility）

- 状态不得仅靠颜色表达；"异常"在分布条或标签中带斜纹 / 形状冗余。
- 用于文字的状态色对比度 ≥ 4.5:1；填充色保留标准状态色。
- 复制、展开 / 收起、密度切换必须可键盘触发并有可见焦点。
- 既有路由、深链与交互行为不得改变。

## 8. 上传预检（UploadPrecheck）

- 选择文件后展示任务 ID 预览、文件大小与校验结论；非法时禁用提交并给出具体原因。
- 任务 ID 派生规则必须与后端 `clean_task_id` 一致（固定样例单测锁定）。
- 同名冲突提示必须包含下一步动作，不允许只报"创建失败"。
- 不新增接口调用；后端校验语义与错误码不变。
