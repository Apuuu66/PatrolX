# 阶段 0 研究：界面降噪与一致性精修

本功能不新增后端接口；研究聚焦"用既有数据与组件完成展示层精修"的技术决策。

## R1 状态分布排序与权重

- **决策**：在 `web/src/utils/taskDisplay.ts` 扩展 `getHealthBarSegments`，统一输出顺序为 `fail → warn → error → skip → pass`，并新增 `emphasis` 概念：概览条中 pass/skip 使用低饱和浅色（`#b7eb8f` / `#91caff`），fail/warn/error 保持标准状态色（`#ff4d4f` / `#faad14` / `#8c8c8c`）；任务行与任务详情保持标准色但沿用同一排序。
- **理由**：排序与权重规则集中在一处工具函数，列表、详情、概览条自动一致；不引入新状态语义。
- **备选**：新增独立"概览条"组件（否决：重复逻辑）；修改全局状态色（否决：违反 DESIGN.md 状态语义一致性）。

## R2 分布 Tooltip 与占比

- **决策**：`StatusDistribution` 每段与计数使用 Ant Design `Tooltip`，内容为"状态中文名 + 计数 + 整数百分比"；空态与全 0 逻辑不变。
- **理由**：AntD Tooltip 自带键盘与读屏可达性，无需新增依赖；占比在组件内由既有 total 推导。
- **备选**：原生 `title`（否决：触达慢、样式不可控）；ECharts（否决：小场景过度设计）。

## R3 概览指标口径

- **决策**：新增前端常量表（`web/src/utils/taskOverview.ts`）描述 4 个指标的名称、口径说明与统计范围；界面用信息图标 + Tooltip 展示，"规则结果"与"发现问题数"的差异在说明中解释。
- **理由**：纯展示层映射，数据仍来自既有 `OverviewSummary`，不触碰契约。
- **备选**：后端新增口径字段（否决：无必要，违反本轮边界）。

## R4 时间与耗时排版

- **决策**：新增 `formatRelativeTime`（基于 dayjs `relativeTime` 插件 + `zh-cn` locale），任务列表以相对时间为主、`Tooltip` 显示完整时间；耗时使用主文本色与 `font-variant-numeric: tabular-nums`。
- **理由**：dayjs 与中文 locale 已在依赖内，零新增依赖即可满足。
- **备选**：手写相对时间（否决：边界多、易错）。

## R5 任务行操作收敛

- **决策**：行内常驻操作只保留"详情"；"报告 / 失败日志"在行 hover 或聚焦时显示，并同时保留在 ⋯ 菜单中作为键盘与触屏兜底；重跑 / 重建 / 删除保持在 ⋯ 菜单；失败原因摘要本身可点击进入日志。
- **理由**：兼顾扫读噪音与操作效率；菜单项保留既有 key 与行为，降低回归风险。
- **备选**：全部收进 ⋯（否决：报告是高频操作）；保持平铺（否决：与降噪目标冲突）。

## R6 零值与空元数据

- **决策**：`deriveTaskConclusion` 按非零状态动态拼接结论句；`buildMetadataItems` 过滤空值字段，"数据包 / 版本 / 设备"优先平铺，客户元数据按可用性补齐，最多 4 项，其余进 `Popover` "更多元数据"；全部为空时隐藏元数据行。
- **理由**：结论与元数据都来自既有字段，纯展示层过滤即可消除噪音。
- **备选**：后端过滤（否决：属于展示策略）。

## R7 重点关注与全部规则去重

- **决策**：`TaskDetailPage` 把"重点关注"中的规则 code 传给 `RuleBrowser`，默认从"全部规则"排除这些条目，并显示"另有 N 条已在上方重点关注 · 显示全部"开关；开启后完整展示。
- **理由**：不改变规则分组、搜索与筛选语义（搜索命中被排除项时自动纳入并提示）。
- **备选**：全部规则中保留但降低不透明度（否决：仍属重复表达）。

## R8 发现证据结构化

- **决策**：新增 `parseFindingEvidence` 工具：按 `；` 拆段，识别"键：值"或"键 值"结构输出键值列表；数字、次数、时长用高亮 span；解析失败降级为原文；默认折叠超过 4 行；来源文件路径提供复制按钮。
- **理由**：证据字符串是既有契约字段，展示层拆分不改变数据；降级策略保证任意文本可读。
- **备选**：修改后端证据结构（否决：本轮不改契约）。

## R9 源文件匹配降级

- **决策**：`RuleDetailPage` 移除独立 Card，改为结论卡片内一行元数据（等宽字体 pattern + 复制按钮），保留 `data-testid="rule-section-source-patterns"` 便于等价替换断言。
- **理由**：配置信息不占首屏高位，发现与结论优先（SC-005）。
- **备选**：折叠面板（否决：仍占独立区块）。

## R10 严重度轻量表达

- **决策**：`SeverityTag` 增加 `variant?: "tag" | "plain"`，`plain` 为"色点 + 文字"（含 title 与 aria-label）；规则详情与规则结果表使用 plain，其它场景保持 tag。
- **理由**：把彩色标签额度留给状态；组件复用避免各处自绘。
- **备选**：全局替换 Tag（否决：其他页面仍需标签语义）。

## R11 表格密度切换

- **决策**：新增 `useTableDensity`（localStorage key `patrolx.tableDensity`，默认 `compact`）+ `DensitySegmented` 组件；任务列表、任务详情重点关注表、规则管理表接入；AntD `Table size` 与自定义行内 padding 联动；读取失败静默回退。
- **理由**：局部接入避免全局 ConfigProvider 影响的回归面。
- **备选**：全局 ConfigProvider（否决：影响所有页面）；仅 CSS 媒体查询（否决：无法记忆用户选择）。

## R12 规则管理页细节

- **决策**：更新时间列改相对时间 + Tooltip 完整时间并支持排序；规则编码等宽字体；开关变更沿用 loading 并保证失败回滚（仅在后端确认成功后更新本地状态）。
- **理由**：失败回滚在现有实现中已基本成立（先请求后更新），需补测试与提示文案；其余为展示增强。
- **备选**：增加二次确认（否决：启停是低频可逆操作，确认会拖慢批量调整）。

## R13 可访问性与对比度

- **决策**：新增"文本安全"状态色：warn 文本 `#ad6800`、pass 文本 `#389e0d`、skip 文本 `#0958d9`、error 文本 `#595959`；分布条与标签的填充仍用标准状态色；"异常"分段叠加斜纹背景以满足颜色以外的冗余；对比度以单测算法断言 ≥ 4.5:1。
- **理由**：区分"填充色"与"文字色"，在不破坏状态语义的前提下满足 AA。
- **备选**：仅调整黄色（否决：异常灰与中性灰同样需要冗余区分）。

## R14 顶栏与侧边栏

- **决策**：顶栏左侧由固定产品名改为当前页面标题（路由映射），右侧保留用户区；登录按钮降为 `default`；侧边栏保留 PatrolX 品牌与深色可读性，选中态改为淡色底 + 左侧指示条 + 品牌色文字（浅色主题）。
- **理由**：消除三处重复品牌；减少与内容区主操作的权重竞争。
- **备选**：完全移除顶栏（否决：用户区与上下文仍有价值）。

## R15 术语表

- **决策**：`docs/design/DESIGN.md` 新增术语表：规则结果、发现、问题条目、状态分布、任务；界面文案按词表更新。
- **理由**：指标口径与文案统一需要一份可引用的权威定义。
- **备选**：仅改文案不写规范（否决：无法防止再次混用）。

## R16 上传预检

- **决策**：前端新增 `deriveTaskIdPreview`（与后端 `clean_task_id` 同规则）与 `validatePackageFile`；上传弹窗选择文件后显示任务 ID 预览、文件大小与校验结论，非法时禁用提交；`package_checksum_conflict` 提示增加"修改文件名 / 查看已有任务"两个动作；不新增接口调用。
- **理由**：派生规则简单且稳定，前端复刻成本低；通过固定样例单测锁定与后端一致性。
- **备选**：新增预览接口（否决：需要契约变更，收益不足）。
- **风险**：规则漂移 → 单测固定样例 + quickstart 人工对照一次后端行为。

## R17 验证策略

- **决策**：vitest 单测覆盖工具函数与组件（排序、弱化色、Tooltip 文案、零值/空值、证据解析、密度 hook、task_id 预览、对比度）；Playwright 覆盖任务列表、任务详情、规则详情、规则管理、上传弹窗与 1280/1920 布局回归；截图 5 张存入 `web/e2e/screenshots/`（不提交）。
- **理由**：沿用既有测试栈与 031 建立的走查方式，满足宪法"新功能验证与展示效果"要求。
- **备选**：仅组件测试（否决：布局与交互需真实浏览器验证）。
