# 前端展示契约：UI 基线

**功能**：031-ui-information-hierarchy | **日期**：2026-10-10

**契约类型**：前端展示层契约（非 HTTP 契约）。本文件不改变 API；接口字段与 Schema 仍以 `docs/api/openapi.yaml` 为准。

**适用范围**：`web/src` 全部页面与共享组件；其余 7 个主页面按本契约第 2、3、5、6 节统一。

---

## 1. 视觉基线契约（全站 MUST）

### 1.1 字号层级

| 层级 | 规格 | 用途 |
| --- | --- | --- |
| 页面标题 | 16px / 600 | 每个页面唯一，置于 `PageHeader` |
| 区块标题 | 14px / 600 | 卡片、分组、折叠面板标题 |
| 正文 | 14px / 400 | 表格、列表、说明正文 |
| 次要说明 | 12px | 辅助说明、时间戳、脱敏提示 |
| 标识符 | 12px 等宽 | 任务 ID、规则编码、文件路径 |
| 数字指标 | 20–24px / 600 | 仅概览条使用，同一页面不得出现第二组等权大数字 |

- MUST NOT 使用超过 24px 的页面标题或指标数字。
- MUST 保证同一页面只有 1 个 16px 页面标题。

### 1.2 间距与圆角

- MUST 使用 `--space-1: 4px`、`--space-2: 8px`、`--space-3: 12px`、`--space-4: 16px`、`--space-5: 24px` 五档刻度，不得引入任意像素值。
- 卡片之间 MUST 为 16–20px；卡片内边距 MUST 为 16–24px。
- 页面内容区 MUST 保持既有 `padding: 24px` 与 `#f5f5f5` 背景。
- 圆角 MUST 沿用 `ConfigProvider` 的 `borderRadius: 8` 与 `--radius-round`（胶囊）。

### 1.3 卡片与分隔线

- 每张卡片 MUST 只表达一个主要对象。
- 状态与关键数字 MUST 靠近标题或内容左端；操作 MUST 位于右上或底部，不得与状态混排。
- 卡片内区块之间 MUST 用 12–16px 间距或 1px `#f0f0f0` 分隔线区分，不得叠加多层边框。

## 2. 状态语义契约（全站 MUST）

| 状态 | 文字 | 颜色 | 用法 |
| --- | --- | --- | --- |
| pass | 通过 | `#52c41a` | 成功、正常 |
| warn | 告警 | `#faad14` | 需要关注但不阻断 |
| fail | 失败 | `#ff4d4f` | 失败结论、失败计数 |
| error | 异常 | `#8c8c8c` | 执行异常 |
| skip | 跳过 | `#1677ff` | 无匹配/不适用，必须附 `skip_reason` |

- MUST 同时提供文字标签，不得只依赖颜色表达状态。
- MUST 全站复用 `web/src/components/statusLabels.ts` 的 `RESULT_STATUS_META` 与 `TASK_STATUS_LABELS`，不得在页面内重新定义状态色。
- MUST NOT 用失败红表达"只有告警"的任务（用黄）。
- MUST NOT 让 0 值状态获得与非零状态相同的视觉权重：0 值不渲染计数、不渲染分段、不渲染独立占位块。
- 状态分布 MUST 使用"分段条 + 非零计数"；五态总和为 0 时 MUST 渲染"暂无规则结果"，不得渲染空条。

---

## 3. 操作分层契约（全站 MUST）

| 类型 | 示例 | 展示位置 |
| --- | --- | --- |
| Primary | 上传数据包、查看报告（结论区） | 主按钮；每个页面最多 1 个 |
| Secondary | 详情、报告、失败日志 | 文本按钮或链接，紧随主操作 |
| More | 重跑、增量重建、全量重建、删除 | `⋯` Dropdown |
| Danger | 删除、全量重建 | 危险样式 + 二次确认 |

- MUST 保证每个页面最多 1 个主操作。
- MUST 把删除与全量重建收进危险入口并要求二次确认。
- MUST NOT 在列表行内平铺超过 3 个可见操作。
- 禁用操作 MUST 说明原因（如"任务执行中不可查看报告"）。

---

## 4. 页面模式契约

### 4.1 任务列表（行式单表）

- MUST 以单表、列对齐的行式列表呈现，每行一个任务。
- MUST 固定列顺序：任务（名称 + 状态 + ID + 失败原因摘要）→ 状态摘要 → 元数据 → 时间与耗时 → 操作。
- MUST 将 `fail / error` 任务默认置顶，并可扩展到 `warn`；同状态内 MUST 按 `created_at` 倒序。
- MUST 在失败任务行直接显示原因摘要，并提供进入失败日志的入口（≤2 次点击）。
- MUST 通过行展开承载数据准备状态、问题文件摘要与重试、失败日志入口。
- MUST 保留状态筛选、搜索、分页（默认 10 条）、轮询与上传表单。
- MUST NOT 保留卡片网格形态与五色等权状态块。

### 4.2 任务详情（结论优先）

- MUST 按以下顺序组织：面包屑 → 结论 Hero → 重点关注 → 全部规则 → 标签页（执行日志 / 设备台账 / 报告预览）→ 折叠的执行与技术信息。
- 结论 Hero MUST 包含结论标签、一句话结论、状态计数、主操作与关键元数据，且在 1440×900 首屏内可见。
- 结论形态 MUST 覆盖：全部通过 / 需要关注 / 任务失败 / 执行中 / 排队中。
- 重点关注 MUST 按 fail → warn 排序、默认可见，最多 5 条 + 其余折叠。
- 全部规则 MUST 按类别分组折叠，默认展开含异常的分组。
- 执行信息与技术信息 MUST 默认折叠。
- MUST NOT 同时出现"提示条"与"重点关注列表"重复表达同一事实。
- 主包解压失败任务 MUST 显示失败原因与阶段并提供日志入口，MUST NOT 展示空规则表格冒充结果。

### 4.3 规则详情（结论 → 证据 → 建议）

- MUST 按以下顺序组织：结论 + 建议 → 源文件匹配 → 发现 → 证据面板 → 折叠技术信息。
- 首屏 MUST 可见规则状态、严重度、结论摘要与建议。
- `skip` MUST 展示 `skip_reason`。
- 指标表 MUST 默认精简列，并支持"显示全部列"切换。
- 重跑入口 MUST 首屏可及；重跑中 MUST 呈进行中状态，完成后 MUST 只刷新本页结果。

### 4.4 其余主页面（仅基线统一）

适用于设备台账、设备详情、基础指标、规则管理、数据字典、报告、日志、用户管理。

- MUST 套用第 1、2、3、5、6 节基线。
- MUST NOT 重排信息架构或改变功能语义（留待后续独立版本）。
- 设备台账与设备详情 MUST 使用默认分页 10 条。

---

## 5. 空 / 加载 / 错误态契约（全站 MUST）

- 页面级加载 MUST 使用骨架屏；局部刷新 MUST 使用轻量 loading，不得引起整页骨架抖动。
- 空状态 MUST 包含"简短说明 + 下一步动作"；任务列表空状态主 CTA MUST 为"上传数据包"。
- 错误态 MUST 提供统一重试入口与一致文案风格，不得只在控制台报错。
- 数据准备失败、规则解析失败等局部问题 MUST 以局部提示表达，不得中断整页渲染。

---

## 6. 可访问性与健壮性契约（全站 MUST）

- 状态信息 MUST 有文字，不得只靠颜色。
- 可交互元素 MUST 可键盘聚焦并用 Enter/Space 触发（沿用 AntD 语义）。
- 长任务名、规则名、文件路径 MUST 截断显示，完整值 MUST 可通过 `title` / 复制获得。
- 1280px 宽度 MUST NOT 出现横向滚动；1920px MUST NOT 无限拉伸内容（内容区最大宽度沿用现有约束）。
- MUST NOT 新增移动端适配。
- MUST NOT 破坏既有路由与 URL 语义，既有深链继续可用。

---

## 7. 兼容与变更约束

- MUST NOT 新增或修改 OpenAPI 字段；展示确需新数据时必须先更新 `docs/api/openapi.yaml` 并同步生成客户端。
- MUST NOT 新增 UI 组件库或运行时依赖。
- MUST 保持既有交互：状态筛选、搜索、分页、轮询、详情页标签与续跑状态、单规则重跑、报告查看、删除与重建确认。
- 因结构调整导致的测试选择器变化 MUST 等价替换断言，不得删除既有行为覆盖。
- 本契约条目在实现完成后 MUST 回写进 `docs/design/DESIGN.md`，作为长期约束。
