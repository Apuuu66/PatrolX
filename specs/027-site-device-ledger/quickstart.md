# 快速验证：局点设备台账

## 展示效果用例

目录：`tests/fixtures/inventory/`

至少构造以下可重复生成的压缩包：

| 场景 | 包内文件 | 上传元数据 | 期望 |
| --- | --- | --- | --- |
| 成功归档 | `config/LST ME.txt`，包含 `NE name = GD-GZ-Core-01` 和 `Software version = V900R021C10SPC100` | 广东省 + 移动 | 任务详情显示局点、设备名、版本、来源；设备列表可见 |
| 缺版本 | 同上，但无版本字段 | 广东省 + 移动 | 观测归档；版本显示未知；质量问题显示版本缺失 |
| 版本冲突 | 同一文件出现两个不同版本 | 广东省 + 移动 | 观测归档；当前版本不更新；质量/任务详情显示冲突值 |
| 设备身份冲突 | 同一文件出现两个不同设备名 | 广东省 + 移动 | 观测不归档；任务详情和质量问题显示身份冲突 |
| 缺局点 | 包含有效 `LST ME.txt` | 省份或运营商为空 | 任务完成；观测不归档；显示缺局点 |
| 缺来源文件 | 不包含 `LST ME.txt` | 广东省 + 移动 | 任务完成；显示缺少 `LST ME.txt`，不等同日志补充包 |
| 日志补充包 | 只包含日志文件 | 无省份 / 运营商 | 任务完成；任务详情显示不涉及设备台账；无观测和版本历史 |
| 局点归属变化 | 同省份同名设备分别上传不同运营商任务 | 运营商不同 | 设备只在当前局点列表显示；历史观测保留局点变化提示 |

`LST ME.txt` 样例可使用：

```text
+++    2026-09-27 10:20:31
O&M IP = 10.10.10.10
%%LST ME%%
RETCODE = 0
Execution succeeded.

NE name = GD-GZ-Core-01
ME ID = 333
Product name = UMF
ME type = UMF2020
Software version = V900R021C10SPC100

---END---
```

构造包时该文件必须命名为 `LST ME.txt` 并放在会被解压分类为 `config` 的路径下。

## 后端验证

实现分支内运行：

```bash
python build.py contract
python build.py gen-web-api
python build.py lint
python build.py test
```

必须覆盖的自动化断言：

1. v3 巡检包创建要求省份和运营商；日志补充包不要求。
2. 日志补充包传入省份或运营商时得到明确错误，不静默关联。
3. v2 创建接口保持既有语义，旧客户端不受影响。
4. 解析器支持成功、缺版本、版本冲突、设备冲突、缺文件和编码兼容。
5. 日志补充包不调用设备解析器，`inventory_parse_results.status=not_applicable`。
6. 全量任务完成后生成 `inventory.json` 并归档观测。
7. 任务重跑覆盖同一 `task_id` 观测且不新增观测行。
8. 覆盖结果变化时生成审计记录；结果不变时不重复生成审计。
9. 输出目录重建不会清空台账表。
10. 设备列表只显示当前局点设备，历史局点在观测历史中可见。
11. 版本方向按原始字符串字典序返回 `upgrade` / `downgrade` / `unchanged`。
12. 缺失、冲突或错误版本保留时间线缺口，不参与方向计算。
13. 台账查询列表默认分页大小为 10。
14. CLI 与 API 对同一样例产生一致的 `inventory.json` 和观测状态。

## 全流程验证

```bash
python build.py verify
```

用于确认台账归档不破坏既有解压、规则执行、摘要、报告和任务目录契约。

## 前端与 E2E

```bash
python build.py web-build
python build.py e2e
```

E2E 至少覆盖一个完整入口到关键结果：

1. 打开任务列表并点击上传。
2. 选择“巡检包”，上传成功样例，选择广东省和移动。
3. 提交后进入任务详情，轮询任务完成。
4. 任务详情显示：
   - 包类型：巡检包
   - 局点来源：上传元数据
   - 局点：广东省 + 移动
   - 设备：`GD-GZ-Core-01`
   - 版本：`V900R021C10SPC100`
   - 来源文件：`config/LST ME.txt`
5. 从任务详情或导航进入局点设备视图。
6. 选择广东省和移动，确认设备列表出现目标设备。
7. 打开设备详情，确认当前版本、观测历史和版本历史。
8. 返回任务列表，上传“日志补充包”，不填写省份和运营商。
9. 打开日志补充任务详情，确认显示“不涉及设备台账”。
10. 打开局点设备列表，确认日志补充任务没有生成设备观测。

## 手动检查重点

- 上传巡检包时没有人工版本输入。
- 上传日志补充包时局点字段不可见或禁用。
- 普通巡检包缺 `LST ME.txt` 时不会显示“不涉及设备台账”，而是显示未归档原因。
- 设备改名或跨运营商迁移不会自动合并历史记录。
- 冲突、缺失和解析错误都有明确中文说明，不出现静默跳过。
- 页面刷新后任务详情和设备详情仍能读取台账状态。
