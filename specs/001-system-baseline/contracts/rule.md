# 规则契约：系统基线

本契约定义巡检器如何接入基线执行器，以及其输出如何被验证和消费。

## 注册元数据

每条可见巡检规则必须声明：

| 字段 | 要求 |
| --- | --- |
| `code` | 稳定的小写点分标识符；可用作文件名。 |
| `name` | 可读展示名称。 |
| `category` | `log`、`kpi`、`traffic`、`alarm`、`config`、`resource` 或 `other`。 |
| `severity` | 规则级严重程度。 |
| `priority` | P1 基础巡检或 P2 综合分析。 |
| `rule_version` | 规则逻辑版本；提交逻辑变更时递增。 |
| `description` | 非空的检查内容说明。 |
| `recommendation` | 非空的后续行动指引。 |
| `hidden` | 内部解压规则为 true，普通巡检规则为 false。 |
| `source_patterns[]` | 匹配任务目录内相对文件路径的正则表达式；普通巡检规则必须非空。 |
| `outputs.metrics[]` | 规则预期产生的指标键/单位。 |
| `params[]` | 可选参数元数据。 |

## 文件匹配规则

1. `source_patterns` 使用正则表达式对 `output/<task_id>/` 内的相对路径做完整匹配。
2. 执行器把匹配到的文件路径集合交给规则的 `RuleContext`。
3. 规则不得导入、调用或依赖其他巡检规则的实现。
4. 没有匹配文件时，规则结果为 `skip`，并必须提供可读的 `skip_reason`。
5. 隐藏的 `pkg.extract.*` 规则是唯一的解压准备规则族，不面向普通规则声明源文件。

## 执行顺序

1. 先执行安全分类解压，保证任务目录内存在按类别组织的文件。
2. 再按 `priority` 和 `code` 执行普通巡检规则。
3. 规则之间没有依赖图，也没有循环依赖问题。

## 执行状态契约

| 状态 | 含义 | 输出契约 |
| --- | --- | --- |
| `pass` | 规则运行且未发现问题 | 必须产生声明的指标。 |
| `warn` | 规则运行且发现告警级问题 | 必须产生声明的指标。 |
| `fail` | 规则运行且发现失败级问题 | 必须产生声明的指标。 |
| `error` | 规则执行失败 | 豁免契约指标输出；失败必须被记录/日志化。 |
| `skip` | 规则不适用 | 豁免契约指标输出；`skip_reason` 必填。 |

## 发现契约

一条发现必须提供：

- 稳定的结果局部 `finding_id`。
- 标题。
- 严重程度。
- 来源文件或包相对位置。
- 证据，截断至安全展示大小。
- 可选详情。
- 建议或对规则级建议的明确引用。

无可追溯证据的泛化结论不是有效的基线发现。

## 重跑契约

1. 目标规则可以独立请求。
2. 如果任务现场尚未解压，执行器先完成幂等安全解压。
3. 执行器按目标规则 `source_patterns` 匹配文件。
4. 规则处理匹配文件后重写自己的结果 JSON。
5. 系统摘要和 HTML 报告同步刷新。
6. 无关规则结果不被抹除或重写。
