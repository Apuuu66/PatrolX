# 实现计划：KPI 跨任务历史趋势

**分支**：`025-kpi-cross-task-trend` | **日期**：2026-09-23 | **规格**：[spec.md](./spec.md)

## 摘要

在保持“一个压缩包 = 一个任务 = 一个输出目录”的前提下，为同一 `device_id` 的已完成任务提供单指标按需历史趋势。任务创建时可填写设备 ID，任务创建后允许 admin 修改；历史查询按设备、测量单元、指标、行对象和周期严格匹配，并以当前任务最新测量时间所在自然日为终点聚合最近 7 个自然日。

后端新增轻量 KPI 历史点索引，避免历史查询全量扫描大任务结果；前端在单指标趋势弹窗中按需加载“单任务趋势 / 历史趋势”，不把历史数据放进任务首屏。

## 技术上下文

**语言/版本**：Python 3.11+；TypeScript / Vite。

**主要依赖**：FastAPI、Pydantic v2、SQLAlchemy、React、Ant Design、ECharts。

**存储**：
- SQLite 只保存任务元数据；`device_id` 保存在 `TaskRecord.customer["device_id"]`。
- `output/<task_id>/task.json` 和 `system.json` 保持任务结果唯一数据源。
- 新增 `output/<task_id>/kpi/history/index.jsonl` 作为 KPI 历史点索引；不把历史点写回 SQLite。

**测试**：pytest；前端 Vitest；涉及契约时执行 OpenAPI 校验和前端客户端生成。

**目标平台**：桌面浏览器访问的本地/在线 Web 服务；离线巡检。

**项目类型**：FastAPI + React 单仓库 Web 应用。

**性能目标**：
- 任务首屏不请求任何跨任务历史数据。
- 单指标历史接口只返回一个指标、一个行对象、一个周期、最多 7 个自然日的点。
- 5 分钟周期理论最大约 2016 点/指标；响应不包含全部原始明细证据。
- 历史读取优先使用 JSONL 索引，不反序列化整个 `system.json` 或旧版大规则 JSON。

**约束条件**：
- 不连接被检系统、不在线采集。
- 不修改原始上传包。
- 不合并任务或压缩包。
- API 变更必须先更新 `docs/api/openapi.yaml`，再实现和生成前端客户端。
- 所有持久化时间使用 UTC 并使用 `*_at` 命名。
- 缺少设备 ID、当前时间、同维度匹配或样本不足时必须明确降级，不得给出误导性历史结论。

**规模/范围**：单任务 22 个测量单元、600+ 指标；本期只覆盖单任务与历史任务的原始 KPI 时间序列，不做任务对比入口和局点画像。

## 设计决策

### 1. 设备 ID

- 创建任务使用表单字段 `device_id`，可选；保存前 trim，保存为 `system.customer.device_id` 与 `TaskRecord.customer["device_id"]`。
- `TaskSummary.device_id` 作为列表/详情展示的派生字段，来源是 `system.customer.device_id` 或 SQLite `customer.device_id`。
- 新增 `PATCH /api/v2/tasks/{task_id}/device-id`，仅允许 admin；pending/running 任务禁止编辑，避免执行输出和数据库元数据竞争。
- 重跑和重建继续从 `task.json` 或 SQLite 读取原 `customer`，天然保留设备 ID。
- 设备 ID 为空时不参与历史匹配，单任务趋势不受影响。

### 2. 历史索引

- 在 KPI 测量单元巡检完成时生成 `output/<task_id>/kpi/history/index.jsonl`，一行一个去重后的时间序列点。
- 索引不保存 `device_id`，避免任务创建后修改设备 ID 时重写索引；查询时读取任务元数据。
- 索引按行对象和周期拆分维度，供单指标查询顺序过滤。
- 历史查询优先读取索引；索引缺失时明确返回 `history_index_missing` 降级，不回退加载未知体积的大 JSON。
- 旧任务如需参与历史，通过显式重建生成索引；不自动改写旧任务输出。

### 3. 查询窗口与冲突

- 窗口终点取当前任务所有有效 KPI 测量点中的最新 UTC 时间所在自然日。
- 窗口为 `[终点日 - 6 天, 终点日]`，共 7 个自然日。
- 历史候选只使用 `status=completed`、`device_id` 非空且与当前任务相同、`completed_at` 不晚于当前任务的任务；同一时间点再按“最新完成巡检任务”去重。
- 完成时间相同且不是当前任务时，按 `task_id` 倒序稳定取舍。
- 同一任务内部的重复点沿用现有单任务规则求均值；跨任务冲突不做均值。
- 不混合设备、测量单元、指标、行对象或周期。

### 4. 基线口径

- 对每个 `HH:mm` 同时刻，收集 7 天窗口内历史任务去重后的值。
- 基线值使用中位数；同时展示样本数和覆盖日期数。
- 样本数少于 3 时输出“样本不足”，不判定显著偏离。
- 显著偏离使用可解释的鲁棒阈值：`abs(current - median) > max(3 * 1.4826 * MAD, 10% * max(abs(median), median_abs_dev), 1e-9)`。
- 摘要只标记“显著高于/低于历史基线”，不引入机器学习模型。

### 5. 前端交互

- 上传表单增加可选“设备 ID”输入框。
- 任务详情显示设备 ID；admin 登录时显示编辑入口。
- 趋势弹窗提供“单任务”和“历史对比”两个视图；打开弹窗且存在设备 ID 时才请求历史接口。
- 多行对象/周期时显示选择器，默认使用当前单任务主趋势的行对象和周期。
- 历史视图展示按日曲线、历史中位数基线、窗口/覆盖/样本摘要和显著点列表。
- 无历史、索引缺失、设备缺失、周期不一致或样本不足时回退单任务趋势，并显示原因；历史加载失败提供重试。
