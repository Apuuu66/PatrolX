# 功能规格：KPI 跨任务历史趋势

**功能分支**：`025-kpi-cross-task-trend`

**创建日期**：2026-09-23

**状态**：已澄清

**输入**：用户描述：第二期支持跨任务历史趋势。单个压缩包可能只覆盖一天或部分时段，因此可以取多次巡检压缩包覆盖多天；创建任务时允许用户简单手动填写设备 ID，用于匹配同一设备的 KPI 历史数据。查看指标趋势时应支持按日对齐对比、同时刻基线和偏差摘要。

## 背景

本功能依赖以下前置能力：

```text
021-kpi-auto-catalog       固定指标清单
023-kpi-single-task-trend  单任务趋势分析
024-kpi-risk-overview      KPI 总览与风险入口
```

第一期的趋势分析只回答：

```text
当前任务包内，这个指标发生了什么变化？
```

第二期要回答：

```text
同一设备在今天这个时刻的表现，和前几日同时刻相比是否异常？
```

本功能不合并任务、不合并压缩包、不建立自动局点画像。每个压缩包仍然保持一个任务、一个输出目录的隔离模型。

## Clarifications

### 2026-09-23

- **Q1：设备 ID 创建后能否调整？**  
  **A1：可以。** 有权限的用户在任务创建后可以修改设备 ID；修改必须由后端权限校验，不能只依赖前端隐藏编辑入口。修改后，后续历史趋势按新设备 ID 匹配。
- **Q2：最近 7 天如何锚定？**  
  **A2：以当前任务数据中的最新测量时间为准。** 最近 7 个自然日指当前任务最新测量时间所在自然日及之前 6 个自然日；不以任务创建、上传或完成时间锚定。
- **Q3：跨任务同一时间点重复时如何取舍？**  
  **A3：以最新完成巡检的任务为准。** 在设备、测量单元、指标、行对象和周期完全相同，且测量时间相同的情况下，只保留任务完成时间最新的成功任务数据；完成时间相同时按 `task_id` 倒序形成稳定结果。

## 用户场景与测试 *(必填)*

### 用户故事 1 - 标记和维护设备 ID（优先级：P1）

巡检操作人员创建任务时，可以在表单中手动填写设备 ID。系统把设备 ID 保存为任务元数据，并在任务详情中展示。有权限的用户创建任务后可以修改设备 ID，修正后的归属用于后续历史匹配。

**优先级理由**：没有稳定的设备归属，多次巡检包无法可靠关联，后续历史对比无从谈起。

**独立测试**：创建任务时填写设备 ID，打开任务详情确认设备 ID 被保存；由有权限用户修改设备 ID 并确认详情和历史匹配使用新值；再次重跑或重建任务，确认设备 ID 不丢失。

**验收场景**：

1. **给定** 用户上传压缩包并填写设备 ID，**当** 任务创建成功，**则** 任务详情显示该设备 ID。
2. **给定** 用户没有填写设备 ID，**当** 任务创建成功，**则** 任务仍然可以正常执行，但设备 ID 显示为空。
3. **给定** 任务已带设备 ID，**当** 用户重跑或重建任务，**则** 设备 ID 保持不变。
4. **给定** 用户输入的设备 ID 只有前后空格，**当** 保存任务，**则** 系统去除首尾空格后保存。
5. **给定** 有权限用户修改已有任务的设备 ID，**当** 修改成功，**则** 任务详情展示新设备 ID，后续历史趋势按新设备 ID 匹配。
6. **给定** 无权限用户尝试修改设备 ID，**当** 发起修改，**则** 系统拒绝变更且原设备 ID 保持不变。

---

### 用户故事 2 - 查看同一设备的历史趋势（优先级：P1）

巡检查看人员打开某个指标趋势后，可以查看跨任务历史趋势。系统只汇总相同设备 ID、相同测量单元、相同指标、相同行对象和相同周期的历史数据，并按日期对齐展示。

**优先级理由**：单个压缩包经常只包含一天或部分时段数据，只有跨任务汇总才能观察日周期异常。

**独立测试**：准备两个或多个已完成任务，任务填写相同设备 ID，数据覆盖不同日期；打开同一测量单元、指标、对象和周期的趋势，确认能看到多日曲线和偏差摘要。

**验收场景**：

1. **给定** 当前任务和多个历史任务使用相同设备 ID，**当** 查看指标历史趋势，**则** 能看到按日期分组的曲线。
2. **给定** 历史数据覆盖多个日期，**当** 查看按日对齐视图，**则** 同一天的曲线按一天内时刻对齐展示。
3. **给定** 存在历史同期数据，**当** 查看某个时间点，**则** 能看到历史同时刻基线、最新值和偏差。
4. **给定** 用户查看历史趋势，**则** 系统不会混合不同设备 ID、不同测量单元、不同指标、不同行对象或不同周期的数据。
5. **给定** 历史任务包含来源信息，**当** 用户定位某个趋势点，**则** 能知道该点来自哪个任务和来源文件。

---

### 用户故事 3 - 历史基线和偏差解释（优先级：P1）

巡检查看人员希望系统直接给出可解释的历史基线结论，而不是只提供多条肉眼难辨的曲线。

**优先级理由**：日周期曲线信息量大，用户需要快速知道当前值是否偏离历史正常范围。

**独立测试**：构造当前任务值明显高于或低于历史同时刻数据的场景，检查基线和偏差摘要。

**验收场景**：

1. **给定** 当前时间点存在多个历史同时刻样本，**当** 查看偏差摘要，**则** 系统展示历史基线值、当前值和偏差。
2. **给定** 当前值偏离历史典型范围，**当** 查看趋势摘要，**则** 系统能提示当前点显著偏离历史基线。
3. **给定** 当前值在历史典型范围内，**当** 查看趋势摘要，**则** 系统不会夸大为异常。
4. **给定** 用户查看历史基线，**则** 能理解基线覆盖的历史日期数量。

---

### 用户故事 4 - 无历史或数据不足时可靠降级（优先级：P2）

巡检查看人员在没有历史任务、历史任务设备 ID 缺失、周期不同或历史点数不足时，仍能清楚理解系统能比较什么、不能比较什么。

**优先级理由**：压缩包覆盖天数不可控，历史对比不能为了出结论而误导用户。

**独立测试**：分别创建只有一个任务、多个任务但设备 ID 不同、多个任务但周期不同的场景，检查趋势视图提示。

**验收场景**：

1. **给定** 当前任务没有可匹配的历史任务，**当** 查看趋势，**则** 系统回退到单任务趋势，并提示无可用历史。
2. **给定** 当前任务只有单日数据，**当** 无历史同期样本，**则** 系统只做短期突变对比并标注“单日数据”。
3. **给定** 历史数据点不足以计算稳定基线，**当** 查看历史趋势，**则** 系统显示数据不足，不输出误导性异常结论。
4. **给定** 历史任务使用了不同周期，**当** 查看对比，**则** 系统不把它们混合成同一条基线。

---

### 用户故事 5 - 大指标量下按需查看（优先级：P2）

巡检查看人员浏览 600+ 指标时，任务列表和测量单元列表不会因为历史趋势能力而变慢；只有用户主动打开某个指标历史趋势时，系统才加载该指标的历史数据。

**优先级理由**：跨任务历史数据会进一步放大数据量，必须避免任务详情首屏被历史数据拖慢。

**独立测试**：准备多日、多任务和 600+ 指标结果，浏览任务结果首屏和指标列表，再打开单个指标历史趋势。

**验收场景**：

1. **给定** 任务包含 600+ 指标，**当** 打开任务结果首屏，**则** 历史趋势数据不被默认全量加载。
2. **给定** 用户点击单个指标趋势，**当** 系统需要历史数据，**则** 只加载该指标相关历史数据。
3. **给定** 历史查询失败，**当** 用户查看趋势，**则** 系统保留单任务趋势，并显示历史数据加载失败和重试入口。

## 边界情况

- 当历史任务没有设备 ID 时，系统不能自动猜测设备归属，也不能参与匹配。
- 当设备 ID 相同但测量单元或指标不同，系统不能混合比较。
- 当设备 ID 相同但行对象不同，系统必须按对象分别比较。
- 当数据周期不同，系统必须按周期分别比较，不能把 5 分钟和 15 分钟点混成一条基线。
- 当多个任务包含同一设备、同一对象、同一周期和同一时间的点，系统必须使用稳定冲突规则去重，默认以最新成功任务的值为准。
- 当当前任务没有有效测量时间时，系统无法确定最近 7 个自然日窗口，必须输出明确降级原因。
- 当任务处于创建中、执行中或失败状态时，其数据不应作为可信历史基线。
- 当任务被删除时，其数据不应继续出现在历史趋势中。
- 当某天只有部分时段数据时，系统按已有时间点展示，不填补虚构数据。
- 当历史数据中存在异常离线值或解析失败行，系统不能把解析失败值作为正常基线样本。
- 当当前任务数据覆盖多个日期时，系统仍能识别最新日期和历史日期。

## 需求 *(必填)*

### 功能需求

- **FR-001**：系统必须允许用户在创建任务时手动填写设备 ID，并允许有权限用户在任务创建后修改该设备 ID。
- **FR-002**：系统必须将设备 ID 保存为任务元数据，并在任务详情中展示。
- **FR-003**：系统必须在重跑和重建后保留设备 ID。
- **FR-004**：系统必须只把设备 ID 相同的任务视为同一设备的数据来源。
- **FR-005**：系统必须按设备、测量单元、指标、行对象和周期组织跨任务趋势数据。
- **FR-006**：系统必须按日期对齐展示历史趋势，并支持同时刻基线比较。
- **FR-015**：系统必须以当前任务最新测量时间所在自然日为终点，只聚合最近 7 个自然日（含该日）内已完成任务的同维度历史数据；窗口外数据不参与本期历史基线。
- **FR-007**：系统必须为存在足够历史样本的时间点输出当前值、基线值和偏差。
- **FR-008**：系统必须区分“多日历史同期对比”和“单任务短期突变对比”。
- **FR-009**：系统必须在无历史、历史点不足、周期不同或设备 ID 缺失时输出明确降级原因。
- **FR-010**：系统必须保证历史趋势点能追溯到任务、来源文件、时间、行对象和周期。
- **FR-011**：系统必须使用稳定规则处理跨任务重复时间点冲突：同维度、同周期、同测量时间的数据，保留任务完成时间最新的成功任务值；完成时间相同时按 `task_id` 倒序取值。
- **FR-012**：系统必须按需加载单个指标的历史趋势数据，不能在任务首屏默认加载全部历史趋势。
- **FR-013**：系统必须在任务重跑、重建或删除后保持历史趋势数据与任务结果一致。
- **FR-014**：系统必须在查看历史趋势时保持任务隔离语义，不修改原始压缩包，也不把多个任务变成一个任务。

### 关键实体 *(如果功能涉及数据则填写)*

- **设备标识**：用户手动填写的任务级设备 ID，用于跨任务匹配。
- **历史趋势点**：某设备、某测量单元、某指标、某行对象、某周期在某个时间的值。
- **历史基线**：由历史任务中同周期、同对象、同时刻样本计算出的参考值。
- **偏差摘要**：当前值相对历史基线的差异和是否显著偏离的说明。
- **历史覆盖信息**：可参与比较的历史日期、任务数量、样本数量和数据缺口。

## 成功标准 *(必填)*

### 可度量结果

- **SC-001**：创建任务时填写或后续修改的设备 ID 能在任务详情中完整展示，重跑后不丢失。
- **SC-002**：不同设备 ID 的 KPI 数据在历史趋势中零混合。
- **SC-003**：对同一设备、同一指标，用户能看到多日按时刻对齐曲线和偏差摘要。
- **SC-004**：无历史、点数不足或周期不一致时，系统 100% 显示降级原因，而不是输出误导性历史结论。
- **SC-005**：用户打开单个指标历史趋势时，系统只加载该指标相关数据。
- **SC-006**：600+ 指标任务浏览首屏时，历史趋势加载不阻塞任务结果展示。
- **SC-007**：同一组历史任务重复查询时，历史曲线、基线和偏差摘要保持一致。
- **SC-008**：当前任务最新测量日期之外的历史数据不进入最近 7 天基线。
- **SC-009**：跨任务重复测量时间按最新完成巡检任务去重后，同一查询结果保持稳定。

## 假设

- 设备 ID 由用户手动填写，并支持有权限用户创建后修改；本期不做自动识别、自动推断或局点画像。
- 设备 ID 只用于跨任务匹配，不改变任务 ID 生成规则。
- 没有设备 ID 的历史任务可以继续执行单任务巡检，但不参与跨任务历史对比。
- 第一版默认比较最近 7 个自然日，以当前任务最新测量时间所在自然日为终点；后续可以扩展选择范围。
- 历史基线第一版采用可解释的统计口径，不要求机器学习模型。
- 跨任务历史趋势只读取已有巡检结果，不引入在线采集。
- 桌面端是主要使用场景。
